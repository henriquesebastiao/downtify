# 存储空间与用量

**Storage and usage** 可查看媒体库容量、增长速度、各部分的音频来源、下载结果，以及媒体库不需要的文件占用空间，无需逐个打开目录。管理员可在 Library 页面顶部点击 **Storage and usage** 按钮进入；其他账户看不到该页面。

页面顶部的时间范围按钮（7、30、90 或 365 天）决定整页中“该时间段内”的含义，页面会记住上次选择。

## 页面内容

| 部分 | 说明 |
|---------|-------------------|
| **Library** | 媒体库大小及歌曲数量 |
| **Added in N days** | 该时间段内加入媒体库且目前仍存在的歌曲数量和大小 |
| **Net change** | 该时间段内媒体库容量的增减，以及按周计算的变化速度 |
| **Free space** | 下载目录所在磁盘的剩余空间；当媒体库增长速度达到一定程度时，会估算按当前速度多久会占满磁盘 |
| **Downloaded** | 该时间段内完成的下载，以及跳过或失败的数量 |
| **Could be freed** | [可清理内容](#could-be-cleaned-up)的预计占用总量 |
| **Library size** | 每日结束时媒体库的大小（365 天范围下按周显示）；悬停图表可查看当天大小和歌曲数。图表下方显示每日或每周新增量 |
| **By source** | 按音频来源划分媒体库：YouTube Music、YouTube、SoundCloud、Soulseek（slskd）、Deemix、[额外音乐文件夹](external-library.md)，并列出各来源在该时间段内的新增内容 |
| **Where it is stored** | 按目录（下载目录、slskd 目录、额外音乐目录）和格式（MP3、FLAC、M4A 等）划分媒体库 |
| **Downloads** | 每日或每周完成、跳过和失败的下载，以及各来源的下载数量 |
| **Could be cleaned up** | 重复歌曲、slskd 工作副本、遗留临时文件和孤立侧车文件，并列出相关文件 |
| **Folders** | Downtify 写入目录中的全部内容，按类型分组：歌曲、播客、歌词、图片、播放列表、艺人照片和个人资料、临时文件 |

此页面不会删除或更改任何文件，只会告诉你空间由哪些内容占用，供你通过 Library 的删除操作、[Replace Audio](replace-audio.md) 或手动方式决定如何清理。

## 统计媒体库，不包含工作副本

以上所有数字统计的是**媒体库**：即 Library 页面列出的歌曲，但不含 **slskd 工作副本**。关闭 **Leave files in the slskd folder** 后，Downtify 会将每个已完成的 Soulseek 传输复制到媒体库，而原始传输仍留在 slskd 目录中。这些副本会作为工作副本单独统计，不会被误认为媒体库内容（参见 [slskd 与 Navidrome](slskd-navidrome.md)）。工作副本包括：

- Downtify 已复制到媒体库的传输；从当前版本开始的每次下载都会记录。
- 当未启用原位保留时，slskd 目录中其他不被 Downtify 识别为媒体库歌曲的音频文件。

启用 **Leave files in the slskd folder** 后，slskd 目录就是这些歌曲的存放位置，因此它属于媒体库。

## 数据计算方式

### 随时间增长

Downtify 每小时记录一次媒体库大小，并保留每天最后一次记录。图表会用实线绘制这些实际记录。

首次查看时，首次记录之前的日期（即所有过去日期）会根据媒体库中仍存在的歌曲进行**估算**：优先使用下载时间（Downtify 开始记录每个文件来源后下载的歌曲才有），否则使用文件修改时间。估算数据以虚线显示；由于只能统计目前仍存在的歌曲，已删除的歌曲不会反映在历史估算中。Downtify 运行时间越长，图表中的实测数据就越多。

### 下载

每次下载结束时都会计数，包括队列中的下载和 [Playlist Monitor](playlist-monitor.md) 扫描：

- **Completed**：下载并写入标签的新文件；其大小计入获取它的来源。
- **Skipped**：歌曲已在媒体库中，因此没有下载（关闭 **Download again if the file exists** 时；参见[覆盖现有文件](download-settings.md#overwrite-existing-files)）。
- **Failed**：没有任何来源提供该歌曲、歌曲过长，或来源发生错误。

每次尝试都会计数：监控每次检查都未能下载的歌曲，每次都算作一次失败。Downtify 从此版本开始记录下载数据，并保留 400 天；如果时间范围早于开始统计的日期，页面会显示统计起始时间。

### 可清理内容

| 类别 | 内容 |
|----------|-----------|
| **重复歌曲** | 媒体库中包含相同歌曲的文件。**相同文件**：不同目录中存在名称和大小都相同的文件，通常是同一首歌曲下载到了多个播放列表目录。**可能为同一首歌**：艺人和标题相同，时长相差不超过 3 秒，例如一首从 YouTube Music 下载、又从 Soulseek 下载的歌曲。显示的大小表示只保留每组最大副本时可释放的空间。 |
| **slskd 工作副本** | 参见[统计媒体库，不包含工作副本](#the-library-not-its-working-copies)。 |
| **遗留临时文件** | 超过一小时的部分下载（`.part`、`.ytdl`）、未完成转换（`.temp.mp3`）、原子写入遗留文件（`.tmp`）和[升级媒体库](library-upgrade.md)的工作副本；较新的文件可能仍在使用中。 |
| **孤立侧车文件** | 找不到同名歌曲的 `.lrc` 歌词文件（专用歌词目录中则指路径上不存在媒体库歌曲），以及所在目录中已没有歌曲或播放列表的专辑 `cover.jpg` 文件。 |

展开类别即可查看文件，按大小从大到小排列（最多列出最大的 50 个）。

::: tip 重复项是线索，并非最终结论
“可能为同一首歌”只比较标签和时长，不会比较音频内容。使用录音室版本标题和时长标记的现场版，或标题和艺人相同的不同歌曲，都可能被列出。删除前请先确认。
:::

### 文件夹

**Folders** 部分会遍历下载目录、slskd 目录和歌词目录（歌词另存于单独目录时；参见[歌词](lyrics.md)），并按类型整理所有文件。已包含在其他目录中的子目录只会以自身身份遍历一次。大型媒体库的扫描可能需要一段时间，因此结果会缓存 10 分钟；点击 **Scan again** 可立即重新扫描，点击顶部的 **Refresh** 会重新加载所有内容。不会遍历额外音乐文件夹，因为这些目录由你管理，而非 Downtify。

## API

[`GET /api/library/usage`](../api-reference.md#get-apilibraryusage)（可带 `?days=`）返回除文件夹扫描外的所有数据；文件夹扫描使用 [`GET /api/library/usage/scan`](../api-reference.md#get-apilibraryusagescan)（可带 `?refresh=`）。两者都仅供管理员使用。
