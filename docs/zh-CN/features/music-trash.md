# 音乐回收站

开启**音乐回收站**后，从音乐库移除歌曲不再立即删除文件：管理员会将歌曲移入回收站，保留 **30 天**，期间可以恢复到原位置，并保留原有喜欢记录、播放列表和应用中的离线副本。保留期结束后，工作进程才会永久删除文件。

回收站默认**关闭**，需由服务器管理者开启。未开启时，删除歌曲仍会像以前一样立即删除文件。

## 开启回收站

通常安装方式下，歌曲保存在下载文件夹中，只需设置一个环境变量并重新创建容器：

```yaml
services:
  downtify:
    environment:
      - DOWNTIFY_TRASH=true
```

回收站随后会覆盖下载文件夹（`/downloads`），由 Downtify 自行移动文件。若要覆盖 [slskd 文件夹](slskd-navidrome.md)、[现有音乐文件夹](external-library.md)等其他位置，或由独立进程移动文件，请改用[配置文件](#the-configuration-file)。

回收站开启期间：

- 只有**管理员**可以移除歌曲，而且必须通过回收站。其他账户不再显示歌曲删除按钮，即使歌曲由其本人下载。
- **删除播放列表会将歌曲保留在音乐库中**，与删除自己创建的播放列表一样。
- 回收站未覆盖的文件夹中的歌曲无法移除（`This song’s folder isn’t covered by the trash`）。请将其文件夹加入配置文件。

再次关闭回收站会恢复永久删除。仍在回收站中的歌曲会保留在原位置，即 `.downtify-trash`（参见[文件位置](#where-the-files-go)），并继续从音乐库中排除；重新开启后即可恢复。

## 将歌曲移至回收站

网页端的**移至回收站**位于每首歌曲的菜单、音乐库歌曲标签页的选择栏，以及专辑菜单中。[Android 应用](mobile-apps.md)中，管理员配对的手机可在歌曲 **⋮** 菜单中找到。

移动前，服务器会检查确切的文件；选择较多歌曲或存储较慢时可能需要等待。确认对话框会列出文件，确认后只移动这些文件：

- 歌曲音频文件，以及旁边同名的歌词文件（`.lrc`、`.txt`、`.srt`），或单独保存在[歌词文件夹](lyrics.md)中的 `.lrc`；
- **不会**移动另一种格式的同一歌曲副本，例如 FLAC 旁的 MP3 会保留；若该副本共用歌词文件，歌词也会保留；
- **不会**移动文件夹封面，或其他歌曲使用的内容。

歌曲会立即从所有人的音乐库中移除，即使仍处于“等待移动”。一次最多处理 200 首歌曲。有人正在播放的歌曲必须暂停后才能移动；[音乐库升级](library-upgrade.md)运行期间也不会移动，操作会等待这两种情况结束。

标签信息不足以再次识别的歌曲无法移入回收站（`This song’s tags are too thin…`）：既没有 Spotify、Deezer 或 YouTube ID，也没有 ISRC，而且标题、艺人和专辑不完整。请先修复标签。

## 回收站页面

管理员可通过音乐库页面顶部的**回收站**按钮进入，也可从应用侧边菜单打开。页面按最新优先列出回收站内容，提供搜索框，每首歌曲显示：

| 状态 | 含义 |
|-------|---------|
| **等待移动** | 已确认，工作进程尚未移动；已从音乐库移除 |
| **正在移动** | 正在移入回收站 |
| **已在回收站** | 已移动，显示保留截止时间 |
| **等待恢复** / **正在恢复** | 正在返回音乐库 |
| **已停止，文件已保留** | 出现问题，消息会说明原因；未删除任何内容 |

**恢复**单首或所选歌曲会将文件放回原位置。歌曲使用原音乐库 ID 返回，因此喜欢记录、播放列表和应用离线副本仍能对应。尚未移动的歌曲，包括“等待移动”或移动前停止的歌曲，也可以恢复，此时只需将其重新纳入音乐库。

恢复不会覆盖任何文件：若原位置已有其他文件，歌曲会留在回收站并说明原因。请移动或重命名该文件后重试。

修复消息指出的问题后，例如存储未挂载或文件被修改，可用**重试**继续已停止的操作。服务器中途停止导致的移动或恢复中断，会在重新启动后自动继续。

无法提前清空回收站：歌曲只会通过恢复离开，或在 30 天保留期结束后删除。

## 排除自动下载

回收站中的歌曲会被所有下载跳过，包括队列、[播放列表监控](playlist-monitor.md)和艺人监控，下载结果为 `In the music trash: an admin has to allow it again`。识别使用来源 ID，或精确的标题、艺人和专辑，因此不会影响其他发行版本。

30 天后仍会继续排除，避免受监控播放列表重新下载已移除的歌曲。回收站页面的**已排除自动下载**视图会列出这些歌曲；**允许下载**会让下次同步能够再次获取，但不会立即开始下载。恢复歌曲也会解除排除。

## 文件位置

歌曲会移入其音乐库文件夹根目录下的 `.downtify-trash`，例如 `/downloads/.downtify-trash/<id>/`，仅 Downtify 的运行用户可读，并包含一个空 `.ignore` 文件，供 Jellyfin 忽略。Downtify 自身的扫描、播放器、流式播放和应用都不会显示其中内容。

移动通过同一磁盘上的重命名完成，不复制，也不替换已有文件。移动前、恢复前和删除前，都会按确认时的大小和 SHA-256 检查每个文件。期间被修改的文件会停止处理并保留。此功能需要 Linux，以及支持原子、不覆盖重命名的文件系统（`renameat2` 配合 `RENAME_NOREPLACE`，例如 ext4、XFS、Btrfs、tmpfs、ZFS）；其他环境会拒绝移动任何文件（`This storage can’t move files safely`）。

歌曲仍在回收站时，不要删除 `/data` 中的数据库，也不要回退到不支持回收站的 Downtify 版本；数据库记录着每个文件的原位置。

## 配置文件

`DOWNTIFY_TRASH_CONFIG` 指定容器内的 JSON 文件，列出回收站覆盖的各个文件夹，其优先级高于 `DOWNTIFY_TRASH`。

```json
{
  "version": 1,
  "worker": "embedded",
  "roots": {
    "downloads": { "path": "/downloads" },
    "slskd": { "path": "/slskd" },
    "nas": {
      "path": "/music/nas",
      "marker": ".downtify-nas",
      "marker_value": "living-room-nas"
    }
  }
}
```

| 键 | 说明 |
|-----|-------------|
| `version` | 始终为 `1` |
| `worker` | `embedded`（默认）：Downtify 自行移动文件。`external`：只由[独立工作进程](#a-separate-worker)处理 |
| `roots` | 各文件夹使用自选名称。`path` 必须是 Downtify 看到的绝对路径，即下载文件夹、slskd 文件夹或额外音乐文件夹之一，且其本身不能是符号链接 |
| `marker`, `marker_value` | 可选，用于可移动或网络存储：指定文件夹中的标记文件及预期内容。文件缺失或内容不符时，例如磁盘未挂载或挂载了其他磁盘，该文件夹中的任何文件都不会移动 |

配置无法读取时，服务器会停止启动并在日志中说明原因，不会退回永久删除。

## 独立工作进程

设置 `"worker": "external"` 后，Downtify 只记录待执行操作，不触碰文件。其容器可只读挂载音乐，由独立进程执行移动、恢复和过期删除；该进程只需挂载音乐文件夹与 `/data`，不需要网络或 Docker socket：

```sh
python -m downtify.trash_worker \
  --config /config/trash.json \
  --database /data/downtify_library.db \
  --auth-database /data/downtify_auth.db \
  --limit 5
```

每次运行最多处理 `--limit` 指定的操作数（1–20），以 JSON 打印执行结果（`{"processed": 1, "succeeded": 1, "failed": 0}`）后退出。可用 systemd timer、cron 或 Kubernetes CronJob 等每分钟左右调度一次。工作进程会只读访问账户数据库，再次确认发起者仍为管理员，并保证两次运行不会同时执行。请使用与服务器相同的 Downtify 版本运行，并确保期间没有其他进程重写相同文件。

网页应用与 Android 应用使用 `/api/v1/library/trash` 下的相同端点，参见 API 参考中的[音乐回收站](../api-reference.md#music-trash)。
