# 医生

新版 Downtify 会修复**此后**发生的问题：slskd 传输在导入后移除，播放列表封面保存在 M3U 旁，Navidrome 播放列表保持同步。不过，旧版本写入的文件和播放列表仍保持旧状态，例如每次 Soulseek 下载留下的第二份副本、位于旧路径的 M3U，以及在 Navidrome 中重复显示的播放列表。**设置 → 医生**会查找这些遗留状态，只修复能够*确认*安全的部分，让旧版本开始积累的音乐库跟上新版行为。

只有管理员可见。

## 健康检查

**立即检查**会检查下列所有内容，不做任何修改。检查在后台运行，离开页面不会停止；返回时仍会显示上次结果。

## slskd 遗留文件

旧版本将每个已完成的 Soulseek 下载复制到音乐库后，会将原文件留在 slskd 文件夹中，导致每首歌曲占用双倍空间。**暂停下载并检查**会：

1. 暂停下载队列并等待正在运行的下载完成，确保文件比对期间没有写入；
2. 列出 slskd 文件夹中没有任何音乐库歌曲、播放列表、受监控播放列表或 M3U 引用的文件（启用**将文件保留在 slskd 文件夹中**时，该文件夹*就是*音乐库，无需清理）；
3. 按艺人和标题相同，或时长和格式相同，找出可能对应的音乐库文件，只比较双方的**音频内容**。

Downtify 会重写导入文件的标签和封面，因此两份文件的整体字节不会相同，但音频不会改动。医生使用 `ffmpeg` 对两份文件的音频数据包计算哈希，不解码，也不包含标签和封面。只有在 slskd 文件夹之外找到音频逐位相同的音乐库文件，遗留文件才会标记为**音乐库中有相同文件**。其他文件均会保留并显示原因：

- **相似但不相同**：存在相似文件，但音频不同，例如不同抓轨或现场版本；
- **不在音乐库中**：没有找到相似文件；
- **无法读取**：`ffmpeg` 无法读取；
- **最近有改动**：过去 15 分钟内修改过，slskd 可能仍在写入。

**删除相同的副本**只删除已确认相同的文件。每个文件删除前都会再次检查：大小和修改时间必须与比对时一致，音乐库中的对应副本也必须仍然存在。清空的文件夹会移除，下载会恢复，并请求 Navidrome 重新扫描。**保留并恢复下载**会恢复队列而不删除任何文件；一小时内不作选择也会恢复下载。

音频哈希缓存在 `/data/doctor/audio_hashes.db` 中，因此新增少量下载后再次检查，只需读取新文件。

## 重复的播放列表

同一个播放列表可能有两个 M3U 文件：名称相同但位置不同，通常是 M3U 移入播放列表自身文件夹之前留下的 `Playlists/<name>.m3u`，或切换**按艺人整理/按专辑整理**后留下的文件；也可能名称不同但歌曲几乎相同，例如播放列表在 Spotify 上改过名。

**合并**会保留 Downtify 当前使用的文件，将两个列表的每首歌曲各保留一次，先沿用较大列表的顺序；若保留文件旁没有封面，则复制封面，再移除另一个文件及其封面。两个文件都会先备份到 `/data/doctor/backups/<date>/`。只有较小列表中至少 80% 的歌曲也存在于较大列表时才允许合并，否则可能是不同播放列表，按钮会禁用。你在音乐库中创建的播放列表不会合并。

**自行选择播放列表**会列出所有 M3U，让你比较检查未自动配对的两个列表，并按相同规则合并。

## Navidrome

这里显示 Navidrome 及 Symfonium 等所有连接它的应用实际看到的内容。需要提供 [Navidrome 管理员登录信息](slskd-navidrome.md#navidrome)：只有管理员能查看 Navidrome 导入的播放列表及其来源文件。

Navidrome 会将音乐文件夹中的每个 M3U 导入为自己的播放列表，使用文件旁的封面，并归其管理员所有。开启**在 Navidrome 中创建播放列表**后，Downtify *还会*通过 API 创建同一列表，因此每个列表显示两次：导入的列表有封面，Downtify 创建的没有。检查会报告：

- **重复**：归为同一名称的播放列表及原因，包括导入的 M3U 与 Downtify 副本、M3U 重复导入，或 Downtify 重复创建；
- **M3U 已不在**：来源 M3U 已不存在的导入播放列表。即使完整扫描，Navidrome 也不会自行移除；
- **缺少歌曲**：歌曲数量少于其 M3U 的导入播放列表。Navidrome 会跳过指向音乐文件夹外部的行，例如歌曲保留在不属于其音乐库的 slskd 文件夹中，并显示有多少首位于外部；
- **Navidrome 中的重复歌曲**：出现多次的歌曲，判定依据为艺人和标题相同、时长相差不超过 2 秒，并统计有多少副本位于 `slskd` 文件夹中。

**修复**会删除标记为“将被删除”的播放列表：Navidrome 已导入列表的 Downtify 副本（副本含有导入列表缺失的歌曲时除外）、Downtify 创建的多余副本，以及 M3U 已不存在的导入列表。随后在设置 → Navidrome 中开启**让 Navidrome 导入 M3U 播放列表**，避免再次创建副本，再让 Navidrome 重新扫描并再次列出列表，报告剩余问题。只允许删除上次健康检查标记的播放列表。

## 重复歌曲

这是 Downtify 自己看到的情况，与[存储与用量](storage-usage.md#could-be-cleaned-up)相同：列出**相同文件**和**可能是同一首歌**及示例。医生不会删除音乐库歌曲，请在音乐库中检查。

## 以新的 Spotify ID 再次下载

Spotify 有时会将播放列表中的曲目替换为同一首歌的新 ID，例如重新发行、重制或地区版本。Downtify 按 ID 记录受监控播放列表的曲目，因此即使没人修改列表，替换后的曲目也会被视为新歌曲并再次下载。检查会列出同一受监控列表中以多个 ID 存在于多个文件的歌曲。

## API

接口均仅限管理员，位于 `/api/doctor` 下：`GET /api/doctor`（运行中或最近一次任务，以及每类检查的最近结果）、`POST /scan`、`POST /cancel`、`POST /slskd/scan`、`GET /slskd/files`、`POST /slskd/clean`、`POST /slskd/release`、`POST /playlists/preview`、`POST /playlists/merge` 和 `POST /navidrome/repair`。同一时间只运行一个医生任务。
