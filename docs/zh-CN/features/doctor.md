# 医生

新版 Downtify 会修复**此后**发生的问题：slskd 传输在导入后移除，播放列表封面保存在 M3U 旁，Navidrome 播放列表保持同步。不过，旧版本写入的文件和播放列表仍保持旧状态，例如每次 Soulseek 下载留下的第二份副本、位于旧路径的 M3U，以及在 Navidrome 中重复显示的播放列表。**设置 → 医生**会查找这些遗留状态，只修复能够*确认*安全的部分，让旧版本开始积累的音乐库跟上新版行为。

只有管理员可见。

## 健康检查

**立即检查**会检查下列所有内容，不做任何修改。检查在后台运行，离开页面不会停止；返回时仍会显示上次结果。

下面每个部分都可以单独展开；标题会显示检查结果（**一切正常**、**3 个待合并**……），一眼就能看出哪里需要处理。页面会记住你展开了哪些部分。

一次修复可能改变其他部分的结果：合并重复歌曲会改写播放列表，还可能移除 slskd 遗留文件所匹配的音乐库文件；删除 slskd 遗留文件会改变歌曲数量；合并播放列表会改变 Navidrome 的结果。修复之后，可能受影响的每个部分都会标为**已过期**，在你点击**重新检查**之前无法在其中修复，这样就不会根据已不成立的结果进行操作。服务器同样会拒绝这些修复，而不只是页面。

## AI 助手

逐个查看每一项发现需要读很多内容，而下面的检查都是非此即彼的严格规则。**AI 助手**可以让 Claude 等 AI 助手和你一起阅读。用平常的话告诉它你想要什么（“这些都是同一个自驾游歌单，留一个就行”“这些歌保留专辑版，不要混音版”）。它会比较、解释每一项发现，并给出建议。决定权始终在你手里。它覆盖每个部分：[重复的播放列表](#duplicate-playlists)、[重复歌曲](#duplicate-songs)、[以新的 Spotify ID 再次下载的歌曲](#downloaded-again-under-a-new-spotify-id)、[slskd 遗留文件](#slskd-leftovers)和 [Navidrome](#navidrome)。

它适合偶尔整理一次，而不是一直开着：

- **启动 AI 助手**会开启它并显示一个新密钥。**停止**会关闭它，密钥随即失效。
- 助手 2 小时内没有收到请求，或 Downtify 重启时，它也会自动停止。重启后，它的建议会被清空。

### 连接助手

AI 助手是一个 [MCP](https://modelcontextprotocol.io) 服务器，地址为 `/api/doctor/ai/mcp`，与 Downtify 使用同一个地址。运行期间，这个部分会为每个应用显示可直接复制的设置，密钥已经填好：

| 应用 | 连接方式 |
|---|---|
| Claude Code | 在能访问服务器的电脑上（家庭网络或 Tailscale 即可），于终端运行一条 `claude mcp add` 命令 |
| Claude Desktop | 在 `claude_desktop_config.json` 中加入几行，通过小型桥接程序 `mcp-remote` 连接（那台电脑需要 Node.js），然后重启 Claude Desktop |
| 网页版或手机上的 Claude、ChatGPT | 仅当服务器能通过 HTTPS 从互联网访问时可用，例如使用 Tailscale Funnel 或 Cloudflare Tunnel。ChatGPT 需要开发者模式，并非所有套餐都有 |

下面还有一条可以粘贴到聊天中的第一条消息，用来开始。请妥善保管密钥：助手运行期间，持有密钥的人可以更改你的音乐库。

### 助手能做什么

- 读取上一次健康检查的结果，或重新检查。
- **重复的播放列表：**列出所有播放列表、读取某个播放列表的歌曲，并逐首比较 2 到 20 个播放列表（哪些歌都有、哪些只在其中一个里）。它会建议合并，或建议某一组是**不同的播放列表**。合并仍然遵循原来的规则（较小播放列表中 80% 的歌曲在较大的那个里），你在音乐库中创建的播放列表永远不会被合并。
- **重复歌曲：**检查给出的分组，以及对整个音乐库的搜索，因此也能找到检查从不归组的混音、现场和加速版本（它们的时长不同）。对每个文件，它可以读取标签、ISRC、歌词、时长、格式、来源和所在的播放列表，检查两个文件的音频是否完全相同，并在 MusicBrainz 上查询这首歌（官方发行、时长、ISRC）。它会建议**保留一份**，效果与**保留所选副本**相同：用到其他副本的内容会先转到保留的那份，然后其他副本进入音乐回收站，回收站关闭时则被永久删除。也可能建议**不同的歌曲**。音乐回收站开启时，它会先检查每个副本：回收站无法识别的副本（没有 Spotify、Deezer 或 YouTube ID，没有 ISRC，标题、艺术家和专辑标签也不全）不能被移除，所以助手会在建议之前就说明，而不是让**应用**卡在这一步。
- **以新的 Spotify ID 再次下载：**完整列表，用**保留一份**来修复。
- **slskd 遗留文件：**运行 slskd 检查（期间新的下载会等待，与你在这里运行时一样），并建议删除遗留文件。只有确认与音乐库中某个文件音频相同的遗留文件才能删除。
- **Navidrome：**发现的问题和页面自己的方案。它会建议删除检查标记过的播放列表（只能是这些），以及开启 M3U 导入。

每条建议都附有写给你的理由。它们显示在**助手的建议**下，按部分分组，使用与医生其他部分相同的卡片：播放列表带封面和歌曲数量，歌曲的每个副本都带播放器并标明保留哪一份，slskd 文件附上它匹配的音乐库文件，Navidrome 列出将删除的播放列表。**应用**执行一条。某个部分的**全部应用**会一起执行该部分的建议，歌曲合并逐个进行。**忽略**移除一条。应用的效果与你在页面上自己决定完全相同：同样的检查、备份和音乐回收站。之后被改变的部分会标为**已过期**，直到重新检查，这些部分中等待的建议也要等到那时，所以一次处理一个部分。

**允许助手应用你在聊天中同意的内容**让助手在你于聊天中同意后替你点击应用。每次启动助手时它都是关闭的。关闭时，助手只能提出建议。

## slskd 遗留文件

旧版本将每个已完成的 Soulseek 下载复制到音乐库后，会将原文件留在 slskd 文件夹中，导致每首歌曲占用双倍空间。**暂停下载并检查**会：

1. 暂停下载队列并等待正在运行的下载完成，确保文件比对期间没有写入；
2. 列出 slskd 文件夹中没有任何音乐库歌曲、播放列表、受监控播放列表或 M3U 引用的文件（启用**将文件保留在 slskd 文件夹中**时，该文件夹*就是*音乐库，无需清理）；
3. 按艺人和标题相同，或时长和格式相同，找出可能对应的音乐库文件，只比较双方的**音频内容**。

Downtify 会重写导入文件的标签和封面，因此两份文件的整体字节不会相同，但音频不会改动。医生使用 `ffmpeg` 对两份文件的音频数据包计算哈希，不解码，也不包含标签和封面。只有在 slskd 文件夹之外找到音频逐位相同的音乐库文件，遗留文件才会标记为**音乐库中有相同文件**。其他文件均会保留并显示原因：

- **相似但不相同**：存在相似文件，但音频不同，例如不同抓轨或现场版本；
- **不在音乐库中**：没有找到相似文件；
- **无法读取**：`ffmpeg` 无法读取；
- **最近有改动**：过去 15 分钟内修改过，slskd 可能仍在写入。

**删除相同的副本**只删除已确认相同的文件。每个文件删除前都会再次检查：大小和修改时间必须与比对时一致，音乐库中的对应副本也必须仍然存在。清空的文件夹会移除，下载会恢复，并请求 Navidrome 重新扫描。**保留并恢复下载**会恢复队列而不删除任何文件；一小时内不作选择也会恢复下载。

音频哈希缓存在 `/data/doctor/audio_hashes.db` 中，因此新增少量下载后再次检查，只需读取新文件。

**slskd 文件夹里有什么**（健康检查后显示）说明为什么文件浏览器里该文件夹比存储页面显示的更大。其中每个文件都属于以下之一：**音乐库歌曲**（存储页面计入的部分）、**遗留文件**（上方检查会比较的副本）、**Downtify 不认识的音频**（从未导入，或导入失败后保留，其他地方都不计入），或**其他文件**（封面、歌词及其他不是歌曲的文件）；后两类中最大的文件会按名称列出。它只读取文件夹。这里的大小按 1 GB = 1024³ 字节计算；有些文件浏览器按 1000³ 计算，因此同一文件夹在那里可能显示得更大。

## 重复的播放列表

同一个播放列表可能有两个 M3U 文件：名称相同但位置不同，通常是 M3U 移入播放列表自身文件夹之前留下的 `Playlists/<name>.m3u`，或切换**按艺人整理/按专辑整理**后留下的文件；也可能名称不同但歌曲几乎相同，例如播放列表在 Spotify 上改过名。

比较名称时会忽略大小写、重音、标点和表情符号，因此 `DAMNN...its already 3am🥵` 与为它写入的 `DAMNNits already 3am` 文件夹算同一个名称。名称不同的两个播放列表，只有*各自*至少 80% 的歌曲也在对方之中，才算歌曲相同；而且一个播放列表只有与组内每个播放列表都匹配时才会加入该组——一个几乎全部包含在 7,000 首“喜欢的歌曲”备份中的 50 首混音，并不是它的副本。**名称相同**和**歌曲相同**可按发现原因筛选列表。

浏览时逐组决定：在每组上选择**合并**或**不同的播放列表**，最后点击一次**应用更改**。所有合并在同一个任务中进行，最后只让 Navidrome 重新扫描一次。标记为不同播放列表的组不再列出；**重新列出**可让它们再次出现。

**合并**会保留 Downtify 当前使用的文件，将两个列表的每首歌曲各保留一次，先沿用较大列表的顺序；若保留文件旁没有封面，则复制封面，再移除另一个文件及其封面。两个文件都会先备份到 `/data/doctor/backups/<date>/`。只有较小列表中至少 80% 的歌曲也存在于较大列表时才允许合并，否则可能是不同播放列表，按钮会禁用。你在音乐库中创建的播放列表不会合并。

**自行选择播放列表**会列出所有 M3U，让你比较检查未自动配对的两个列表，并按相同规则合并。

有封面的 M3U 会显示其封面；点击即可放大查看。

## Navidrome

这里显示 Navidrome 及 Symfonium 等所有连接它的应用实际看到的内容。需要提供 [Navidrome 管理员登录信息](slskd-navidrome.md#navidrome)：只有管理员能查看 Navidrome 导入的播放列表及其来源文件。

Navidrome 会将音乐文件夹中的每个 M3U 导入为自己的播放列表，使用文件旁的封面，并归其管理员所有。开启**在 Navidrome 中创建播放列表**后，Downtify *还会*通过 API 创建同一列表，因此每个列表显示两次：导入的列表有封面，Downtify 创建的没有。检查会报告：

- **重复**：归为同一名称的播放列表及原因，包括导入的 M3U 与 Downtify 副本、M3U 重复导入，或 Downtify 重复创建；
- **M3U 已不在**：来源 M3U 已不存在的导入播放列表。即使完整扫描，Navidrome 也不会自行移除；
- **缺少歌曲**：歌曲数量少于其 M3U 的导入播放列表。Navidrome 会跳过指向音乐文件夹外部的行，例如歌曲保留在不属于其音乐库的 slskd 文件夹中，并显示有多少首位于外部；
- **Navidrome 中的重复歌曲**：出现多次的歌曲，判定依据为艺人和标题相同、时长相差不超过 2 秒，并统计有多少副本位于 `slskd` 文件夹中。

**修复**会删除标记为“将被删除”的播放列表：Navidrome 已导入列表的 Downtify 副本（副本含有导入列表缺失的歌曲时除外）、Downtify 创建的多余副本，以及 M3U 已不存在的导入列表。随后在设置 → Navidrome 中开启**让 Navidrome 导入 M3U 播放列表**，避免再次创建副本，再让 Navidrome 重新扫描并再次列出列表，报告剩余问题。只允许删除上次健康检查标记的播放列表。

## 重复歌曲

这是 Downtify 自己看到的情况，与[存储与用量](storage-usage.md#could-be-cleaned-up)相同：列出**相同文件**和**可能是同一首歌**及示例。医生不会删除音乐库歌曲，请在音乐库中检查。

仅从音乐库中删除重复歌曲的一个副本还不够：使用它的播放列表、喜欢记录和受监控播放列表会指向空处，因此这首歌看起来像是缺失了，受监控播放列表还会再次下载它。**保留所选副本**则改为合并：先把其他副本关联的所有内容迁移到你保留的那一个，包括 M3U 文件（你自己的播放列表也一样，歌曲在其中只出现一次）、播放列表目录、Spotify 曲目索引、所有账号的喜欢记录和所有者、从播放列表中隐藏的歌曲、移动端应用中的离线副本，以及播放列表监控的已下载曲目、艺人发行和历史记录。然后移除其他副本：若[音乐回收站](music-trash.md)已开启，则将其移入回收站（无法移入的副本，即位于未覆盖的文件夹中或正在播放的副本，会在任何更改前停止合并）；否则直接永久删除。结果会说明更新了哪些播放列表，并检查是否仍有内容指向已移除的副本。在音乐库中隐藏某个副本，不会隐藏你保留的那一个。

**保留全部，它们不同**用于确实是不同录音的相似歌曲：编辑版、现场版、以原曲名义出现的戏仿版本。在出现其他副本之前，医生不再列出它们；**重新列出**会恢复所有以此方式保留的分组。

## 要转换的格式

资料库中已有的、你不想要的格式的文件：例如在设定格式规则之前下载的 FLAC，可能占用 MP3 320 的十倍空间。选择格式（默认选中 FLAC），**查找文件**会列出资料库中这些格式的所有文件，最大的排在前面，并显示现在的大小以及按你的下载质量转成 MP3 后的大小。此时还不会改动任何东西。

**转换**会在每个文件旁边生成一个下载质量的 MP3（除非你选了更低，否则为 320 kbps），保留相同的标题、艺人、专辑、编号、日期、流派、ISRC、封面和歌词；同名的 `.lrc` 文件继续有效。会先检查 MP3 与原文件时长一致，然后它会像重复项的 **保留所选副本** 一样接管指向原文件的一切，原文件在音乐回收站开启时移入回收站。无法转换的文件保持原样，并给出原因。可以在文件之间停止。

无损文件（FLAC、WAV、AIFF、APE、WavPack）转成 MP3 320 听起来一样：好的 MP3 就是这样做出来的。有损文件（M4A、OGG、Opus）再次转换会略有损失，只在需要空间时才选择它们。请先合并重复的歌曲，这样每首歌只转换一次。要防止这类文件再次出现，请在下载设置中设定 **避免的格式**。

## 以新的 Spotify ID 再次下载

Spotify 有时会将播放列表中的曲目替换为同一首歌的新 ID，例如重新发行、重制或地区版本。Downtify 按 ID 记录受监控播放列表的曲目，因此即使没人修改列表，替换后的曲目也会被视为新歌曲并再次下载。检查会列出同一受监控列表中以多个 ID 存在于多个文件的歌曲。

## API

接口均仅限管理员，位于 `/api/doctor` 下：`GET /api/doctor`（运行中或最近一次任务，以及每类检查的最近结果）、`POST /scan`、`POST /cancel`、`POST /slskd/scan`、`GET /slskd/files`、`POST /slskd/clean`、`POST /slskd/release`、`POST /playlists/preview`、`POST /playlists/merge` 和 `POST /navidrome/repair`。同一时间只运行一个医生任务。`GET /api/doctor` 还会列出已过期的部分（`stale`）；在重新检查之前，这些部分的修复会返回 `409` 和 `rescan_first`。

[AI 助手](#ai-helper)的接口同样仅限管理员：`GET /api/doctor/ai`（是否在运行、密钥和建议）、`POST /ai/start`、`POST /ai/stop`、`PUT /ai/settings`（`can_apply`）、`POST /ai/apply` 和 `POST /ai/dismiss`（`ids`），以及 `POST /ai/clear`。助手本身连接 `/api/doctor/ai/mcp`（基于 HTTP 的 MCP，每个 `POST` 返回一个 JSON 应答），它用助手的密钥（`Authorization: Bearer`）代替登录。
