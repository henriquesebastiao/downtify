# 升级音乐库

长期积累的音乐库会保留歌曲下载时对应版本的能力：来源提供的小尺寸封面、缺失歌词、没有专辑或年份的标签。**升级音乐库**会检查磁盘上的已有文件，只修复尚未完善的部分，无需重新下载，也无需手动逐一整理。

通过**音乐库 → 升级音乐库**打开。

::: info 默认升级只重写标签
默认模式重写**封面、歌词和标签**。可选的 [Deemix 替换](#deemix-recording-replacement)是独立扫描模式，默认关闭。若要手动选择其他版本，请使用[替换音频](replace-audio.md)。
:::

## 工作流程

1. **扫描。** Downtify 读取音乐库中的每首歌曲，按类别报告需要完善的内容，不写入任何文件。
2. **选择。** 扫描发现问题的每个类别都会显示歌曲数量和开关，可取消不需要的类别。
3. **升级。** 所选歌曲进入队列，逐首处理。可暂停、继续或停止，重启后也能保留队列。

## 修复内容

| 类别 | 操作 | 查找来源 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **升级封面** | 替换小于目标尺寸的封面 | Spotify、Apple Music（iTunes）、YouTube Music |
| **添加缺失歌词** | 为没有歌词的歌曲补充嵌入歌词和 `.lrc` 附属文件 | 按你设置的[歌词服务](lyrics.md)顺序查找 |
| **刷新标签** | 补充专辑、专辑艺人、发行日期和曲目编号，包括旧版单曲下载缺失的专辑 | Spotify |

满足以下任一条件的歌曲会被视为需要完善：

- 嵌入封面的短边**小于目标尺寸**，完全没有封面也包括在内；
- **既没有**嵌入歌词，**也没有** `.lrc` 附属文件，检查音频旁以及设置中的歌词文件夹；
- 标签缺少**专辑**、**专辑艺人**、**年份**或**曲目编号**之一。

**刷新标签**只适用于 Downtify 仍保存 Spotify 曲目 ID 的歌曲，即通过 Spotify 链接下载、并保留在[曲目索引](library-catalog.md#what-gets-stored)中的歌曲。其他歌曲也会进入队列，但结果为“无需处理”。

## 选项

### 升级小于此尺寸的封面

`300px` · `500px` · **`600px`** · `1000px` · `1200px`

达到或超过此尺寸的封面保持不变。Downtify 只会写入比文件现有封面**严格更大**的图片，因此重复升级不会无意义地重写文件。

各来源的典型尺寸：

| 来源 | 典型尺寸 |
| ------------------------ | --------------------------------------------------------------------------- |
| **Apple Music（iTunes）** | 1200px 或更大 |
| **Spotify** | 最大 640px |
| **YouTube Music** | 最高取决于[封面尺寸](download-settings.md)设置，约为 1200px |

这也是旧音乐库封面经常停留在 300–640px 的原因：Spotify 提供固定尺寸封面，最大为 640px。

### 封面来源

| 选项 | 行为 |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **最高可用分辨率**（默认） | 查询所有来源并保留最大的图片 |
| **优先 Spotify** / **优先 Apple Music** / **优先 YouTube Music** | 只要指定来源有图片就使用，其他来源仅在其没有图片时作为备用 |

### 重复检查间隔

`Always check every track` · `7 days` · **`30 days`** · `90 days` · `365 days`

歌曲检查后，下次扫描会在此期限内跳过，避免大型音乐库重复向相同来源查询相同歌曲。

检查记录按**歌曲和类别分别保存**，因此支持分批处理：只修复 16,000 首歌曲的封面，并不代表检查过歌词，之后的歌词升级仍会检查全部歌曲。扫描也会记录检查过但无需处理的类别，未发现问题同样算一次检查。

Downtify 为每首歌曲的每个类别记录检查时间、执行检查的 Downtify 版本；封面类别还记录找到的最大封面及来源。各歌词服务的查询记录则按歌曲和服务单独保存，参见[歌词](lyrics.md)。

两种情况始终会忽略间隔：

- **更新的 Downtify 版本**会重新检查全部歌曲，因为新版可能改进匹配或标签写入；
- 选择**每次检查全部歌曲**会在本次扫描忽略检查记录。

如果没有可升级内容只是*因为*全部歌曲近期已检查，页面会说明原因，并提供忽略记录重新运行的选项，而不是只显示无法解释的“无需升级”。

## 运行期间

进度面板显示队列处理数量、近似数据量（`8.4 GB of 51.3 GB`），以及已升级、无需处理和失败的数量。每首歌曲会显示当前阶段：“正在匹配”“正在查找封面”“正在查找歌词”“正在写入文件”，结束时说明修改内容，例如 `artwork 1200px (itunes)`。

**暂停**会完成当前歌曲后停止，保留队列。**停止**会丢弃剩余队列，已升级的歌曲保持升级后的状态。可以离开页面，任务仍会继续，其他已打开的标签页也会同步进度。

队列保存在 `/data/downtify_library.db`，因此**运行中重启 Downtify 或容器后，会从停止位置继续**。进程退出时正在处理的歌曲会重新放回队列。

## 升级失败不会丢失原文件

所有写入都先进入原文件旁的工作副本（`<name>.downtify-upgrade.<ext>`）。只有确认副本可读取为相同时长的音频后，才会替换原文件；否则丢弃副本，原文件保持不变。该临时文件不会作为独立歌曲显示，歌曲处理结束后就会移除。

原文件的**修改时间会保留**，因此升级不会打乱“最近添加”的顺序。

### 只读音乐文件夹

升级会原位重写标签，因此只读文件系统中的歌曲会在查询元数据、封面或歌词之前被**跳过**，并说明原因。歌曲仍可播放，仍在播放列表中，文件和挂载权限不变。跳过的只读歌曲不会记为成功检查，文件夹以后可写时还能再次检查。意外的权限、空间不足和 I/O 错误仍会显示为失败。

这与[现有文件夹内容补充](external-library.md)不同，后者可以将封面和歌词独立保存在 Downtify 数据文件夹中，不重写受保护的音频文件。

## 为什么不替换音频

常规标签升级不替换音频。下方独立模式要求准确的录音元数据，并完成引用发布；无法确定的版本仍需手动检查。

## Deemix 录音替换

启用并测试 [Deemix 来源](deemix.md)后，**升级音乐库**会在扫描前提供两个独立开关：

- **使用已验证的 Deemix 录音**：扫描 Downtify 原始下载，包括被优先外部收藏隐藏的副本。精确匹配艺人、完整标题及版本和专辑，拒绝有歧义的目录结果。不会仅因旧片段的时长而排除正确的目录录音。会验证下载后的标签、目录时长、所选音质和完整 FFmpeg 解码。
- **导入后移除旧的 Downtify 音频**：另外在发布后移除每个未改变的原文件，默认关闭。即使保留原文件，也会将播放列表和喜欢记录更新为 Deemix 录音。

此扫描生成**音频**类别，而不是封面、歌词或标签任务。输出文件、封面、专辑布局和原生歌词由 Deemix 管理，Downtify 原位读取。已有原生或嵌入歌词会保留；只有缺失歌词时，才可能补充到可写的专用歌词文件夹，不重写音频。Deemix 配置为 MP3 时，会保留音质更高的无损原文件。

每批只发布一次。M3U 注释、手动标记和歌曲顺序保持不变，随后在一个 SQLite 事务中迁移目录路径、播放列表成员关系、所有用户的喜欢记录、所有权和隐藏规则。旧文件缓存的 Navidrome ID 会失效，以便重新进行原生查找。之前发给移动客户端的 ID 和旧播放 URL 会保留到已登记替代文件的只读别名；修改操作不会使用这些 URL 别名。

音乐库数据库中的持久化回执会记录来源与目标的 SHA-256 及发布状态。替代文件和引用验证通过前，原文件会保留。挂载变化或缺失、文件被修改、外部只读播放列表引用、正在播放或目录发布失败，都将停止清理并显示原因。暂停、继续和重启会复用这些回执。不会进行通用重复文件扫描，也不会按年龄清理；只有 Downtify 下载文件夹中已验证的原文件才可删除。手动 Deemix/slskd 下载、外部原文件、目录和附属文件不会删除。原文件删除后，回退容器版本也无法恢复；需要时请从自己的存储备份还原。

若 NAS 使用的挂载名与 Docker 路径不同，管理员可将 `DOWNTIFY_DEEMIX_M3U_ROOT` 设为指向 Deemix 根目录的容器别名。相对 M3U 路径会使用该别名，例如将 `/Download` 映射到 `/music/existing`。可选的 `DOWNTIFY_LIBRARY_READY_MARKERS` 是由标记文件路径及预期文本组成的 JSON 对象，在准备和清理前检查；标记缺失时不会继续。默认模式不要求这两个变量。

扫描 API 接受 `replace_audio_deemix: true`、可选的 `delete_replaced_audio: true`，以及可选的 `files: ["relative/original.mp3"]` 用于小范围试运行。启动该扫描时选择 `categories: ["audio"]`。运行状态包含替换数量，并在发布暂停时提供 `finalization_error`。不会仅因为 Deemix 队列项显示完成，就移除任何原文件。

### 检查不确定的录音版本

跳过或失败的音频任务会提供**选择 Deezer 录音版本**。粘贴准确的曲目链接，预览艺人、专辑和时长，再选择**分析所选版本**。这只会准备一次新的单曲扫描，确认扫描后才开始替换。默认自动匹配不会猜测其他专辑。

明确选择可以修正旧专辑标签，但完整标题及版本和艺人仍必须匹配。已知含露骨内容的原版不能悄然替换为删减版。所选录音会经过相同的时长、音质、解码、引用和删除检查。不同选择不会悄然复用已准备的回执。高级扫描载荷以 `deemix_recordings: {"relative/original.mp3": "123456"}` 记录选择，范围仅限该文件，并保存以供重启和继续使用。

## API

| 方法 | 路径 | 说明 |
| ------ | ----------------------------- | ----------------------------------------------- |
| `GET` | `/api/library/upgrade` | 运行状态、队列数量和扫描结果 |
| `GET` | `/api/library/upgrade/jobs` | 每首歌曲的任务行（`status`、`stage`、`detail`） |
| `POST` | `/api/library/upgrade/scan` | 扫描音乐库，不写入任何内容 |
| `POST` | `/api/library/upgrade/start` | 按所选 `categories` 开始运行 |
| `POST` | `/api/library/upgrade/pause` | 当前歌曲完成后暂停并保留队列 |
| `POST` | `/api/library/upgrade/resume` | 继续已暂停的任务 |
| `POST` | `/api/library/upgrade/cancel` | 丢弃剩余队列 |

进度也会通过 [WebSocket](../api-reference.md#websocket) 以 `{"type": "library_upgrade", "upgrade": {…}}` 推送。

请求和响应结构参见 [API 参考](../api-reference.md#library)。
