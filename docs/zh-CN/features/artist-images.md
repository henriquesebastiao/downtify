# 艺人照片、横幅与简介

Downtify 可以为音乐库中的每位艺人显示真实头像、横幅和简介，而不只是生成的姓名首字母和空白文字区域。首次打开新艺人页面，或该艺人的一首歌曲下载完成后，会自动补充资料；之后可自行选择其他照片或横幅，重新获取或编写简介，并手动填写社交链接。

每个音乐库艺人页面都可以编辑，无需先开启任何设置。

::: info 关于设置中的“自动获取艺人照片”和“自动获取艺人横幅”
**设置 → 下载与文件 → 自动获取艺人照片 / 自动获取艺人横幅**决定 Downtify 是否可以自行保存艺人照片或横幅。自动保存发生在首次打开艺人页面或其歌曲下载完成时，参见[首次打开新艺人](#the-first-time-you-open-a-new-artist)和[下载完成时](#when-a-download-finishes)。照片默认开启，横幅默认关闭。这些设置不限制编辑对话框，无论如何都可手动选择照片或横幅。
:::

## 编辑对话框

**艺人设置横幅后，页头会隐藏圆形头像**：通常横幅已经足够，同时显示会显得拥挤。照片并未删除，仍可在编辑对话框的另一个标签页中编辑。

在音乐库艺人页面（`/library/artist?name=…`），将鼠标移到圆形头像上（显示时）可看到**编辑照片**按钮，移到横幅区域可看到**编辑艺人**按钮。两者打开同一个对话框，顶部显示当前照片，下方有四个标签页。点击照片或横幅入口时，分别打开**头像**或**横幅**；其他情况默认打开**横幅**，因为照片未必显示，无法点击。

- **头像** / **横幅**：两者使用相同的选图方式：
  - **按姓名搜索**：从 YouTube Music 和 Deezer 查找匹配的艺人照片，Deezer 只有通用占位图的艺人会排除。可输入其他姓名重新搜索，也可输入直接的 `http(s)://` 图片链接，将其作为本次候选。
  - **从设备上传**：可上传任意图片文件。
  - **移除照片 / 移除横幅**：只在当前标签页已有保存图片时显示，确认后删除对应附属文件。

  每个搜索结果卡片都会标明来源，选择后立即下载并保存。头像和横幅标签页分别为当前使用的候选显示绿色边框和勾号，方便识别。自行上传的照片，或 Downtify 开始记录此信息之前保存的照片，没有对应卡片可标记。
- **简介**：纯文本框显示当前保存的简介，没有则为空，可自行撰写或编辑。保存会直接覆盖当前文本。文本框上方的“⚡ 从流媒体获取简介”按钮可从 Apple Music/Deezer 填入内容，无需手动输入，参见下方[自动获取简介](#fetching-a-bio-automatically)。
- **社交**：可直接编辑 Twitter/X、Instagram、Facebook、YouTube 和网站链接。保存时，五个字段都会被表单内容替换，包括留空字段。获取简介不会改动已填写的链接，Deezer 提供的社交链接只填入空字段；Deezer 不一定提供所有平台信息，可自行补全，之后仍会保留。

## 首次打开新艺人

打开音乐库艺人页面时，若尚未保存任何资料，会自动初始化。首次之后的访问会快速跳过，因此不会重复执行或拖慢页面。

- **照片和横幅**：从 Spotify 获取，参见下方 [Spotify](#spotify)；Spotify 没有时，回退到姓名精确匹配的 YouTube Music 艺人。只有设置中开启**自动获取艺人照片**或**自动获取艺人横幅**时才执行，两者默认均关闭且相互独立；编辑对话框始终可以手动设置。
- **简介、来源地、成立年份、流派、组合标记、横幅颜色、社交链接、相似艺人和平台 ID**：按下方[自动获取简介](#fetching-a-bio-automatically)的方法，从 Apple Music 和 Deezer 获取。

若 Apple Music 或 Deezer 在此过程中**失败**，例如无法访问或请求限额用尽，则不会保存任何内容，包括简介和照片。页面暂时不显示资料，下次访问会重试。只有服务明确回答不认识该艺人，才算有效结果，此时使用另一服务提供的内容创建资料。Spotify 提供的相似艺人部分不会阻止资料创建。

## 下载完成时

艺人的一首歌曲下载完成后，若尚无资料，会在后台执行相同初始化。无论下载由你在应用中发起，还是由[播放列表监控](playlist-monitor.md)检查触发，都适用，因此下载的艺人在首次打开页面前就可准备好资料。这不会拖慢下载：艺人会进入队列，几秒后开始补充，每次同时处理两位。已入队的艺人不会因多首歌曲下载而重复入队，50 首同一艺人的播放列表也只初始化一次。音乐库中已有的歌曲不会重复下载，也不会触发初始化。

- **选择哪位艺人**：文件归属的艺人，优先专辑艺人，否则使用第一位署名艺人。跳过 `Various Artists`。
- **语言**：简介和流派使用网页界面语言，页面会将其保存到服务器，参见[国际化](internationalization.md)。页面尚未告知语言时使用英语。
- **照片和横幅**：按执行时读取的**自动获取艺人照片**和**自动获取艺人横幅**设置处理，因此修改设置会从下一首歌曲生效。
- **热门歌曲**：不会在此时生成，需等到打开艺人页面，参见[热门歌曲](top-songs.md)。

若各来源均未找到某位艺人的资料，也只执行一次，不会在以后每次访问时重试。之后可随时在编辑对话框中手动选择照片或横幅，或再次点击获取按钮。

## 链接标签页

至少有一个已保存链接的艺人会显示**链接**标签页，位于最后一个**简介**标签页之前，并显示链接数量。无论屏幕大小或是否设置横幅，都会以卡片列出，先是**流媒体平台**，再是**社交网络**。每张卡片显示站点名称和地址，并在新标签页打开。只显示实际保存的链接；没有链接的艺人不显示链接标签页，访问其 `?tab=links` 时会打开第一个标签页。

- **流媒体平台**：Spotify、YouTube Music、Deezer 和 Apple Music，按资料中的 `platforms_id` 生成，每个已保存 ID 转成链接，例如 Deezer ID 会生成对应艺人页面链接。首次获取简介时会在各平台按姓名精确匹配并自动解析 ID；Spotify ID 若可用，会从艺人自己的 Spotify 歌曲获取，避免匹配到同名艺人。也可在艺人资料 JSON 中手动添加或修正，见下文。
- **社交网络**：Twitter/X、Instagram、Facebook、YouTube 和网站，每个社交标签页中的非空字段显示一张卡片。只打开网页地址：未写 `https://` 的链接会自动补上，`javascript:` 等其他类型地址会忽略。

## Spotify

Spotify 不作为自由文本搜索来源显示，但选图器和首次访问自动初始化仍会尝试在那里查找艺人。首先检查该艺人已有的几首下载歌曲：若其中一首来自 Spotify，Downtify 已知其 Spotify ID，便可直接解析图片。这是最可靠的方式，不会匹配到同名艺人。没有 Spotify 来源歌曲时，例如歌曲来自 YouTube，会改为精确姓名查找，忽略大小写，不接受近似匹配。在选图器中，该候选显示在最前面，标记为 **Spotify**。

姓名查找使用 Spotify 网页播放器自身的搜索，因此依赖 Spotify 可能更改的内部标识符。若标识符变化，Downtify 会回退到 YouTube Music 获取照片或横幅，并将 Spotify ID 留空，不会让整个流程失败。

Spotify 的照片和横幅确实是不同图片，也使用不同解析方式：方形照片来自艺人公开 embed 页面，宽横幅来自 Spotify 艺人页面数据，embed 不提供横幅。并非每位艺人都有横幅；没有时，横幅选择器不会提供 Spotify 候选，也不会用方形照片代替。

尚无 Spotify 来源歌曲的艺人不会提供 Spotify 候选，可改为搜索 YouTube Music/Deezer、粘贴链接或上传图片。

## 自动获取简介

艺人页面在页头下方显示只读短简介，保存前为空。要补充内容，打开编辑对话框的**简介**标签页，点击文本框上方的**从 Apple Music 获取**或**从 Deezer 获取**（参见[选择来源](#choosing-the-source)），将该服务的简介载入文本框，供检查和保存。自动首次初始化会自行保存：使用 Apple Music 应用自身的姓名搜索方式精确匹配艺人，并获取简介、来源地、成立年份、流派、组合标记和横幅强调色；简介和流派使用当前界面语言。Apple Music 为每位艺人提供一个流派，例如“Hard rock”，显示在艺人页面简介标签页顶部，位于来源地和成立年份旁。Apple Music 还会说明是否为组合：组合的日期显示为“成立于 1995”，个人艺人的日期通常为生日，显示为“出生于 1984 年 9 月 27 日”。标签会随界面语言翻译，组合标记未知时仍显示“成立于”。日期内容本身按 Apple Music 返回值显示，保留获取时的语言。若 Apple Music 没有精确匹配，或对应语言没有简介，会尝试 Deezer 作为第二来源；Deezer 还会提供社交链接和“歌迷也喜欢”的相似艺人姓名，并补充社交标签页。相似艺人会保存到资料文件，但目前不显示，留待未来功能使用。只有两个来源都没有任何资料时，才显示错误，而不会猜测或使用错误简介。

Apple Music 的编辑简介并非每位艺人都有全部语言版本。某位艺人缺少指定语言时，会使用 Deezer 简介（若有），但来源地、成立年份和组合标记仍取自 Apple Music，因为这些事实不是翻译文本；流派只取自 Apple Music，因此 Apple 没有匹配时会留空。少数语言，如撰写原文时的保加利亚语，Apple Music 完全不提供，会始终回退到默认语言简介。

简介以纯文本保存在艺人 JSON 中，不含 HTML 标签或项目符号：段落之间使用空行分隔，Apple Music 简介中原本以单次换行分隔的每个 `•` 项目也会转为独立段落。Deezer 的 HTML 简介同样转换，各段落用空行分隔，其他标签全部移除。艺人页面会分别显示段落，并保留段内单次换行；简介标签页文本框编辑的就是这份文本。

再次获取只会在点击按钮时执行，不会在首次自动初始化之后自行覆盖内容。只有第一次获取，无论自动还是手动，才需按姓名搜索；解析后的 Apple Music 和 Deezer 艺人 ID 会缓存到资料文件，以后直接重新读取同一艺人。

要清除已保存简介，打开简介标签页，清空文本框并点击保存。来源地、成立年份、流派、组合标记、社交链接、相似艺人和缓存的平台 ID 均保持不变。

## 选择来源

简介标签页的文本框上方有两个链接，可选择哪份简介更合适：

- **从 Apple Music 获取**：将 Apple Music 编辑简介载入文本框。该艺人没有当前语言简介时，显示错误而不使用替代内容。
- **从 Deezer 获取**：即使 Apple Music 有简介，也可载入 Deezer 简介；Deezer 没有时显示错误。

点击链接**只填入文本框**，点击**保存**前不会写入，因此可先阅读、编辑或尝试另一服务，直接关闭对话框会保留原简介。这些链接只载入简介文本，不改动来源地、成立年份、流派、社交链接、相似艺人和平台 ID；这些信息由首次自动初始化填写。自动初始化不会询问来源，会优先 Apple Music 简介，只有 Apple Music 没有时才回退到 Deezer。

## 文件位置

```
<downloads>/.metadata/ArtistImage/<Artist>.jpg
<downloads>/.metadata/ArtistBannerImage/<Artist>.banner.jpg
<downloads>/.metadata/ArtistData/<Artist>.json
<downloads>/.metadata/ArtistTopSongs/<Artist>.topsongs.json
```

每位艺人对应一个同名文件，名称按歌曲文件名相同的规则处理，不依赖数据库记录，艺人页面直接检查磁盘文件是否存在。保存新照片或横幅会覆盖旧文件。为避免网页继续显示缓存的旧图，每张已保存图片的 URL 都带有文件修改时间，因此替换后的照片会重新获取，未修改的仍使用缓存。`ArtistData/<Artist>.json` 保存上述简介、社交、相似艺人和平台 ID 信息，还通过 `current_cover` 和 `current_cover_banner` 记录当前照片和横幅的图片来源：保存下载 URL 的路径，不含主机和查询参数，因此同一图片换用其他 CDN 地址仍可匹配；上传图片则记为 `upload`。编辑对话框按这些值比对候选，标记当前使用项。它们都是下载文件夹中的普通文件，Navidrome 等服务指向同一位置后也可直接读取。

艺人姓名匹配遵循磁盘命名方式：Downtify 会将 `AC/DC` 保存为 `ACDC`，因为文件名不能包含 `/`；没有艺人标签的歌曲会从文件名提取艺人，因此同一艺人可能显示为 `AC/DC` 或 `ACDC`。Spotify、Deezer、YouTube Music 和 Apple Music 的所有姓名查找都会忽略大小写和文件名不允许包含的字符，因此两种写法会找到同一艺人，并共用上述文件。其他方面不同的姓名，例如 `AC/DC Tribute`，仍视为不同艺人，不会匹配。

`platforms_id` 支持 `spotify`、`youtubemusic`、`deezer` 和 `applemusic`，均自动解析。Spotify 优先从艺人自己的 Spotify 歌曲获取，否则精确姓名匹配；其他平台均按精确姓名匹配。获取简介也会补充缺失的 Spotify ID，因此此前打开过的艺人可在获取一次简介后显示 Spotify 图标。已保存 ID 不会替换，也可直接编辑 JSON 手动设置。

## 不涉及的内容

在此选择照片或横幅不会影响下载流程，也不会改变音频文件标签中嵌入的内容；下载歌曲本身不会自动获取艺人图片。

“歌迷也喜欢”标签页也会为尚未收藏的艺人显示照片，音乐库的“艺人”网格、艺人自身页面、监控的“艺人”标签页（列表及编辑对话框中的监控对象）、[发现](discover.md)和[查找](finder.md)中的艺人也一样。这些页面已有艺人的 Deezer 图片，无需按姓名搜索；自行保存的照片会优先显示。搜索页的艺人结果也采用相同方式，使用 YouTube Music 图片，由服务器转发，因为 Google 图片 CDN 可能拒绝页面一次加载大量照片；服务器无法转发时则直接从 YouTube Music 加载。粘贴艺人链接的照片同样处理，使用该链接所属的 Spotify、Deezer 或 YouTube Music 图片，适用于未自行选图的艺人。Deezer 没有图片时，音乐库和艺人页面会使用该艺人的歌曲封面；监控没有歌曲可用，则显示首字母。只使用真实照片，Deezer 返回通用占位图时也会改为首字母。这些图片仅用于显示：服务器转发到浏览器，浏览器缓存三小时，不保存为艺人照片或横幅。只有有效响应会缓存；Deezer 不可达或请求被限流时，暂时显示首字母或歌曲封面，不记住失败，因此下次打开页面可再次显示照片。只有你自行设置的照片，或首次访问时按上述设置允许自动保存的照片和横幅，才会写入磁盘。参见 [`GET /api/artists/photo-proxy`](../api-reference.md#get-apiartistsphoto-proxy)。
