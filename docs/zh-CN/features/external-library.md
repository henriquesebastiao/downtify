# 现有音乐文件夹

Downtify 媒体库由它下载的文件构成，也可以包含你指定的**额外文件夹**。这些文件夹不会复制到 `/downloads`。Downtify 会读取每个文件的标签（标题、艺人、专辑、曲目编号、年份），跳过已有歌曲，并在媒体库和播放器中将其他歌曲归入匹配的艺人。

## 添加文件夹

1. 将主机文件夹挂载到容器中（Docker）。在设置中输入的路径必须是**容器内部**路径，规则与 [slskd 下载目录](slskd-navidrome.md)相同。
2. 打开 **Settings → Library**。
3. 在 **Existing music folders** 下添加一个或多个路径（例如 `/music/collection`）。输入时会提示可用目录。
4. 若暂时不想同步，可点击 **Save** 保存列表；也可以点击 **Sync folders**，保存列表并立即扫描。

```yaml
services:
  downtify:
    volumes:
      - ./downloads:/downloads
      - /path/on/host/to/mp3s:/music/collection
      - downtify_data:/data
```

然后在设置中填写 `/music/collection`。

::: warning 文件会留在原位置
同步不会将文件复制到 `/downloads`。如果文件夹可写，Downtify **会**像处理下载文件一样写入附加信息：歌词（以及 `.lrc` 旁置文件，可放在音频旁或设置中指定的目录）、缺失的封面，以及可从 iTunes 获取的流派信息。之后再次同步时，即使标签中已有歌词，也会补写缺失的旁置歌词文件；当源文件可写时，还会将现有 `.lrc` 文件**移动**到当前设置的目录。从 Library 页面删除曲目仍会删除磁盘上的对应文件。
:::

::: tip 只读挂载
如果不希望 Downtify 改写 MP3，请使用 `:ro` 挂载收藏目录。同步仍会建立索引。请将 `.lrc` 文件放在[歌词目录](lyrics.md#sidecar-lrc-file)中（关闭 **Keep .lrc next to the audio**）。缺失封面会保存到 `/data/cover_cache`，通过媒体库封面接口提供，而不是写入 MP3。iTunes 流派会保存在 Downtify 媒体库元数据库中，不会写入文件。只读文件旁已有的 `.lrc` 会被**复制**到歌词目录，原文件保持不变。
:::

## 同步会执行什么操作

1. 遍历所有配置文件夹，查找可播放音频（与媒体库其他部分相同，支持 MP3、M4A、FLAC、OGG、WAV、AAC、OPUS）。
2. 读取嵌入标签。没有标题或艺人的文件会像其他媒体库行一样，回退到文件名中的 `Artist - Title`。
3. 如果媒体库中已有相同歌曲（艺人和标题相同；如果双方都知道时长，则时长也须相差几秒以内），**跳过**该文件，无论它是由 Downtify 下载还是来自其他额外文件夹。
4. 将艺人名称与媒体库中已有名称**匹配**（`The Beatles` 和 `Beatles` 会被视为同一艺人）。无法匹配到已知艺人的名称会成为新艺人。如果启用了艺人资料设置，新艺人也会像下载完成时一样加入资料补全队列（例如照片和简介）。
5. 文件夹可写时，会像下载一样**补充标签**。每首导入曲目都会使用相同的歌词来源、封面查找（仅在文件没有封面时）和 iTunes 流派查找。歌词会写入文件；`.lrc` 旁置文件会写在音频旁或 Settings 中指定的[歌词目录](lyrics.md#sidecar-lrc-file)。封面和流派受[下载设置](download-settings.md)（`download_cover_art`、`download_lyrics`）控制。只读挂载不会改写 MP3：缺失封面保存在 `/data/cover_cache`，流派保存在媒体库目录中，`.lrc` 文件在配置时写入歌词目录。查找任务按**并行下载**设置分批运行；Settings → Downloads & files 中的 **Pause between sync lookups** 会在批次之间等待，避免大型文件夹对来源服务触发速率限制。
6. 使媒体库路径缓存失效，让 Library 页面和播放器无需等待常规扫描 TTL 即可显示结果。

同步在**后台**运行。你可以离开设置页；返回时若任务仍在运行，页面会显示同步状态。任务结束后，设置页会显示**最近一次同步日志**（导入数量、重复项、错误，以及歌词/封面相关信息）。

将更多文件放入这些文件夹后，再次点击 **Sync folders**。即使只保存文件夹列表而不立即同步，这些文件也会在下一次媒体库扫描中纳入索引（约一分钟后，或下一次下载/删除时）。

从列表中移除文件夹会**取消映射**：相应曲目会从媒体库和播放器中移除，由 Downtify 生成的附加文件（`.lrc` 旁置文件、缓存封面）也会删除，但磁盘上的音频文件仍保留。

同步完成后会报告不存在或无法读取的文件夹，其他文件夹仍会继续扫描。

## 媒体库路径

额外文件夹中的文件使用虚拟路径 `ext/<id>/…`；其中 `<id>` 是根据文件夹路径生成的哈希，因此文件夹列表可以重新排序。播放器和 `GET /media/…` 使用该路径，与保留在原位置的 Soulseek 文件使用 `slskd/…` 类似。

已经位于 `/downloads`（或 slskd 来源目录）**内部**的文件夹会被忽略，因为该目录树已经属于媒体库。

## API

| 方法 | 路径 | 说明 |
| ------ | ----------------------------- | -------------------------------------------------------------------------------- |
| `POST` | `/api/library/external/sync` | 启动后台扫描。可选请求体 `{folders: ["/path", …]}` 会先保存文件夹列表。 |
| `GET` | `/api/library/external/sync` | 获取正在运行的任务，或最近一次完成日志。 |
| `POST` | `/api/library/external/unmap` | 移除一个文件夹的媒体库映射，但不删除音频。 |

响应结构请参阅[API 参考](../api-reference.md#post-apilibraryexternalsync)。

## 主媒体库文件夹

在 **Settings → Library → Primary library folder** 中选择一个已登记的外部文件夹，使其内容优先显示。默认设置会保留现有行为。匹配时必须同时满足艺人、完整标题（包括版本信息）和专辑；未知元数据不会导致其他文件被隐藏。选定来源可以代表包含片头/片尾剪辑的另一份录音。

这只是列表显示偏好，不会迁移文件。源文件、已保存的播放列表路径、所有权、点赞和可见性规则都不会改写或删除。显示条目的播放列表徽标会合并；显式保存的播放列表仍播放其原始路径。选定文件夹中不同专辑和版本仍会分别显示。文件夹为空或不可用时，会回退到媒体库其余内容。移除该文件夹后会重置此偏好。
