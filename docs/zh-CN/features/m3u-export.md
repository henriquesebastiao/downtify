# M3U 导出

每当下载 Spotify 播放列表时（手动下载或通过 [Playlist Monitor](playlist-monitor.md) 下载），Downtify 都会自动生成标准 `EXTM3U` 播放列表文件。

## 文件位置

| 情况 | M3U 路径 |
|-----------|---------|
| 正常下载播放列表 | `<downloads>/<playlist-name>/<playlist-name>.m3u` |
| 启用 *Organize by artist* 后下载播放列表 | `<downloads>/Playlists/<playlist-name>.m3u` |

启用 *Organize by artist* 后，曲目会分散在多个艺人目录中，因此 M3U 会放在集中管理的 `Playlists/` 目录中，而不是播放列表子目录。

[喜欢的歌曲](liked-songs.md)也会写入 `Playlists/Downtify Liked Songs.m3u`，无论目录布局如何，也不受 *Write M3U playlists* 开关影响。

## 相对路径

M3U 中的曲目路径是相对于 **M3U 文件自身**写入的，而非绝对路径。因此，无论在 Downtify 容器内（`/downloads/…`）还是通过其他根目录挂载相同媒体库的程序中读取（例如 Jellyfin 使用 `/nas/music/…`），同一文件都能使用。只需让媒体服务器指向同一媒体库挂载点，播放列表就会作为一个整体显示。

## 启用或禁用

通过 **Settings → Downloads & files → Write M3U playlists** 控制 M3U 生成（默认开启）。关闭后完全跳过 M3U 创建，不会影响下载流程的其他部分。

## 封面

其下方的 **Save playlist cover art**（默认开启）会将播放列表自己的封面图与 M3U 以相同名称保存在同一目录中，并在曲目下载前就写入，因此目录从一开始看起来就像该播放列表。随后 Downtify 会使用此图片作为播放列表封面，而不是显示曲目封面拼图。在 Library 中创建的播放列表也会以相同方式生成最多由四张曲目封面组成的拼图。参见[播放列表封面](playlist-cover-art.md)。

## 写入时机

每首曲目下载完成后都会重写 M3U，因此播放列表文件会随下载进度逐步增长，而不必等到全部结束。播放列表和专辑下载、[CSV 导入](library-import.md)以及 [Playlist Monitor](playlist-monitor.md#m3u-integration) 扫描都适用此规则。

因此，第一首歌曲写入后就可以开始播放；你可以随时确认同步进度，单首下载缓慢或挂起也不会阻止 M3U 或已完成曲目显示。

整批任务完成后还会执行最后一次重写。此时会根据文件系统逐一解析所有曲目（而不是只使用当前批次在内存中的下载列表），因此也会纳入之前批次下载的文件，并修正任务运行期间磁盘上的变化。

每次写入都按**播放列表顺序**排列曲目，而不是按下载完成顺序，因此即使 M3U 尚未写完，曲目顺序也始终正确。

::: info 已存在于磁盘的曲目
之前任务下载的曲目会始终保留在 M3U 中：首次写入时就会包含它们，而不只是等到最后一次写入才添加。
:::

## 重新生成

每次运行时都会重新生成 M3U；再次粘贴相同播放列表 URL 会生成完整且顺序正确的文件，并包含之前批次遗漏的曲目。

下载失败或无法匹配 YouTube Music 的曲目会被静默跳过。

## 兼容性

生成的文件采用：

- UTF-8 编码，无 BOM
- LF 换行符
- 标准 `#EXTM3U` / `#EXTINF` 格式

兼容 Jellyfin、Navidrome、Plex、VLC、Kodi、Sonos，以及所有支持标准 M3U 播放列表的播放器和媒体服务器。

Library 读取已有 `.m3u` 播放列表时，会先尝试严格 UTF-8，并接受可选的 UTF-8 BOM。解码失败后会尝试严格 Windows-1252，与外部播放列表导入器使用相同的回退方式；这也支持包括 `Beyoncé` 在内的可打印 Latin-1 文本。这是回退策略，并非自动检测编码；其他旧式编码可能需要先转换为 UTF-8。`.m3u8` 必须使用 UTF-8，不会回退到旧编码；Library 扫描仍只会发现 `.m3u` 文件。

如果两种允许的编码都无法解码、文件包含 NUL 字符（例如 UTF-16 数据），或文件无法打开，Downtify 会跳过该播放列表，并记录路径和提醒检查权限或保存 UTF-8 副本的警告。其他播放列表仍会继续加载。系统绝不会静默丢弃或替换字符，读取时也不会重写播放列表或音频文件。明确编辑播放列表时仍会写入 UTF-8。

## 创建的播放列表

**Library → Playlists → New playlist** 会在 `Playlists/` 中写入相同类型的 M3U 文件，并额外加入一行 `#EXTDOWNTIFY:manual`，以便 Downtify 将它与从 Spotify/YouTube 链接下载的播放列表区分开。你可以重命名列表、添加或移除歌曲（包括来自[额外文件夹](external-library.md)的歌曲）。删除该播放列表、删除曲目或取消映射额外文件夹时，M3U 会同步更新；只有删除曲目本身或删除导入的播放列表时，音频才会被删除。

### 向播放列表添加歌曲

管理员可以通过以下入口将歌曲加入这些播放列表或新建播放列表：

- 在任意曲目列表中打开**歌曲的 ⋯ 菜单** → **Add to playlist**。
- 在 Library 中**选择多首歌曲**，然后点击 **Add to playlist**。
- 打开**专辑的 ⋯ 菜单** → **Add to playlist**，将专辑中的所有歌曲加入列表。
- 在艺人页面打开**艺人的 ⋯ 菜单** → **Add to playlist**，按专辑将该艺人在媒体库中的所有歌曲加入列表。

每个菜单都会列出你的播放列表，并提供 **New playlist…**，可创建一个已包含所选歌曲的新列表。若歌曲已在列表中，则会跳过；确认消息会说明实际添加数量，或告知歌曲已全部存在。每个播放列表最多可包含 500 首歌曲。
