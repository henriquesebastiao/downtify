# Обновление библиотеки

Библиотека, накопленная со временем, несёт в себе всё то, что умела каждая версия Downtify на момент скачивания трека: самую маленькую обложку, какую предлагал источник, отсутствие текстов, теги без альбома и года. **Обновление библиотеки** смотрит, что уже лежит на диске, и исправляет только отставшее — без повторной загрузки и без ручной разборки.

Открывается из **Библиотека → Обновить библиотеку**.

::: info Обычное обновление переписывает только теги
Режим по умолчанию переписывает **обложки, тексты и теги**. Необязательная [замена записей через Deemix](#deemix-recording-replacement) — отдельный режим сканирования, по умолчанию отключённый. Чтобы вручную выбрать другую версию, используйте [Замену аудио](replace-audio.md).
:::

## Как это работает

1. **Сканирование.** Downtify читает каждый трек библиотеки и по категориям сообщает, что отстало. Ничего не записывается.
2. **Выбор.** Каждая категория, где сканирование что-то нашло, показана со счётчиком треков и переключателем. Снимите галочки с ненужного.
3. **Обновление.** Выбранные треки попадают в очередь, которая разбирается по одному. Её можно поставить на паузу, продолжить или остановить, и она переживает перезапуск.

## Что она исправляет

| Категория               | Что делает                                                                                                                | Откуда берёт                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **Обновить обложки**    | Заменяет обложку меньше целевого размера                                                                                    | Spotify, Apple Music (iTunes), YouTube Music      |
| **Добавить недостающие тексты** | Заполняет тексты для треков, где их нет, — встраивает их в файл и пишет sidecar-файл `.lrc`                        | Ваши [провайдеры текстов](lyrics.md), в вашем порядке |
| **Обновить теги**       | Заполняет альбом, артиста альбома, дату релиза и номер трека — включая альбом, которого не хватает старым загрузкам одиночных треков | Spotify                                           |

Трек считается отставшим, когда:

- короткая сторона его встроенной обложки **меньше целевого размера** (трек вовсе без обложки тоже считается);
- у него **нет ни** встроенных текстов, **ни** sidecar-файла `.lrc` (рядом с файлом или в папке текстов из Настроек);
- в его тегах нет любого из полей **альбом**, **артист альбома**, **год** или **номер трека**.

**Обновление тегов** работает только для треков, для которых Downtify ещё хранит Spotify track ID — тех, что скачаны по ссылке Spotify и лежат в [индексе треков](library-catalog.md#what-gets-stored). Остальные треки ставятся в очередь, но возвращаются со статусом _Делать нечего_.

## Параметры

### Обновлять обложки меньше

`300px` · `500px` · **`600px`** · `1000px` · `1200px`

Обложки такого размера или больше не трогаются. Downtify записывает обложку, только если она **строго больше** уже стоящей в файле, так что повторный запуск обновления ничего не переписывает зря.

Откуда берутся эти размеры:

| Источник                 | Типичный размер                                                             |
| ------------------------ | --------------------------------------------------------------------------- |
| **Apple Music (iTunes)** | от 1200px и выше                                                            |
| **Spotify**              | до 640px                                                                    |
| **YouTube Music**        | по настройке [разрешения обложек](download-settings.md), не больше ~1200px   |

Поэтому библиотека, скачанная раньше, часто застревает на 300–640px: Spotify публикует обложки в фиксированных размерах, а самый большой из них — 640px.

### Источник обложек

| Вариант                                                                | Поведение                                                                                            |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Максимальное доступное разрешение** (по умолчанию)                   | Опрашивает каждый источник и оставляет самое большое изображение                                      |
| **Предпочитать Spotify** / **Предпочитать Apple Music** / **Предпочитать YouTube Music** | Использует этот источник, когда у него есть хоть что-то; остальные — лишь запасной вариант, если у него ничего нет |

### Не проверять трек снова

`Always check every track` · `7 days` · **`30 days`** · `90 days` · `365 days`

После проверки трек пропускается следующим сканированием в течение этого срока, так что повторный заход по большой библиотеке не спрашивает у тех же источников про те же треки.

Память ведётся **по каждому треку и по каждой категории**, именно поэтому работают частичные запуски: обновление обложек у 16 000 треков ничего не говорит о том, искали ли когда-нибудь их тексты, так что последующий запуск текстов всё равно рассмотрит каждый из них. Сканирование запоминает и категории, которые просмотрело и где делать нечего, — «посмотреть и не найти» такая же проверка, как любая другая.

Downtify запоминает для каждого трека и категории: когда его проверяли, какая версия Downtify проверяла, а для обложек — самую большую найденную обложку и откуда она. Список уже опрошенных провайдеров текстов хранится отдельно, по каждой песне и провайдеру (см. [Тексты песен](lyrics.md)).

Два обстоятельства всегда отменяют эту память:

- **более новая версия Downtify** проверяет всё заново — она может лучше подбирать записи и записывать теги, чем та, что работала раньше;
- выбор **Always check every track** игнорирует память для этого сканирования.

Когда сканирование не находит работы _потому что_ всё недавно проверялось, оно так и сообщает и предлагает запуститься снова без памяти, а не оставлять вас с необъяснимым «обновлять нечего».

## Во время работы

Панель прогресса показывает обработанные треки из очереди, примерный объём данных (`8.4 GB of 51.3 GB`) и сколько треков обновлено, где делать нечего и сколько с ошибкой. Каждый трек показывает, чем занят, — _Подбор_, _Поиск обложки_, _Поиск текста_, _Запись файла_ — и завершается тем, что изменилось, например `artwork 1200px (itunes)`.

**Пауза** останавливает работу после трека, который идёт прямо сейчас, и сохраняет очередь. **Остановить** отбрасывает её хвост; уже обновлённые треки остаются обновлёнными. Страницу можно покинуть — работа продолжается, а другие открытые вкладки следуют за ней.

Очередь хранится в `/data/downtify_library.db`, поэтому **перезапуск Downtify (или контейнера) посреди работы подхватывает её** с того же места. Трек, который был в обработке, когда процесс погиб, возвращается в очередь.

## Ничего не теряется, если обновление не удалось

Каждая запись идёт в рабочую копию рядом с оригиналом (`<name>.downtify-upgrade.<ext>`). Копия должна открыться как аудио той же длины, прежде чем встанет на место; иначе она выбрасывается, а оригинал остаётся нетронутым. Такой файл никогда не показывается как отдельный трек и исчезает, как только трек обработан.

Исходное **время изменения сохраняется**, так что обновление библиотеки не перетасовывает _Недавно добавленные_.

### Музыкальные папки только для чтения

Обновление переписывает теги на месте, поэтому треки на файловой системе только для чтения **пропускаются**, с объяснением, ещё до поиска метаданных, обложек или текстов. Они остаются доступными для воспроизведения и в своих плейлистах; их файлы и права монтирования не меняются. Пропущенный из-за «только чтение» трек не запоминается как успешно проверенный, поэтому его можно рассмотреть снова, если папка позже станет доступной для записи. Неожиданные ошибки прав доступа, места на диске и ввода-вывода по-прежнему показываются как ошибки.

Это отличается от [обогащения существующих папок](external-library.md), которое может хранить обложки и тексты отдельно в папке данных Downtify, не переписывая защищённые аудиофайлы.

## Почему аудио не заменяется

Обычное обновление тегов не заменяет аудио. Отдельный режим ниже требует точных метаданных записи и публикации эталона; сомнительные версии остаются на ручную проверку.

## Замена записей через Deemix

После включения и проверки [источника Deemix](deemix.md) **Обновление библиотеки** предлагает перед сканированием два независимых переключателя:

- **Использовать проверенные записи Deemix**: сканирование оригинальных загрузок Downtify, включая копии, скрытые предпочитаемой внешней коллекцией. Совпадение точного артиста, полного названия/версии и альбома; двусмысленные результаты каталога отклоняются. Длительность старого отрывка не используется для отклонения правильной записи из каталога. Проверяются скачанные теги, длительность по каталогу, выбранное качество и полный декод FFmpeg.
- **Удалять старое аудио Downtify после импорта**: дополнительно удалять каждый неизменённый оригинал после публикации. По умолчанию выключено. Сохранение оригиналов всё равно обновляет плейлисты и любимые песни до записи Deemix.

Это сканирование создаёт категорию **audio** вместо задач по обложкам/текстам/тегам. Deemix владеет выходными файлами, обложками, раскладкой альбома и нативными текстами. Downtify читает их на месте. Существующие нативные или встроенные тексты сохраняются; только отсутствующие тексты можно дополнить в доступной для записи отдельной папке текстов, не переписывая аудио. Лучший lossless-оригинал сохраняется, если Deemix настроен на MP3.

Публикация происходит один раз на батч. Комментарии M3U, ручные метки и порядок треков сохраняются, затем пути каталога, вхождения в плейлисты, отметки «нравится» каждого пользователя, владение и правила скрытых треков переносятся в одной транзакции SQLite. Кэшированные ID Navidrome для старых файлов инвалидируются для свежего нативного поиска. Выданные ранее мобильные ID и старые URL воспроизведения сохраняют read-only-алиасы к зарегистрированной замене; мутации эти алиасы URL никогда не используют.

Стойкие квитанции в базе данных библиотеки хранят SHA-256 источников и целей и состояние публикации. Источники остаются, пока замена и ссылки не пройдут проверку. Изменившееся или исчезнувшее монтирование, изменённый файл, внешняя ссылка из плейлиста «только чтение», активное воспроизведение или неудачная публикация в каталоге останавливают очистку с видимой причиной. Пауза/продолжение и перезапуск повторно используют квитанции. Общей чистки дубликатов или чистки по возрасту нет: подходят только проверенные оригиналы в папке загрузок Downtify. Ручные загрузки Deemix/slskd, внешние оригиналы, каталоги и sidecar-файлы никогда не удаляются. После удаления оригинала откат контейнера не вернёт файл; при необходимости восстановите его из собственного резервного хранилища.

Для пользователей NAS, у которых имена монтирований отличаются от путей Docker, администратор может задать `DOWNTIFY_DEEMIX_M3U_ROOT` — алиас контейнера, указывающий на корень Deemix. Относительные пути M3U используют этот алиас (например, `/Download` отображается на `/music/existing`). Необязательный `DOWNTIFY_LIBRARY_READY_MARKERS` — объект JSON из путей маркеров и ожидаемого текста, проверяемых перед подготовкой и очисткой. Отсутствие маркера останавливает работу. Ни одна из переменных не нужна для режима по умолчанию.

API сканирования принимает `replace_audio_deemix: true`, необязательный `delete_replaced_audio: true` и необязательный `files: ["relative/original.mp3"]` для ограниченного пилота. Запуск этого сканирования выбирает `categories: ["audio"]`. Статус выполнения включает счётчики замен и `finalization_error`, когда публикация приостанавливается. Исходный файл не удаляется лишь потому, что элемент очереди Deemix сообщает о завершении.

### Разбор сомнительной записи

Пропущенная или завершившаяся ошибкой задача из категории audio предлагает **Выбрать запись Deezer**. Вставьте точную ссылку на трек, посмотрите превью артиста, альбома и длительности, затем выберите **Проанализировать этот выбор**. Это лишь готовит новое сканирование одного трека; подтвердите это сканирование, чтобы начать замену. Автоматический подбор по умолчанию никогда не подменяет альбом наугад.

Такой явный выбор может исправить старую метку альбома, но полное название/версия и артист всё равно должны совпадать. Известный оригинал с флажком explicit не может молча превратиться в чистую версию. Выбранная запись проходит те же проверки длительности, качества, декодирования, эталона и удаления. Другой выбор не может молча переиспользовать уже подготовленную квитанцию. Полезная нагрузка расширенного сканирования записывает выбор как `deemix_recordings: {"relative/original.mp3": "123456"}`; она ограничена этим файлом и сохраняется для перезапуска и продолжения.

## API

| Метод | Путь                          | Описание                                        |
| ------ | ----------------------------- | ----------------------------------------------- |
| `GET`  | `/api/library/upgrade`        | Состояние выполнения, счётчики очереди и что нашло сканирование |
| `GET`  | `/api/library/upgrade/jobs`   | Строки по трекам (`status`, `stage`, `detail`)   |
| `POST` | `/api/library/upgrade/scan`   | Сканировать библиотеку; ничего не записывает    |
| `POST` | `/api/library/upgrade/start`  | Запустить выполнение для выбранных `categories` |
| `POST` | `/api/library/upgrade/pause`  | Остановить после текущего трека, сохранить очередь |
| `POST` | `/api/library/upgrade/resume` | Продолжить приостановленное выполнение          |
| `POST` | `/api/library/upgrade/cancel` | Отбросить остаток очереди                       |

Прогресс также передаётся по [WebSocket](../api-reference.md#websocket) как `{"type": "library_upgrade", "upgrade": {…}}`.

Форматы запросов и ответов см. в [справочнике API](../api-reference.md#library).
