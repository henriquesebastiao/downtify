# Тексты песен

Downtify ищет текст песни, пока трек загружается, и встраивает его в файл, а также сохраняет соседний файл `.lrc`, когда текст синхронизирован по времени.

## Включение текстов песен

Тексты **включены по умолчанию**. Отключите их в **Настройки → Теги и тексты → Загружать тексты песен**.

## Провайдеры и порядок отката

Каталоги различаются: песня, о которой один провайдер никогда не слышал, часто есть у другого. Поэтому Downtify держит упорядоченный список провайдеров и пробует их по одному, останавливаясь на первом, у которого что-то нашлось.

| Провайдер | Тексты | Примечания |
|----------|--------|-------|
| **[LRCLIB](https://lrclib.net)** | Обычные и синхронизированные | Бесплатная сообществская база, без ключа. Сопоставление по названию, основному артисту, альбому и длительности. |
| **NetEase Cloud Music** | Обычно синхронизированные | Большой каталог, силён на азиатских релизах и часто на западных тоже. Сопоставление по названию, артисту и длительности; находка, у которой артист написан иначе (например, традиционный против упрощённого китайского), принимается только когда и название, и длительность совпадают. |

В **Настройки → Теги и тексты → Провайдеры** можно перетащить провайдеров в нужном порядке или использовать стрелки, а также выключить любого из них. Хотя бы один остаётся включённым; чтобы полностью перестать искать тексты, используйте переключатель **Загружать тексты песен**.

::: info А как насчёт Genius, Musixmatch и AZLyrics?
Они недоступны, и Downtify больше их не предлагает:

- **AZLyrics** запрещает стороннее использование своих текстов в самой странице.
- Десктопный API **Musixmatch** отвечает пустым токеном, если у вас нет учётных данных, которые он не выдаёт приложениям.
- `robots.txt` у **Genius** запрещает конечную точку поиска, нужную, чтобы найти страницу песни.

Сохранённые настройки, которые всё ещё называют их, продолжают работать: имена игнорируются, а список, в котором не осталось ничего другого, откатывается к провайдерам по умолчанию.
:::

## Пропуск провайдеров, у которых ничего не было

После поиска Downtify записывает для каждой песни, какие провайдеры ответили и у кого оказалось пусто, в `downtify_library.db` под `/data`.

Провайдера, у которого не нашлось текста для песни, о ней не спрашивают снова **30 дней**, поэтому повторные загрузки и большие проходы по библиотеке не повторяют одни и те же неудачные поиски. По истечении этого срока он пробуется снова, ведь каталоги растут. Провайдер, у которого тексты *были*, никогда не пропускается, поэтому повторно загруженный файл получает их обратно.

## Встраивание

| Формат | Тег обычного текста | Тег синхронизированного текста |
|--------|-----------------|------------------|
| MP3 | `USLT` (ID3) | `USLT` с отметками времени |
| FLAC | `LYRICS` (комментарий Vorbis) | `LYRICS` с содержимым LRC |
| M4A | `©lyr` | `©lyr` с содержимым LRC |
| OGG / OPUS | `LYRICS` (комментарий Vorbis) | `LYRICS` с содержимым LRC |

## Соседний файл .lrc

Когда доступны синхронизированные тексты, Downtify также сохраняет файл `.lrc`. По умолчанию он лежит **рядом с аудио** с тем же базовым именем. В **Настройки → Теги и тексты** можно отключить это и вместо этого выбрать **папку текстов** (по умолчанию `/data/lyrics`). Эта папка должна быть **вне** `/downloads`, дерева slskd и любых дополнительных музыкальных папок — относительный путь аудио воссоздаётся под ней (`Артист/Альбом/track.lrc`). Медиапроигрыватели, читающие внешние тексты (и [встроенный плеер](player.md#now-playing)), всё равно подхватывают соседний файл. Изменение этого параметра и запуск **Синхронизации** на дополнительной папке копирует существующие файлы `.lrc` в новое место; исходный файл удаляется, когда это дерево доступно на запись, и остаётся на месте на монтировании «только чтение». Соседний файл записывается, даже если тексты уже встроены в теги.

Удаление трека со страницы Библиотеки убирает и `.lrc` (рядом с файлом и в выделенной папке) вместе с аудио, поэтому тексты никогда не остаются осиротевшим файлом.

## Когда ничего не найдено

Если ни у одного провайдера песни нет, загрузка продолжается как обычно — аудиофайл сохраняется без текста, и никакая ошибка не возникает.
