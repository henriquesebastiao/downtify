# Пользователи и вход

Каждый, кто пользуется Downtify, входит с **именем пользователя и паролем**, и у каждого может быть собственный аккаунт. Администратор управляет аккаунтами в **Настройки → Пользователи** и видит действия всех в **Настройки → Активность**.

## Первый вход

На новом сервере есть один аккаунт:

| Имя пользователя | Пароль |
|----------|----------|
| `admin` | `downtify` |

Войдите с ним и **смените пароль** в **Настройки → Общие → Аккаунт**: пароль по умолчанию знает каждый, кто знает Downtify. Пока вы этого не сделали, Downtify напоминает о нём после входа и показывает предупреждение в Настройках.

::: warning Смените пароль по умолчанию, прежде чем открывать сервер наружу
Пароль по умолчанию ничего не защищает. Смените его, прежде чем сделать Downtify доступным из-за пределов вашей домашней сети — и используйте там HTTPS (см. [За обратным прокси](mobile-apps.md#behind-a-reverse-proxy)).
:::

### Обновление с более старой версии

Сервер, работавший на версии без аккаунтов, получает тот же аккаунт `admin`, а страница входа один раз сообщает — пока администратор не войдёт — какие имя пользователя и пароль использовать:

- Если вы задали пароль в старой настройке **Требовать вход**, этот пароль продолжает работать для `admin`.
- Иначе это `downtify`.

Браузеры, вошедшие до обновления, входят заново. Телефоны, сопряжённые до него, остаются сопряжёнными и теперь принадлежат `admin`.

## Администраторы и пользователи

| | Администратор | Пользователь |
|---|---|---|
| Слушать, искать, скачивать, лайкать, Discover, Чарты, Поиск, подкасты | ✓ | ✓ |
| Сопрягать телефонные приложения (со своим аккаунтом) | ✓ | ✓ |
| Настройки → Общие (свой аккаунт и предпочтения), Приложения, О программе | ✓ | ✓ |
| Все остальные настройки (источники, файлы, теги, Navidrome, библиотека, сервер), переименование сервера | ✓ | |
| [Делиться своими плейлистами](#sharing-playlists) (только просмотр), подписываться на публичные, сохранять копии | ✓ | ✓ (если администратор разрешит) |
| Удалять файлы и плейлисты (пользователь — только [то, что скачал сам](#deleting-songs), и свои плейлисты), управлять своими отслеживаниями плейлистов и подписками на подкасты, заменять аудио трека, редактировать фото артистов | ✓ | ✓ (только свои) |
| [Скрывать песни, альбомы и артистов от пользователей](#hiding-from-users) | ✓ | |
| Управлять пользователями, видеть журнал активности | ✓ | |

Пользователь, который попробует действие, требующее администратора, получит об этом сообщение.

## Ваша библиотека

Библиотека общая: каждый аккаунт видит каждую песню, скачанную кем угодно, — в Библиотеке, в результатах поиска с пометкой «скачано» и на сопряжённом телефоне. Файлы никогда не хранятся дважды: когда два человека скачивают одну песню, она один раз попадает на диск — с одним владельцем у каждого.

Лайки, плейлисты (скачанные и созданные в Библиотеке) и очередь загрузок остаются вашими, если только вы не администратор — или не [поделитесь плейлистом](#sharing-playlists), чтобы его видели другие. Прослушивание общее: любой может проигрывать, прослушивать фрагменты или стримить любой трек и добавлять что угодно в свои плейлисты. Запрос трека, который кто-то уже скачивает, подключается к его заданию вместо повторной загрузки: одна строка в очереди, одна загрузка и владение у каждого — каждый ожидающий видит своё место в очереди.

Подкасты, отслеживания плейлистов и история Discover работают так же: каждый аккаунт подписывается на свои шоу, следит за своими плейлистами и артистами и обучает свои рекомендации. Администратор видит записи всех аккаунтов. Само прослушивание остаётся общим — любой может проигрывать, прослушивать фрагменты или стримить любой трек.

### Обмен плейлистами

Плейлист приватен для его владельца (и администраторов), пока владелец не откроет доступ — через **Поделиться…** на странице плейлиста или в его меню **⋯**. Воспроизведение уже общее между аккаунтами; здесь речь только о том, кто может *видеть* список. Открыть можно любой плейлист, кроме *Любимых песен*, включая импортированные.

| Видимость | Кто видит |
|------------|-------------|
| **Личный** | Только владелец и администраторы — по умолчанию |
| **Конкретные люди** | Пользователи, которых выбрал владелец |
| **Публичный** | Все на сервере |

Чужие плейлисты никогда не подмешиваются к вашим. Вкладка **Плейлисты** в Библиотеке перечисляет их в двух разделах под вашими, каждая запись с пометкой владельца:

- **Открыто мне** — плейлисты, адресованные вам по имени, показываются всегда. У заново открытого есть метка **Новый**, пока вы его не откроете.
- **Публичные плейлисты** — публичные плейлисты всех, отсортированные по владельцу и названию, с поиском по фильтру вкладки; показан владелец, число песен и подписаны ли вы. Раздел свёрнут по умолчанию, и его можно скрыть целиком через **Настройки › Общие › Показывать публичные плейлисты** (включено по умолчанию; это ваша настройка, как и тема).

Боковая панель тоже показывает несколько плейлистов, открытых вам, и несколько из публичных плейлистов, на которые вы подписаны.

**Что может делать смотрящий:** проигрывать, перемешивать, добавлять в очередь, скачивать ZIP-архивом (или в телефонное или десктопное приложение), **подписаться** на публичный плейлист, чтобы он оставался в его списках — даже при выключенной настройке *Показывать публичные плейлисты* — и следовать за изменениями владельца, а также **сохранить копию**: приватный, редактируемый плейлист у себя, с песнями, которые он видит. Смотрящий не может редактировать, переименовывать, удалять, открывать доступ или отвязывать чужой плейлист. Владелец плейлиста из Библиотеки может также сделать некоторых из тех, с кем он открыт, его редакторами — те добавляют и убирают его песни; см. [Совместные плейлисты](collaborative-playlists.md).

**Закрытие доступа:** когда владелец снова делает плейлист приватным или убирает кого-то из списка, плейлист тут же уходит из списков этого человека (подписан он или нет); плейлист, переставший быть публичным, перестаёт отслеживаться. Сохранённые копии остаются у людей. Переименование открытого плейлиста не отменяет доступ; удаление плейлиста забирает доступ с собой. Песни, которые администратор [скрыл от пользователей](#hiding-from-users), исключаются из треков открытого плейлиста для них, как и везде.

Администратор может отключить всё это через **Настройки › Библиотека › Разрешить пользователям открывать доступ к плейлистам** (включено по умолчанию). Пока настройка выключена, все открытия скрыты, и никто не может открыть доступ или подписаться — открытия вернутся, когда её снова включат.

Сопряжённые приложения получают те же списки: [`GET /api/v1/playlists`](../api-reference.md#get-apiv1playlists) сообщает, кто владеет каждым и открыт ли он только для просмотра, а `playlists_changed` по WebSocket велит им обновиться.

### Скрытие от пользователей

Администраторы решают, что видят остальные аккаунты. Всё видно всем, пока администратор что-то не скроет: **песню**, целый **альбом** или целого **артиста**. Скрытое уходит из Библиотеки, из пометок «в библиотеке» в поиске, из списков треков плейлистов и из того, что синхронизирует сопряжённый телефон, — для пользователей, но не для администраторов.

- **В Библиотеке** откройте меню `…` песни, альбома или артиста и выберите **Скрыть от пользователей** (или **Показать пользователям**, чтобы отменить). На вкладке Треки выберите несколько песен и используйте **Скрыть от пользователей** в панели выделения.
- Администраторы видят всё. Скрытое носит маленький перечёркнутый глаз, а подсказка объясняет почему: скрыто само, вместе с альбомом или вместе с артистом.
- **Настройки › Пользователи › Скрытое от пользователей** перечисляет всех скрытых артистов, альбомы и песни; рядом с каждым — **Показать пользователям**.
- Скрытая песня остаётся скрытой при перемещении в другую папку и когда [Обновление библиотеки](library-upgrade.md) или [Замена аудио](replace-audio.md) переписывают её файл. Удаление файла забывает правило.
- Правило альбома сопоставляет артиста и название альбома, а правило артиста — артиста, под которым Библиотека группирует песню: те же имена, что используют вкладки Альбомы и Артисты Библиотеки.

::: info Скрытие — о том, что показывается в списках
Оно управляет тем, что аккаунты видят в приложении, а не тем, кто может забрать файл, адрес которого уже знает. Не используйте его для защиты чувствительных файлов.
:::

Скрытие и показ записываются в [журнал активности](#activity).

### Удаление песен

Удаление песни убирает её с диска для всех, поэтому она следует за тем, кто её скачал. Администратор может удалить что угодно. Пользователь может удалить песню, которую скачал сам; если ту же песню скачал и кто-то ещё, удаление лишь отказывается от его собственной претензии, и песня остаётся в общей библиотеке. Песню, которую никто не скачивал через аккаунт (проверка монитора плейлистов, загрузка времён «до аккаунтов», [внешняя папка](external-library.md)), может удалить только администратор. Удаление вашего плейлиста никогда не уносит чужие файлы.

### Использование по аккаунтам

**Настройки › Пользователи** перечисляет у каждого аккаунта, что он содержит: треки и их размер, лайки, плейлисты, заказанные загрузки и трафик в обе стороны (полученный от источника и отданный клиентам), а под ними — итоги по всем. «Треки» считает песни, которые аккаунт скачал, а не те, что он может видеть.

## Ваш аккаунт и предпочтения

**Настройки → Общие** начинается с вашего **Аккаунта**: смените имя пользователя или пароль либо выйдите из системы. Выйти можно и из боковой панели (или через **Ещё** на телефоне).

Остальное в **Общих** — тема, язык, показ текстов песен в плеере, альбомы в результатах поиска — **ваше**: оно следует за вашим аккаунтом в каждый браузер, куда вы входите, и ничего не меняет для других.

**Настройки → Приложения** перечисляет телефоны, сопряжённые с вашим аккаунтом (администратор видит все — с их владельцами). **Выйти везде** отвязывает ваши приложения и выгоняет вас из всех браузеров.

## Управление пользователями

В **Настройки → Пользователи** администратор может:

- **Добавить пользователя** — имя (от 3 до 32 букв, цифр, `.`, `-` или `_`), пароль (минимум 8 символов) и роль.
- **Изменить** пользователя — переименовать, сделать администратором или пользователем либо задать новый пароль (это выгонит его из браузеров; приложения останутся сопряжёнными).
- **Удалить** пользователя — его приложения отвяжутся, а из браузеров его выгонят. Его файлы останутся на диске (администраторы их видят); его лайки, плейлисты, подписки на подкасты, отслеживания, история рекомендаций и счётчики трафика уйдут вместе с ним.
- **Разлогинить всех** — приложения всех пользователей отвяжутся, из всех браузеров — включая ваши — выгонят.

Администратор всегда есть хотя бы один: последнего нельзя удалить или сделать пользователем, а свой аккаунт нельзя удалить.

## Активность

**Настройки → Активность** (администраторы) показывает, как панель Jellyfin:

- **Сейчас играет** — что играют браузеры и приложения, кто, на каком месте песни и на паузе ли. Обновляется каждые несколько секунд.
- **История** — входы (и неудачные — с адресом, откуда они пришли), выходы, проигранные песни, загрузки, лайки, удалённые файлы, песни, скрытые от пользователей или показанные им, сопряжение и отвязка приложений, добавление, изменение или удаление аккаунтов, смена паролей и настроек. Фильтр по пользователю или по типу. Сохранённые настройки перечисляются только по имени, никогда — их значения. Записи хранятся 90 дней.

Приложения тоже сообщают, что играют, — см. [контракт мобильного клиента](../mobile-client-contract.md#8-report-plays).

## Отключение аккаунтов

Сервер, доступный только вам — на вашем собственном компьютере или за чем-то, что и так запрашивает пароль, — может вполне обойтись без аккаунтов. Задайте `DOWNTIFY_DISABLE_AUTH=true` (см. [Переменные окружения](../getting-started/environment-variables.md#mobile-apps-and-sign-in)):

```yaml
environment:
  - DOWNTIFY_DISABLE_AUTH=true
```

Тогда:

- Страницы входа нет: кто открывает Downtify, тот пользуется им как первым администратором (`admin` на новом сервере).
- Кнопки выхода, **Настройки → Пользователи**, раздел **Аккаунт** в **Настройки → Общие** и **Выйти везде** в **Настройки → Приложения** исчезают.
- Телефоны всё ещё можно сопрягать (с этим администратором), и **Настройки → Активность** по-прежнему показывает, что и где играет.
- Тема, язык и прочие предпочтения **Общих** сохраняются как предпочтения этого администратора.

::: warning Тот, кто может достучаться до сервера, может всё
Без аккаунтов никто не спрашивает, кто вы: любой в вашей сети — или в интернете, если порт открыт, — может менять настройки, удалять музыку и сопрягать телефон. Не отключайте аккаунты на сервере, доступном другим.
:::

Задайте `false` (или удалите переменную), и вход снова станет обязательным — с аккаунтами, паролями и приложениями, как было.

## Забыли пароль?

Выполните это на сервере — `admin` получит пароль `downtify` назад (и будет заново создан как администратор, если был переименован или удалён); остальные аккаунты и сопряжённые приложения не затрагиваются:

```bash
docker exec downtify python main.py auth-reset
```

Вне Docker выполните `python main.py auth-reset` (или `uv run python main.py auth-reset`) в папке Downtify. Затем войдите и смените пароль.

## Скрипты и API

Теперь каждый вызов API требует учётных данных (см. [Справочник API](../api-reference.md#server-and-sign-in)). Скрипт может войти через `POST /api/auth/login` и хранить cookie `downtify_session` или использовать токен сопряжённого устройства.
