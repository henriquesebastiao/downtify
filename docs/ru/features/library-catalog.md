# Каталог библиотеки и синхронизация путей

Downtify ведёт небольшой **каталог** файлов в `/downloads` (папки slskd, когда [файлы slskd остаются на месте](slskd-navidrome.md#leave-files-in-place), и [дополнительных папок](external-library.md), которые вы добавляете в Настройках), чтобы страница Библиотеки, плеер, экспорт M3U, синхронизация с Navidrome и поиск дубликатов оставались согласованными, когда файлы перемещаются, а плейлисты растут.

## Что хранится

| Хранилище | Расположение | Назначение |
|-------|----------|---------|
| **Индекс треков** | `/data/downtify_library.db` | Сопоставляет ID треков Spotify с путями в библиотеке, чтобы трек, уже лежащий на диске, можно было распознать |
| **Каталог плейлистов** | `/data/downtify_library.db` | Какие треки принадлежат каждому загруженному плейлисту Spotify |
| **Загрузки плейлистов** | `/data/downtify_library.db` | Отслеживаемые загрузки плейлистов Spotify и кэш их списков треков из Spotify |
| **Индекс Navidrome** | `/data/downtify_library.db` | ID песен Navidrome для каждого файла |
| **Кэш метаданных библиотеки** | `/data/downtify_library.db` | Название, артист, все указанные артисты, альбом, артист альбома, номер трека, год, длительность и размер обложки для каждого файла — для `GET /tracks`; перечитывается, только когда у файла меняется время изменения или размер |
| **Запуски обновления** | `/data/downtify_library.db` | Очередь [обновления библиотеки](library-upgrade.md) и время последней проверки каждого трека, чтобы запуск переживал перезапуск |
| **Кэш сканирования путей** | ОЗУ, плюс снимок в `/data/downtify_library.db` | Свёрнутые строки `GET /tracks`, списки плейлистов и пары путей. Маршруты интерфейса отдают этот снимок, не обходя диск. Каждая завершённая загрузка **мгновенно сливается со снимком** (чтобы новый артист появлялся без ожидания). Удаление **мгновенно убирает эти файлы из снимка** (чтобы альбом исчезал из сетки без ожидания). Полный обход дерева запускается в фоне через несколько секунд после того, как очередь загрузок опустеет, — не по фиксированному таймеру. `GET /list?refresh=true` сбрасывает снимок и пересканирует сразу. |
| **Скрытые элементы** | `/data/downtify_library.db` | Песни, альбомы и артисты, которые администратор [скрыл от пользователей](users.md#hiding-from-users) |
| **Кэш обложек** | `/data/cover_cache` (необязательно) | Извлечённые изображения обложек для `GET /cover` |

При перемещениях файлы сопоставляются по **ключу содержимого** — хэшу имени и размера файла. Перемещение файла в другую папку сохраняет его ключ; замена другим файлом даёт новый ключ.

## Настройки → Библиотека

### Кэшировать обложки на диске

Когда включено, Downtify хранит извлечённые изображения обложек в `/data/cover_cache`, поэтому Библиотеке и плееру не приходится перечитывать теги ради каждой миниатюры. Отключать в любой момент безопасно; это стоит лишь места на диске.

### Починить пути библиотеки

Используйте это после того, как вы **переместили или переименовали файлы на диске** вне Downtify либо удалили их вручную.

1. Откройте **Настройки → Библиотека → Починить пути библиотеки**.
2. Downtify сканирует папки библиотеки и:
    - **обновляет пути** в индексе треков и каталоге плейлистов, когда файла больше нет на прежнем месте, но тот же самый файл (с тем же ключом содержимого) найден в другом месте;
    - **удаляет устаревшие записи** для файлов, которых больше не существует;
    - **индексирует** старые записи, сохранённые до появления ключей содержимого;
    - **отслеживает [любимые песни](liked-songs.md#keeping-likes-in-step-with-the-files)** по их новому расположению.
3. Если включены **Записывать плейлисты M3U** и/или **Создавать плейлисты в Navidrome**, затронутые плейлисты перезаписываются.

Это выполняется только по нажатию кнопки (или по вызову `POST /api/library/reconcile`) — никогда по расписанию.

### Уже имеющиеся музыкальные папки

Чтобы слушать коллекцию, которую Downtify не скачивал, добавьте папки в **Настройки → Библиотека** и нажмите **Синхронизировать папки**. Файлы остаются на диске; теги читаются, артисты сопоставляются. См. [Уже имеющиеся музыкальные папки](external-library.md).

::: warning
Перезапись плейлиста удаляет файлы библиотеки, чьи теги явно не совпадают с зарегистрированным за ними треком Spotify, — см. [slskd и Navidrome](slskd-navidrome.md#playlist-sync).
:::

::: info Удаление и перенос
Удаление треков со страницы **Библиотека** уже само прибирает каталог и в фоне перезаписывает затронутые файлы M3U и плейлисты Navidrome, так что исправлять после нечего.
:::

## Страница Библиотеки

На странице Библиотеки четыре вкладки — **Альбомы**, **Артисты**, **Плейлисты** и **Треки**:

- **Альбомы, артисты и плейлисты** показываются сеткой обложек или компактным списком (переключение запоминается), с текстовым фильтром и сортировкой по недавнему добавлению, названию, артисту, году или числу треков. Альбомы и артисты строятся по тегам каждого файла (артист альбома, альбом, год), поэтому не зависят от того, как файлы разложены на диске. Сборник — артист альбома `Various Artists` с флагом сборника — остаётся единым альбомом в разделе «Альбомы», а его треки живут на страницах своих артистов. Трек с тегом `Various Artists`, но без флага (так раньше тегировалась любая песня с несколькими артистами, включая дуэты вроде `Zé Neto & Cristiano`), группируется по своему первому артисту. Трек без тега альбома показывается в «Треках» и у своего артиста, но не в «Альбомах».
- **Артисты** перечисляют каждого артиста, к которому принадлежит трек, — его артиста альбома, а для сборника (или файла без артиста альбома) — первого артиста. На странице такого артиста есть и треки, где он в гостях, с пометкой **Гость**; вкладка «Альбомы» там показывает только его собственные альбомы (она скрыта, когда их нет). Имя, которое всегда указывается лишь рядом с кем-то другим, собственной страницы не получает: теги могут перечислять участников дуэта по одному (`Henrique; Juliano`, как указывает некоторые дуэты YouTube Music и как писали старые версии Downtify), и страница для каждого участника была бы артистом, которого не существует. **Various Artists** не числится: треки сборника лежат на страницах артистов, а сам альбом остаётся в «Альбомах».
- Везде, где трек показывает своих артистов, — в списках треков, на экране «Сейчас играет», в Finder и в строках популярных песен — каждое имя ведёт на страницу этого артиста в Библиотеке, а когда страницы в Библиотеке нет — на поиск по нему. На этих строках имя альбома тоже ведёт к альбому в Библиотеке, а когда альбома там нет — к поиску по нему. Discover и его Finder никогда не отправляют вас в Поиск: там артист или альбом, которого нет в Библиотеке, остаётся простым текстом. Артисты берутся из тега файла `ARTISTS` (см. [Несколько артистов и сборники](file-organization.md#several-artists-and-compilations)), поэтому имя вроде *Earth, Wind & Fire* никогда не разрезается по запятой; у файла без этого тега текст артиста делится по `;`, ` / ` или `, `, — если только этот текст не совпадает с артистом альбома файла, либо имена, на которые он делится, в сумме не составляют артиста альбома (`Henrique; Juliano` на альбоме `Henrique, Juliano`) — тогда это одно имя.
- **Плейлисты** — это загруженные плейлисты с [файлом M3U](m3u-export.md), плейлисты, созданные через **Новый плейлист** (редактируемые), плюс отслеживаемые [загрузки плейлистов](slskd-navidrome.md#playlist-downloads), у которых M3U ещё нет. Импортированные плейлисты Spotify и YouTube остаются только для чтения, пока вы их не [отвяжете](#detach-an-imported-playlist). Плейлисты, которыми другие [делятся с вами](users.md#sharing-playlists), перечисляются под сеткой, отдельно от ваших. Как только вы [полюбили](liked-songs.md) песню, *любимые песни* стоят в списке первыми. Для созданного вами плейлиста используется мозаика из до четырёх обложек треков; импортированные плейлисты сохраняют обложку, приложенную к M3U.
- **Треки** — это сортируемая таблица (название, альбом, формат, дата добавления, длительность) с текстовым фильтром, фильтром по формату и флажками — щёлкните один, затем с Shift щёлкните другой, чтобы выбрать диапазон. Сортируйте щелчком по заголовку столбца или через меню **Сортировать по** над таблицей (единственный способ на телефоне, где заголовки скрыты): недавно добавленные или сначала старые, название, артист или альбом A–Z или Z–A, сначала длинные или короткие. Выбор запоминается.

У песен плейлиста то же меню **Сортировать по**, где к вариантам добавлен **Порядок плейлиста** (собственный порядок плейлиста — с него и начинается список); щелчок по заголовку столбца тоже работает. **Играть** и список песен следуют выбранному вами порядку, и выбор запоминается — для каждого плейлиста.

Открыв альбом, артиста или плейлист, вы видите его треки с кнопками **Играть**, **Перемешать** и **Добавить в очередь**. **Скачать ZIP** — кнопка на странице плейлиста и в меню **⋯** на странице альбома. У созданного вами плейлиста есть ещё **Добавить песни**, **Переименовать** и **Поделиться…** (см. [совместное использование плейлистов](users.md#sharing-playlists)); у импортированного — **Поделиться…** и **Отвязать от источника** (ниже); страница загруженного плейлиста показывает, сколько его треков скачано, перечисляет недостающие под фильтром **Нет в библиотеке** (ниже) с кнопкой **Скачать недостающие** и предлагает **Следить за новыми треками**. **Удалить плейлист** находится в меню **⋯**: импортированные плейлисты удаляют и аудио, а созданный вами плейлист удаляет только сам плейлист.

### Поиск по плейлисту

Длинный плейлист отрисовывает только песни на экране, поэтому собственный поиск браузера (`Ctrl` + `F`) остальное не видит. Поле **Искать в этом плейлисте** над песнями просматривает их все — название, артиста, альбом и имя файла, без учёта регистра и диакритики. На странице плейлиста `Ctrl` / `⌘` + `F` ставит курсор туда (нажмите ещё раз внутри поля — получите поиск браузера), а `Esc` очищает.

Рядом фильтры сужают список. Каждый показывает, сколько песен содержит, и появляется, только когда есть что показать:

| Фильтр | Показывает |
|--------|-------|
| **Все** | Каждую скачанную песню плейлиста |
| **Нет в библиотеке** | Песни исходного плейлиста, которых ещё нет в библиотеке (загрузки плейлистов Spotify), с состоянием их загрузки — запрашивается у Spotify при выборе фильтра |
| **С ошибками** | Недостающие песни, чья загрузка не удалась, каждая с кнопкой повтора — после того как **Нет в библиотеке** были запрошены |
| **YouTube Music**, **Soulseek (slskd)**, **Deemix**… | Песни, которые принёс тот источник. Downtify запоминает его для песен, скачанных с этого момента; более старые считаются **Неизвестным источником**, кроме файлов slskd, оставленных на месте, и песен из ваших собственных папок |
| **Нет в Navidrome** | При включённой [синхронизации с Navidrome](slskd-navidrome.md) — песни, которые Downtify ещё не сопоставил с песней в Navidrome |

Поиск и фильтр работают вместе, а под ними выводится число показанных песен. Каждая песня сохраняет свой номер в плейлисте, а сортировка, воспроизведение и меню каждой песни действуют на то, что показано.

### Отвязать импортированный плейлист

Плейлист, импортированный по ссылке Spotify или YouTube Music, нельзя редактировать, потому что Downtify держит его в согласии с источником. Чтобы его прибрать — убрать не относящуюся песню, добавить нужную, — откройте его и выберите **Отвязать от источника**. Он становится обычным плейлистом вроде созданных вами: его песни и владелец остаются как есть, а вы получаете **Добавить песни**, **Переименовать** и удаление песен. Взамен связь с источником рвётся: он больше не обновляется из Spotify или YouTube Music, его отслеживание [монитором плейлистов](playlist-monitor.md) (если оно было) снимается, и уходит учёт «недостающих песен». Уже скачанные песни не трогаются никогда, а его обложка держится до вашего первого изменения, когда её заменяет мозаика из его песен. Отвязку нельзя отменить из приложения; повторное скачивание ссылки создаёт новый импортированный плейлист.

Каждый аккаунт видит одну и ту же библиотеку: то, что администратор [скрыл от пользователей](users.md#hiding-from-users), у них не показывается, а администратор видит всё и с перечёркнутым глазом на том, что скрыто. Администраторы скрывают и показывают элементы через меню `…` песни, альбома или артиста, либо через панель выделения в **Треках**.

**Скачать ZIP** сохраняет выбранные треки на устройство, с которого вы просматриваете страницу, единым ZIP, сохраняя их раскладку по папкам — удобно, когда Downtify работает на домашнем сервере, а вам нужна партия треков локально. Совместите это с **Выбрать всё**, чтобы забрать всё, что показывает текущий фильтр. Архив собирается прямо во время скачивания, так что на диск сервера ничего не пишется, а лимит — 2000 треков за одно скачивание.

## API

| Метод | Путь | Описание |
|--------|------|-------------|
| `GET` | `/list?refresh=true` | Пути библиотеки, мимо кэша сканирования путей |
| `GET` | `/api/library/summary` | Счётчики для главной страницы и недавние альбомы, без полного списка треков |
| `GET` | `/api/library/albums` | Плитки альбомов (счётчики + файл обложки), без каждого трека |
| `GET` | `/api/library/artists` | Плитки артистов (счётчики + файл обложки) для Библиотеки и Discover |
| `GET` `POST` | `/api/library/visibility` | Администраторам: что скрыто от пользователей, скрыть / показать элементы |
| `POST` | `/api/library/lookup` | Строки библиотеки, чтобы найти песни уже скачанными по поиску или ссылке |
| `GET` | `/tracks` | Треки библиотеки с тегами. `?playlist=`, `?artist=`, `?album=`, `?q=` и `?limit=` возвращают подмножество |
| `GET` | `/media/{path}` | Отдаёт файл библиотеки, включая пути `slskd/…` и `ext/…` |
| `GET` | `/playlist-cover?file=…` | Отдаёт собственную [обложку](playlist-cover-art.md) плейлиста, которую `/playlists` отчитывает как `cover` |
| `POST` | `/api/library/archive` | Готовит ZIP выбранных треков (возвращает одноразовый билет) |
| `GET` | `/api/library/archive/{token}` | Отдаёт этот ZIP браузеру |
| `DELETE` | `/api/library/playlist?playlist_name=…` | Удаляет треки импортированного плейлиста, его M3U и каталог — либо только M3U созданного вами плейлиста |
| `POST` | `/api/library/playlists` | Создаёт пустой редактируемый плейлист |
| `POST` | `/api/library/playlists/tracks` | Добавляет или удаляет файлы библиотеки в созданном вами плейлисте |
| `POST` | `/api/library/playlists/rename` | Переименовывает созданный вами плейлист |
| `PUT` | `/api/library/playlists/visibility` | [Делится плейлистом](users.md#sharing-playlists), которым вы владеете, в режиме только для просмотра |
| `POST` | `/api/library/playlists/copy` | Сохраняет копию плейлиста, который вы можете открыть, как редактируемый собственный |
| `POST` | `/api/library/playlists/detach` | Превращает импортированный плейлист в редактируемый |
| `POST` | `/api/library/reconcile` | Чинит пути библиотеки, затем обновляет плейлисты M3U и Navidrome |
| `POST` | `/api/library/external/sync` | Запускает фоновое сканирование дополнительных музыкальных папок |
| `GET` | `/api/library/external/sync` | Идущая синхронизация дополнительных папок или лог последней завершённой |
| `POST` | `/api/library/external/unmap` | Убирает дополнительную папку из библиотеки, не удаляя аудио |
| `GET`/`POST` | `/api/library/upgrade…` | Сканирует и чинит уже скачанное — см. [Обновление библиотеки](library-upgrade.md#api) |

Формы запросов и ответов см. в [справочнике API](../api-reference.md#library).
