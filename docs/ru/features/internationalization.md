# Интернационализация

Downtify переведён в двух независимых местах: **приложение** (его интерфейс) и эта **документация**. Язык по умолчанию у обоих — **English**, ещё десять языков входят из коробки.

## Смена языка

### Приложение

Откройте **Настройки → Язык** и выберите нужный язык. Выбор сохраняется в браузерном `localStorage` и применяется сразу, без перезагрузки страницы. Страница также сообщает серверу (запись `ui_language` в `settings.json`, см. [`POST /api/settings/update`](../api-reference.md#post-apisettingsupdate)) при каждой загрузке и при каждом изменении, поэтому работа без браузера знает ваш язык — биография артиста, запрашиваемая в фоне, когда один из его треков заканчивает скачиваться, приходит на нём (см. [Когда загрузка завершается](artist-images.md#when-a-download-finishes)). Делать с вашей стороны ничего не нужно: если вы выбрали язык до появления этой функции, он будет подхвачен при следующем открытии Downtify. Когда несколько браузеров настроены на разные языки, выигрывает последний, который загрузил или сменил язык.

### Документация

Документация открывается на языке, который предпочитает ваш браузер, если на него переведена, а иначе на English. **Кнопка-глобус** справа на верхней панели переключает язык в любой момент и оставляет вас на той же странице (и разделе). Ваш выбор запоминается в браузере и с того момента выигрывает у языка браузера, пока вы не выберете другой.

Непереведённая страница показывает заметку и текст English, так что у каждого языка всегда есть каждая страница.

## Перевод-вкладка

Вы можете переводить приложение, документацию или и то, и другое. Это отдельная работа с отдельными файлами, поэтому пул-реквест может содержать любую из них — а язык может появиться сначала в одной, потом в другой.

| Вы переводите | Где лежат файлы | Готово, когда |
| ------------- | ------------------- | --------- |
| **Только приложение** | `frontend/src/i18n/locales/<code>.js` | язык появляется в **Настройки → Язык** |
| **Только документацию** | `docs/.vitepress/locales/<code>.mjs` и Markdown-страницы в `docs/<code>/` | язык появляется в меню глобуса документации |
| **И то и другое** | всё перечисленное | и то и другое |

Язык не обязан существовать в приложении, чтобы появиться в документации, и наоборот.

## Перевод приложения

Добавление перевода в приложение — процесс из трёх шагов:

### 1. Скопируйте файл локали English

Файлы локалей лежат в `frontend/src/i18n/locales/`. Каждый файл экспортирует объект, по ключам совпадающий со структурой `en.js`. Для имени файла используйте [тег языка IETF](https://en.wikipedia.org/wiki/IETF_language_tag).

```bash
cp frontend/src/i18n/locales/en.js frontend/src/i18n/locales/it.js
```

### 2. Переведите значения

Ключи, токены-заполнители (например `{count}`, `{name}`, `{file}`) и общая форма должны остаться неизменными — меняться должны только строки справа. Задайте `language.name` в **собственном** (родном) названии языка (`"Français"`, `"Deutsch"`, …) — это подпись, которую показывает переключатель языка.

### 3. Зарегистрируйте локаль

Добавьте импорт и запись в `AVAILABLE_LOCALES` в `frontend/src/i18n/index.js`:

```js
import it from './locales/it.js'

export const AVAILABLE_LOCALES = [
  { code: 'en', name: 'English', messages: en },
  { code: 'es', name: 'Español', messages: es },
  // …
  { code: 'it', name: 'Italiano', messages: it }, // new
]
```

Пересоберите фронтенд, и ваш язык появится в **Настройки → Язык** автоматически:

```bash
cd frontend && npm run build
```

### Советы по переводу приложения

- Отсутствующие ключи возвращаются к English, поэтому частичные переводы работают как надо — присылайте PR с тем, что уже есть.
- Строки, зависящие от числа, — объекты с формами множественного числа, например `tracks: { one: '{count} track', other: '{count} tracks' }`. Форма выбирается через браузерный [`Intl.PluralRules`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) для вашего языка, так что добавьте формы, которые использует ваш язык (`zero`, `one`, `two`, `few`, `many`, `other`), — `other` обязательна. Числа для языка форматируются автоматически.
- Токены-заполнители вроде `{count}` или `{file}` менять нельзя; подставляются они во время отображения.
- Держите строки краткими — интерфейс уложен плотно, и очень длинные переводы могут неловко переноситься.
- После перевода запустите `npm run dev` из `frontend/` и пройдитесь по всем страницам на своём языке, чтобы заметить, что переполняется или странно читается в контексте.

## Перевод документации

English — источник: он лежит в `docs/`. У каждого другого языка есть папка, названная по его коду (`docs/pt-BR/`), **с теми же именами файлов**, что у English, плюс один файл для собственных текстов сайта (`docs/.vitepress/locales/pt-BR.mjs`: названия сайдбара, поле поиска, подвал, подписи выносок). Ещё не переведённая страница — маленькая заглушка, которая показывает заметку и включает страницу English.

### Перевод страницы существующего языка

Из `docs/`:

```bash
npm install
npm run i18n -- status pt-BR           # what is translated, what is English-only, what is out of date
npm run i18n -- start pt-BR features/users.md
```

`start` заменяет заглушку `docs/pt-BR/features/users.md` копией страницы English. Переведите её на месте, затем проверьте:

```bash
npm test             # the translated pages must keep the English page's structure
npm run dev          # read it in the browser, in your language
```

Откройте пул-реквест, когда страница хорошо читается; частичная работа тоже приветствуется, — нетронутые страницы просто остаются на English.

### Добавление языка в документацию

1. Скопируйте `docs/.vitepress/locales/en.mjs` в `docs/.vitepress/locales/<code>.mjs` и переведите его: собственное `name`, тексты сайта (`ui`), подписи выносок (`containers`) и названия сайдбара (`nav`).
2. Зарегистрируйте его в `docs/.vitepress/locales/index.mjs`.
3. Создайте страницы заглушками на English: `npm run i18n -- stubs <code>`.
4. Переводите страницы по одной с `npm run i18n -- start <code> <page>`.

Язык появляется в меню глобуса и в определении языка браузера, как только зарегистрирован.

### Что оставить, а что перевести

- **Переводите** текст, заголовки, ячейки таблиц, названия выносок и значения `title`/`text` в титульной части главной страницы (front matter).
- **Оставляйте как есть** блоки кода, встроенный `code`, URL, переменные окружения, пути API и имена полей, имена файлов и папок, а также ключи front matter, значения `icon:` и `link:`. Перевод комментария внутри блока кода — нормально.
- **Ссылки**: относительные ссылки `.md` страницы English (`[Lyrics](lyrics.md#sidecar-lrc-file)`) оставляйте точно как есть. Ссылка на страницу, которая есть только на English, всё равно работает. На главной странице ссылки записаны с префиксом языка (`/pt-BR/features/player/`).
- **Заголовки**: оставляйте те же заголовки, в том же порядке и на тех же уровнях. Ссылки на разделы (`#sidecar-lrc-file`) продолжают работать на каждом языке, потому что переведённая страница переиспользует идентификаторы заголовков English, — идентификаторы вы не пишете и не переводите никогда.
- **Названия кнопок и настроек**: у приложения есть собственный перевод каждой подписи. Используйте его, жирным, чтобы страница совпадала с тем, что читатель видит на экране: найдите подпись в `frontend/src/i18n/locales/<code>.js`. Если приложение ещё не переведено на этот язык, оставьте подпись на English.
- **Выноски** (`::: tip Title`): сохраняйте вид (`info`, `tip`, `warning`, `danger`) и переводите название. Выноска без названия подписывается словом из `containers` файла локали.
- **Тон**: пишите для читателя своего языка — это справочные страницы, а не дословный пересказ.

### Поддержание переводов в актуальности

Когда страница English меняется, её переводы не обязаны меняться в том же пул-реквесте: переведённая страница продолжает работать, а `npm run i18n -- status <code>` перечисляет страницы, чей источник English менялся после их перевода. Обновлять их — хорошее первое знакомство с вкладом.

Тесты (`npm test` в `docs/`) проверяют, что у каждого языка есть каждая страница и каждый текст сайта, и что переведённая страница по-прежнему хранит заголовки, блоки кода, таблицы, выноски и ссылки страницы English.
