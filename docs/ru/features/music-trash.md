# Музыкальная корзина

Когда **музыкальная корзина** включена, удаление песен из библиотеки больше не стирает их: администратор переносит их в корзину, где они хранятся **30 дней** и до того момента могут быть восстановлены — на прежнем месте, с прежними отметками «нравится», плейлистами и офлайн-копиями в приложениях. После этого воркер удаляет их окончательно.

Корзина **выключена**, пока тот, кто обслуживает сервер, её не включит. Без неё удаление песни сразу удаляет файл, как было всегда.

## Включение

Для обычной установки — песни лежат в папке загрузок — задайте одну переменную окружения и пересоздайте контейнер:

```yaml
services:
  downtify:
    environment:
      - DOWNTIFY_TRASH=true
```

Корзина тогда покрывает папку загрузок (`/downloads`), и файлы переносит сам Downtify. Чтобы покрыть и другие папки ([папку slskd](slskd-navidrome.md), [уже имеющиеся музыкальные папки](external-library.md)) или чтобы файлы переносил отдельный процесс, используйте вместо этого [конфигурационный файл](#the-configuration-file).

Пока корзина включена:

- песни убирают только **администраторы**, и только через корзину: остальные аккаунты больше не получают кнопки удаления для песен, даже скачанных ими самими;
- **удаление плейлиста сохраняет его песни** в библиотеке, как всегда делало удаление созданного вами плейлиста;
- песня, которой нет в папке, покрытой корзиной, не может быть убрана («Папка этой песни не обслуживается корзиной»). Добавьте её папку в конфигурационный файл.

Выключение корзины возвращает безвозвратное удаление. Песни, оставшиеся в корзине, остаются где есть (в `.downtify-trash`, см. [Куда уходят файлы](#where-the-files-go)) и вне библиотеки: включите корзину снова, чтобы их восстановить.

## Перенос песен в корзину

В вебе **Перенести в корзину** находится в меню каждой песни, на панели выделения вкладки Песни Библиотеки и в меню альбома. В [Android-приложении](mobile-apps.md) это меню **⋮** песни, для спаренного телефона администратора.

Перед тем как что-то сдвинется, сервер проверяет точные файлы — на большом выборе или медленном хранилище это может занять момент, — и подтверждение перечисляет их. Подтверждение переносит ровно эти файлы:

- аудиофайл песни, и её собственные файлы текстов рядом с ним (`.lrc`, `.txt`, `.srt` с тем же именем) либо в [папке текстов](lyrics.md), когда `.lrc` хранится там;
- **не** другую копию той же песни в другом формате (MP3 рядом с FLAC остаётся), и когда такая копия делит файл текстов, файл текстов тоже остаётся;
- **не** обложку папки и ничего другого, что используют другие песни.

Песни всем и сразу покидают библиотеку, пока они ещё *Ожидают переноса*. За раз уходит до 200 песен. Песня, которую кто-то слушает, не может быть перенесена, пока не поставлена на паузу, и ничего не переносится, пока идёт [обновление библиотеки](library-upgrade.md): перенос ждёт и того, и другого.

Песня, чьи теги говорят слишком мало, чтобы узнать её снова, — нет id ни Spotify, ни Deezer, ни YouTube, нет ISRC, и не все из названия, артиста и альбома — не может уйти в корзину («У этой песни слишком мало тегов…»): сначала поправьте её теги.

## Страница Корзины

Администраторы открывают **Корзину** с кнопки наверху страницы Библиотеки (или из бокового меню приложения). Она перечисляет содержимое корзины, новейшие первыми, с полем поиска, и для каждой песни:

| Состояние | Значение |
|-------|---------|
| **Ожидает переноса** | Подтверждена; воркер ещё не перенёс. Уже вне библиотеки |
| **Переносится** | В пути |
| **В корзине** | Перенесена. Показывает, до какого времени хранится |
| **Ожидает восстановления** / **Восстанавливается** | На обратном пути |
| **Остановлено — файлы сохранены** | Что-то пошло не так (в сообщении сказано, что); ничего не удалено |

**Восстановить** (одну песню или выбранные) возвращает файлы туда, где они были. Песня возвращается с тем же идентификатором в библиотеке, поэтому отметки «нравится», плейлисты и офлайн-копии в приложениях снова её находят. Песню, ещё не перенесённую (*Ожидает переноса* или остановленную до переноса), тоже можно восстановить: это лишь возвращает её в библиотеку.

Восстановление никогда ничего не перезаписывает: если на старом месте тем временем появился файл, песня остаётся в корзине и об этом сообщает. Переместите или переименуйте этот файл и попробуйте снова.

**Попробовать снова** продолжает остановленную операцию, после того как вы поправили то, на что указало сообщение (хранилище не примонтировано, файл изменён…). Прерванный перенос или восстановление — сервер остановился на середине — продолжаются сами, когда сервер снова стартует.

Опустошить корзину раньше срока нельзя: песни покидают её только восстановлением либо когда истекают их 30 дней.

## Исключение из загрузок

Каждую загрузку песню в корзине пропускает — очередь, [монитор плейлистов](playlist-monitor.md), отслеживания артистов, — а загрузка её завершается сообщением `In the music trash: an admin has to allow it again`. Она распознаётся по своим id у провайдера или по точному названию, артистам и альбому, так что другое издание её не затрагивает.

Это остаётся верным и после её 30 дней, поэтому отслеживаемый плейлист не вернёт песню, которую вы убрали. Вид **Исключены из загрузок** на странице Корзины перечисляет эти песни; **Разрешить загрузки** позволяет следующей синхронизации снова её взять (само скачивание не запускается). Восстановление песни тоже снимает исключение.

## Куда уходят файлы

Песня переносится в папку `.downtify-trash` на вершине её папки библиотеки (например `/downloads/.downtify-trash/<id>/`), читаемую только пользователем Downtify, с пустым файлом `.ignore`, чтобы Jellyfin её пропускал. Собственные сканирования Downtify, плееры, потоки и приложения никогда не показывают её содержимое.

Переносы — это переименования на одном диске, ничего не копируется, и они никогда не заменяют существующий файл; каждый файл сверяется с подтверждённым (размер и SHA-256) перед переносом, перед возвращением и перед удалением. Файл, изменившийся по дороге, останавливает операцию и сохраняется. Для этого нужны Linux и файловая система с атомарными переименованиями, не заменяющими (`renameat2` с `RENAME_NOREPLACE`: ext4, XFS, Btrfs, tmpfs, ZFS…); в прочих местах корзина отказывается что-либо переносить («Это хранилище не может безопасно переносить файлы»).

Не удаляйте базу данных в `/data` и не откатывайтесь на версию Downtify без корзины, пока в ней лежат песни: база данных — это то, что знает, откуда пришла каждая.

## Конфигурационный файл

`DOWNTIFY_TRASH_CONFIG` называет JSON-файл (внутри контейнера), который перечисляет каждую папку, покрытую корзиной; он имеет приоритет над `DOWNTIFY_TRASH`.

```json
{
  "version": 1,
  "worker": "embedded",
  "roots": {
    "downloads": { "path": "/downloads" },
    "slskd": { "path": "/slskd" },
    "nas": {
      "path": "/music/nas",
      "marker": ".downtify-nas",
      "marker_value": "living-room-nas"
    }
  }
}
```

| Ключ | Описание |
|-----|-------------|
| `version` | Всегда `1` |
| `worker` | `embedded` (по умолчанию): файлы переносит сам Downtify. `external`: это делает только [отдельный воркер](#a-separate-worker) |
| `roots` | Папки, каждая под выбранным вами именем. `path` абсолютный и должен быть папкой так, как её видит Downtify, — папка загрузок, папка slskd или одна из дополнительных музыкальных папок — и сама не может быть символической ссылкой |
| `marker`, `marker_value` | Необязательно, для съёмных или сетевых хранилищ: файл в этой папке и его ожидаемое содержимое. Пока файл отсутствует или отличается (диск не примонтирован, примонтирован другой), в этой папке ничего не переносится |

Конфигурация, которую нельзя прочитать, останавливает сервер на старте, сообщая причину в лог, а не возвращает безвозвратное удаление.

## Отдельный воркер

Когда задано `"worker": "external"`, Downtify лишь записывает, что сделать, и никогда не трогает файлы: его контейнер может примонтировать музыку только для чтения, а отдельный процесс — с примонтированными лишь музыкальными папками и `/data`, без сети и без Docker-сокета — делает переносы, восстановления и удаление по сроку:

```sh
python -m downtify.trash_worker \
  --config /config/trash.json \
  --database /data/downtify_library.db \
  --auth-database /data/downtify_auth.db \
  --limit 5
```

Каждый запуск обрабатывает не больше `--limit` операций (1–20), печатает сделанное как JSON (`{"processed": 1, "succeeded": 1, "failed": 0}`) и выходит; назначайте его раз в минуту или около того (таймер systemd, cron, Kubernetes CronJob). Он снова проверяет, что запросивший по-прежнему администратор, читая базу аккаунтов только для чтения, и два запуска никогда не работают одновременно. Запускайте его из той же версии Downtify, что и сервер, и только когда больше никто не перезаписывает те же файлы.
