# Мобильные приложения

Downtify может отдавать приложения на телефон: они просматривают и стримят библиотеку прямо с вашего сервера, а песни хранят на телефоне для офлайн-прослушивания. Приложение входит с вашим именем пользователя и паролем либо сопрягается кодом из **Настройки → Приложения**, где же лежат и ваши сопряжённые приложения, и имя сервера. Кто вообще может пользоваться сервером, задается аккаунтами в [Пользователи и вход](users.md).

::: warning Приложение ещё в разработке
**Настройки → Приложения** помечены *Экспериментальным*. Серверная часть, описанная на этой странице, готова и работает, но **ни одна версия приложения для Android ещё не публиковалась**, так что сейчас нечего устанавливать, а детали сопряжения и стриминга могут ещё меняться между версиями Downtify.

Приложение открыто разрабатывается в [henriquesebastiao/downtify-android](https://github.com/henriquesebastiao/downtify-android). Всё прочее может быть собрано под тот же API — см. [контракт мобильного клиента](../mobile-client-contract.md).
:::

## Вход из приложения

Введите адрес сервера (или выберите его в списке **Найдено в этой сети**), затем войдите с **теми же именем пользователя и паролем**, что и на веб-странице. Телефон становится одним из ваших **Сопряжённых приложений** — ровно так же, как если бы вы сопрягли его кодом ниже: он играет как вы, хранит собственный ключ (пароль на телефоне не сохраняется), и **Разорвать сопряжение** его выключает.

Неверные пароли ограничиваются по частоте вместе со входом на веб-странице. Пока аккаунты выключены (`DOWNTIFY_DISABLE_AUTH`), входиться нечем: сопрягайте кодом.

## Сопряжение телефона

Сопряжению не нужен пароль на телефоне: это удобно, когда веб-страница уже открыта, либо на телефоне, куда не хочется вводить ваш пароль.

1. Откройте **Настройки → Приложения** и нажмите **Сопрячь телефон**.
2. В приложении выберите **Сканировать код** и наведите камеру на QR-код — или введите показанный под ним 8-символьный код (`K7QM-2XPD`; регистр и дефисы не важны).
3. Диалог подтвердит сопряжение, и телефон появится в разделе **Сопряжённые приложения**.

Телефон сопрягается с **вашим аккаунтом**: он играет как вы и виден в вашей активности. Любой пользователь с аккаунтом может сопрягать свои телефоны.

Код действует **один раз**, в течение **пяти минут**, а попытки ввести неверный код ограничены по частоте. Телефон получает собственный ключ и хранит его; сервер хранит лишь его хэш.

**Сопряжённые приложения** перечисляют ваши телефоны (администратор видит все — вместе с тем, чьи они), их платформы, когда телефон видели в последний раз и откуда он заходил. **Разорвать сопряжение** выключает телефон сразу — его следующий запрос проваливается, открытые соединения закрываются, и чем он делился (см. [Трансляция](#casting)), перестаёт работать. Чтобы вернуть его в строй, сопрягите его снова.

## Что может сопряжённое приложение

Сопряжённые приложения могут просматривать библиотеку, играть, добавлять в любимые, хранить песни офлайн и просить сервер скачать музыку — но не изменять настройки, учётные данные и не удалять файлы; для этого нужна веб-страница, под входом администратора.

**Настройки → Приложения → Выйти везде** разрывает сопряжение всех ваших приложений и выгоняет вас из всех браузеров, включая этот. О входе, аккаунтах и забытом пароле — в [Пользователи и вход](users.md).

## Поиск сервера в вашей сети

Сервер объявляет о себе в локальной сети (mDNS / Bonjour, как `_downtify._tcp`), поэтому приложение показывает его в списке **Найдено в этой сети** — имя, адрес и версию — без ввода чего-либо. Имя — то, что задано в **Настройки → Приложения → Имя сервера** (имя хоста машины, пока вы его не поменяете).

::: info Сеть Docker по умолчанию прячет объявление
В сети *bridge*, которая в Docker используется по умолчанию, объявление остаётся внутри Docker, и телефоны его не видят. Либо запустите контейнер с `network_mode: host` (см. [Docker Compose](../getting-started/docker-compose.md#finding-the-server-from-the-apps)), либо введите адрес сервера в приложение — всё остальное работает так же.
:::

Задайте `DOWNTIFY_DISCOVERY=false`, чтобы остановить эти объявления.

## Качество стриминга

Приложения играют файлы такими, какие они есть (**Оригинал**), или просят сервер сделать копию поменьше: Opus, AAC или MP3 на 96–320 кбит/с — это полезно на мобильном интернете. Сервер делает такую копию через ffmpeg, когда песня так воспроизводится первый раз (несколько секунд для обычной песни), и сохраняет её, так что перемотка работает как в любом файле, а следующее воспроизведение начинается мгновенно.

- Файл, который уже достаточно мал (сжатый файл с битрейтом на уровне запрошенного или ниже), стримится как есть — никогда не перекодируется.
- Копии хранятся в `/data/transcode_cache`, по умолчанию всего 2 ГБ; первыми уходят те, что дольше всех не играли. Единовременно делается максимум две копии. Оба предела — [переменные окружения](../getting-started/environment-variables.md#mobile-apps-and-sign-in).
- Если телефон сдался, пока копия ещё делалась, сервер перестаёт её делать.

## Нормализация громкости

Приложение для Android может играть песни с похожей громкостью при тех же измерениях, что и веб-плеер: включите **Нормализовать громкость** в его **Настройках → Воспроизведение**. Действует со следующей песни, а у песни без измерения уровень остаётся исходным. Офлайн-копия использует измерение, только если она была скачана целиком и совпадает с файлом, который измерял сервер. См. [Нормализация громкости](playback-normalization.md).

## Трансляция

Приложения могут передать песню на Chromecast или другой плеер, который сам забирает аудио. Приложение получает с сервера ссылку, работающую для одной песни ограниченное время (по умолчанию час) и только пока телефон остаётся сопряжённым; ключа телефона в ней нет.

## За реверс-прокси

Если Downtify стоит за nginx, Caddy, Traefik или чего-то похожего (для HTTPS, или чтобы дотянуться извне):

- **Пропустите WebSocket.** `/api/ws` требует передачи заголовков `Upgrade`/`Connection` (Caddy и Traefik делают это по умолчанию; nginx нужно `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`).
- **Пропускайте запросы Range** без изменений и не буферизуйте аудиореспонсы (nginx: `proxy_buffering off;` для `/api/v1/` и `/downloads/`), иначе пострадают перемотка и большие файлы.
- **Скажите Downtify, какому прокси доверять.** Задайте `DOWNTIFY_TRUSTED_PROXIES` — адрес прокси (например, `172.18.0.0/16`). Только тогда Downtify берёт адрес клиента из `X-Forwarded-For` (лиметеры частоты, «последний раз в сети» в Сопряжённых приложениях), а `X-Forwarded-Proto`/`X-Forwarded-Host` — чтобы пометить cookie входа как безопасную и проверить, откуда приходят запросы. Без этого эти заголовки игнорируются — иначе их мог бы прислать любой.
- **Используйте HTTPS**, когда сервер доступен извне: и пароль, и ключи приложений идут с каждым запросом.
