# Настройки сервера

**Настройки → Сервер** содержит то, как работает сам сервер. Видна только администраторам (см. [Пользователи и вход](users.md#admins-and-users)).

## Смена порта

Downtify слушает порт **8000**. Администратор может выбрать другой в **Настройки → Сервер → Порт** (1024–65535):

- **Сохранить** оставит его для следующего запуска сервера.
- **Сохранить и перезапустить** немедленно перезапустит сервер на нём. Загрузки в процессе остановятся, а страницы и приложения переподключатся. Страница, открытая на собственном адресе сервера (например, `http://nas:8000`), дождётся сервера и сама откроет новый адрес; вы останетесь в системе.

Когда порт задаётся переменной окружения `DOWNTIFY_PORT` (или `PORT`) или параметром `--port` в командной строке — они всегда берут верх, — поле показывает используемый порт, но его нельзя редактировать, а на странице сказано, чем он задан. Уберите источник (и перезапустите сервер), чтобы выбрать порт в Настройках.

::: warning Сетевой bridge Docker отображает фиксированный порт
В стандартной настройке Docker (`ports: - '8000:8000'`) порт контейнера должен соответствовать маппингу. После смены порта в Настройках измените маппинг на новый порт (`'9000:9000'`) и пересоздайте контейнер — или запускайте с `network_mode: host`. Иначе до Downtify не добраться. Чтобы попасть обратно, задайте `DOWNTIFY_PORT` равным старому порту: он важнее Настроек.
:::

За [обратным прокси](mobile-apps.md#behind-a-reverse-proxy) направьте прокси тоже на новый порт. [Сопряжённые приложения](mobile-apps.md) пользуются выданным им адресом: после смены порта введите новый в приложении.
