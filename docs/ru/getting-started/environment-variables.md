# Переменные окружения

Все переменные окружения необязательны: без любой из них Downtify работает «из коробки».

## Основные

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_PORT` | _(не задано)_ | Порт, на котором слушает сервер (внутри контейнера). Не задана: берётся порт из **Настройки → Сервер → Порт**, иначе `8000`. Задана — она главная, а поле в Настройках блокируется. Левую часть правила проброса портов поменяйте, чтобы открыть другой порт хоста. См. [Смену порта](../features/server.md#changing-the-port). |
| `DOWNLOAD_DIR` | `/downloads` | Папка, куда сохраняются аудиофайлы. Переопределите, если монтируете библиотеку по нестандартному пути. |
| `HOST` | `0.0.0.0` | Адрес, к которому привязывается веб-сервер. |
| `DOWNTIFY_LOG_LEVEL` | `info` | Уровень журнала приложения (`debug`, `info`, `warning`, …). |
| `TZ` | `UTC` | Местный часовой пояс (имя IANA, например `America/Sao_Paulo`); им истолковывается `DOWNTIFY_MONITOR_SYNC_TIME` ниже. |

## Монитор плейлистов

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_MONITOR_SYNC_TIME` | _(не задано)_ | Время суток (24-часовое `HH:MM`, по `TZ` выше), в которое [Монитор плейлистов](../features/playlist-monitor.md#choosing-a-daily-sync-time) с интервалом в сутки и больше (каждый день, неделю, 2 недели, месяц) сверяется с источником. Оставьте пустым, чтобы сверяться ровно через интервал после предыдущей проверки, в какое бы время она ни пришлась. |

```yaml
environment:
  - TZ=America/Sao_Paulo
  - DOWNTIFY_MONITOR_SYNC_TIME=03:00
```

## Мобильные приложения и вход

См. [Мобильные приложения](../features/mobile-apps.md) и [Пользователи и вход](../features/users.md). Вход обязателен, если только `DOWNTIFY_DISABLE_AUTH` не равна `true`; `DOWNTIFY_REQUIRE_SIGN_IN` из прежних версий больше не используется (пока она задана, в журнал пишется предупреждение).

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_DISABLE_AUTH` | `false` | `true` выключает аккаунты: никто не входит в систему, а кто добрался до сервера, пользуется им как администратор. Страница входа, кнопки выхода, **Настройки → Пользователи** и аккаунтная часть **Настройки → Общие** исчезают. Привязанные приложения продолжают работать. Верните `false` (или уберите переменную) — вход снова обязателен, а аккаунты остаются как были. См. [Пользователи и вход](../features/users.md#turning-accounts-off). |
| `DOWNTIFY_TRUSTED_PROXIES` | _(не задано)_ | Адреса или сети обратного прокси через запятую (например, `172.18.0.0/16,10.0.0.5`). Только у запросов с них верят заголовкам `X-Forwarded-For`, `X-Forwarded-Proto` и `X-Forwarded-Host` — это адрес клиента, по которому ограничивается частота попыток входа и привязки, флаг secure у куки входа и проверка same-site. Не задана: такие заголовки игнорируются. |
| `DOWNTIFY_DISCOVERY` | `true` | `false` прекращает анонсировать сервер в локальной сети (mDNS, `_downtify._tcp`), по которому приложения показывают его в списке *Найдено в этой сети*. В сети bridge Docker анонс до локальной сети всё равно не доходит — см. [Docker Compose](docker-compose.md#finding-the-server-from-the-apps). |
| `DOWNTIFY_TRANSCODE_CACHE_MB` | `2048` | Наибольший размер в МБ, под которым держится кэш перекодированных копий (`/data/transcode_cache`); первыми уходят самые давние по воспроизведению. |
| `DOWNTIFY_TRANSCODE_CONCURRENCY` | `2` | Сколько песен сразу перекодируется для меньших качеств стриминга приложений. |
| `DOWNTIFY_STREAM_CACHE_MB` | `1024` | Наибольший размер в МБ, под которым держится кэш стриминга аудио (`/data/stream_cache`); первыми уходят самые давние по воспроизведению. Стриминг через сервер — то, чем играются нескачанные треки там, где браузер сам до YouTube не доберётся. |
| `DOWNTIFY_STREAM_CONCURRENCY` | `2` | Сколько загрузок стрима может идти одновременно. |

## Музыкальная корзина

См. [Музыкальную корзину](../features/music-trash.md). Выключена, пока не задана хоть одна из этих переменных.

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_TRASH` | `false` | `true` включает музыкальную корзину для папки загрузок: удаление песни переносит её в корзину сроком на 30 дней, и файлы переносит сам Downtify. Пока корзина включена, песни удаляют только администраторы. |
| `DOWNTIFY_TRASH_CONFIG` | _(не задано)_ | Путь внутри контейнера к JSON-файлу со списком папок, которые покрывает корзина, и тем, где работает её воркер (`embedded` или `external`). Перебивает `DOWNTIFY_TRASH`. Файл, который не читается, останавливает сервер на старте. См. [Файл настроек](../features/music-trash.md#the-configuration-file). |

## Проверка работоспособности

В образе есть встроенный [Docker `HEALTHCHECK`](https://docs.docker.com/reference/dockerfile/#healthcheck) — особый `--health-cmd` не нужен. Каждые 30 секунд он опрашивает `GET /api/health` на порту самого контейнера (тайм-аут 5 секунд, льготный период на старте 20 секунд, 3 попытки, прежде чем контейнер объявят нездоровым). Результат виден в `docker ps` и `docker inspect`, а инструменты вроде `condition: service_healthy` в Compose или Watchtower могут на него опираться.

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_HEALTHCHECK` | `1` | Поставьте `0`, чтобы выключить встроенную проверку — тогда она всегда отвечает «здоров» без обращения к серверу. Используйте, если единственной инстанцией о здоровье контейнера должна быть внешняя проверка уровня оркестратора (например, liveness probe Kubernetes). |

```yaml
environment:
  - DOWNTIFY_HEALTHCHECK=0
```

## Против ботов / YouTube

YouTube периодически устраивает проверки автоматическим загрузчикам. Эти переменные — запасной выход, если настройки по умолчанию перестали работать.

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `DOWNTIFY_FORCE_IPV4` | _(не задано)_ | Поставьте `1`, чтобы заставить yt-dlp использовать только IPv4. Полезно, когда у хоста сломанный или ограниченный по частоте IPv6. |
| `DOWNTIFY_YT_PLAYER_CLIENTS` | `ios,android,web_embedded,mweb,web,tv` | Список клиентов yt-dlp player через запятую, в порядке перебора. Список по умолчанию в Downtify и так отдает предпочтение клиентам, работающим без JS-рантайма. Меняйте лишь когда точно знаете, что какой-то клиент блокируется. |
| `DOWNTIFY_YT_PO_TOKEN` | _(не задано)_ | Токены Proof-of-Origin для yt-dlp через запятую, каждый в виде `<client>.<context>+<token>` (например, `mweb.gvs+ABC123`). Нужны, только если YouTube начнёт требовать PO Токены для ваших клиентов. |
| `DOWNTIFY_COOKIES_FILE` | _(не задано)_ | Путь к `cookies.txt` в формате Netscape **внутри контейнера**. Позволяет yt-dlp проходить как настоящая сессия браузера — нужно для треков Explicit с ограничением по возрасту и всегда, когда YouTube ставит стену входа. Имеет силу выше файла, загруженного через веб-интерфейс, и делает тот раздел интерфейса доступным только для чтения. См. [Куки YouTube](../features/youtube-cookies.md). |
| `DOWNTIFY_COOKIES_FROM_BROWSER` | _(не задано)_ | Имя браузера, из которого взять куки (например, `chrome`, `firefox`). Требует, чтобы хранилище куки браузера было доступно внутри контейнера, поэтому в Docker почти неприменимо. |

::: tip Они вам, скорее всего, не нужны
Файл `cookies.txt` можно загрузить прямо из **Настройки → Куки YouTube** в веб-интерфейсе. Он лежит в `/data` (значит, переживёт обновление контейнера), не требует bind mount и пути в контейнере и одинаково работает на Windows, macOS и Linux. Переменные выше остаются на случай, когда deployments предпочитают управлять файлом сами.
:::

## Пример: Docker Compose с настройками против ботов

```yaml
services:
  downtify:
    image: ghcr.io/henriquesebastiao/downtify:latest
    ports:
      - '8000:8000'
    volumes:
      - ./downloads:/downloads
      - downtify_data:/data
      - ./cookies.txt:/cookies.txt:ro
    environment:
      - DOWNTIFY_FORCE_IPV4=1
      - DOWNTIFY_COOKIES_FILE=/cookies.txt
    restart: unless-stopped
```

## Как достать cookies.txt

Воспользуйтесь расширением браузера вроде [Get cookies.txt LOCALLY](https://chrome.google.com/webstore/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc) (Chrome) или [cookies.txt](https://addons.mozilla.org/en-US/firefox/addon/cookies-txt/) (Firefox). Экспортируйте с `youtube.com`, войдя в настоящий Google-аккаунт, а дальше либо загрузите файл в **Настройки → Куки YouTube**, либо смонтируйте в контейнер, как показано выше.

О полном порядке см. [Куки YouTube](../features/youtube-cookies.md), а если загрузки всё же падают — [Решение проблем](../troubleshooting.md).

::: warning
Храните свой `cookies.txt` в секрете — в нём лежат токены сессии, дающие доступ к вашему Google-аккаунту.
:::
