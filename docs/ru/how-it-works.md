# Как это работает

Процесс загрузки в Downtify состоит из трёх этапов:

```
Spotify embed  →  YouTube Music search  →  yt-dlp + ffmpeg + mutagen
  (metadata)         (audio match)          (download & tag)
```

## 1. Метаданные — парсинг страницы embed Spotify

Когда вы вставляете URL Spotify, Downtify загружает публичную страницу `open.spotify.com/embed` для этого трека, альбома или плейлиста. Ни аккаунт Spotify, ни API-ключ, ни подписка Premium не нужны — страница embed доступна публично.

Для **треков** страница embed возвращает: название, артиста(ов), название альбома, год выпуска, длительность и URL обложки.

Для **альбомов и плейлистов** страница embed возвращает список треков. Embed плейлистов ограничены примерно 50–100 записями, поэтому Downtify также запрашивает полный список из анонимной конечной точки Spotify `api.spotify.com` с постраничной разбивкой, чтобы справляться с плейлистами на сотни песен.

::: info Обогащение метаданных по каждому треку
В записях embed плейлиста отсутствует год выпуска и используется обложка плейлиста вместо собственной обложки альбома каждого трека. Для [Монитора плейлистов](features/playlist-monitor.md) Downtify заново запрашивает каждый новый трек отдельно, чтобы получить правильные обложку и год перед загрузкой.
:::

## 2. Подбор аудио — YouTube Music, затем YouTube

Downtify использует [`ytmusicapi`](https://ytmusicapi.readthedocs.io/), чтобы искать на YouTube Music лучшее совпадение аудио. Поисковый запрос составляется из названия трека и имени артиста.

Результат принимается, только если его название похоже на исходное и у него есть хотя бы один общий артист. Суффикс версии через тире в стиле Spotify и суффикс в скобках в стиле YouTube Music считаются одним и тем же (`Tubarões - Ao Vivo` совпадает с `Tubarões (Ao Vivo)`), а указание артистов, которое YouTube Music упаковывает в одну запись (`A, B, and C`), перед сравнением разбивается. Ведущее «The» в именах артистов игнорируется (`Eden Project` совпадает с `The Eden Project`), а название может совпасть с одной из частей заголовка загрузки, разделённых ` - ` (`くちづけDiamond - Kuchizuke Diamond`, `Game OST - Song Title - Artist`), если остальные части не называют другую версию. Караоке, каверы, инструменталы, ускоренные/замедленные, концертные (включая `Ao Vivo`/`En Vivo`), акустические, ремиксы и версии на других языках (например, `(Spanish Version)`) отклоняются, если только сам исходный трек не является такой версией. Среди оставшихся результатов побеждает тот, чья длительность ближе к длительности Spotify, с бонусом за совпадающее название альбома. Если ни один результат не подходит, поиск повторяется со словами в другом порядке (`<title> <artist>` вместо `<artist> <title>`) — YouTube Music ранжирует результаты по-разному в зависимости от порядка слов, и некоторые песни оказываются у топа только при одном из порядков. Если и это ничего не находит, а альбом известен, напрямую просматривается список треков альбома.

### Откат на обычный YouTube

Некоторых песен нет на YouTube Music или они существуют там только как другая запись. Поэтому обычный YouTube тоже ищется, когда:

- на YouTube Music **нет приемлемого совпадения**, или
- длительность его лучшего совпадения отличается от длительности Spotify **больше чем на 10 секунд** — сильный намёк на другую запись (например, дублированную версию с тем же названием).

Результаты обычного YouTube проходят те же проверки названия, артиста и версии и никогда не принимаются при расхождении с длительностью Spotify больше 30 секунд. Результат YouTube заменяет слабое совпадение YouTube Music только когда его длительность строго ближе; иначе совпадение YouTube Music остаётся, поскольку его загрузки из каталога обычно имеют самое чистое аудио.

Если ни на одном сайте нет приемлемого совпадения, трек завершается ошибкой `Could not find a YouTube match for '<title>'`, а не скачиванием неправильной песни.

Для ссылок YouTube, введённых напрямую, этот шаг пропускается — Downtify скачивает именно это видео.

**SoundCloud** — тоже необязательный источник аудио (Настройки → Аудио источники, по умолчанию выключен): на своём месте в порядке источников он ищет на SoundCloud со своими проверками названия, артиста и длительности, а для вставленной ссылки на трек SoundCloud — чьи название, артист и обложка берутся из самого SoundCloud — скачивает именно этот трек. Подробности — на странице SoundCloud в разделе «Возможности».

::: info Ссылки Deezer
Вставленная ссылка Deezer на трек/альбом/плейлист/артиста (`deezer.com/track/…`) работает так же, как ссылка Spotify: публичный REST API Deezer даёт название, артиста(ов), альбом и обложку, каждый трек стримится целиком с YouTube перед загрузкой, а затем этот же шаг сопоставляет его на YouTube Music/YouTube. У Downtify нет собственного распознавателя дискографии Deezer сверх того, что уже возвращает API Deezer, поэтому ссылка Deezer скачивается и (для плейлиста) получает собственные M3U и обложку, но не может отслеживаться [Монитором плейлистов](features/playlist-monitor.md).
:::

## 3. Загрузка и теги — yt-dlp + ffmpeg + mutagen

### Загрузка

[yt-dlp](https://github.com/yt-dlp/yt-dlp) скачивает аудио с YouTube (или с SoundCloud — для трека SoundCloud). Для YouTube Downtify настраивает его перебирать несколько клиентов-плееров по порядку (`ios`, `android`, `web_embedded`, `mweb`, `web`, `tv`), чтобы обходить проверки YouTube на ботов. Расширенные варианты защиты от ботов см. в разделе [Переменные окружения](getting-started/environment-variables.md).

### Конвертация

[ffmpeg](https://ffmpeg.org/) конвертирует исходное аудио в выбранный формат (MP3, FLAC, M4A, OGG или OPUS) с выбранным битрейтом.

### Теги

[mutagen](https://mutagen.readthedocs.io/) записывает метаданные в сконвертированный файл:

| Тег | Записывается |
|-----|---------|
| Название | Да |
| Артист(ы) | Да, каждый указанный артист, а также по одному на каждое значение в теге `ARTISTS` |
| Артист альбома | Да, собственный артист альбома, как его указывает источник, иначе первый артист |
| Признак сборника | Только для альбома, который источник указывает как «Various Artists», или который администратор отмечает как сборник |
| Альбом | Да |
| Год | Да |
| Обложка альбома (JPEG) | Да |
| Тексты (обычные + синхронизированные) | Да, если lrclib возвращает результат |
| Пометка explicit | Да, когда песня помечена как explicit (см. [Пометку explicit](features/explicit-marker.md)) |

Какие именно теги ID3/Vorbis/MP4 используются, зависит от выходного формата. Подробности о том, как встраиваются тексты, см. в разделе [Тексты](features/lyrics.md).

## Прогресс в реальном времени

Downtify передаёт прогресс загрузки в браузер по соединению **WebSocket** (`/api/ws`). Пока yt-dlp сообщает о прогрессе, сервер рассылает всем подключённым клиентам обновления процента и статуса. Значит, вы видите, как полоса прогресса движется в реальном времени — без опроса и без перезагрузки страницы.

## Имена файлов и организация

Имя выходного файла строится по шаблону, настроенному в Настройках (по умолчанию: `{artists} - {title}`). Символы, недопустимые в именах файлов, удаляются.

Когда включена *Сортировка по артистам*, файл помещается во вложенную папку, названную по артисту альбома — или, для трека из сборника разных артистов, по его первому артисту. Иначе одиночные треки попадают в корень папки загрузок, а треки плейлистов/альбомов — в отдельную папку плейлиста или альбома. См. [Несколько артистов и сборники](features/file-organization.md#several-artists-and-compilations).
