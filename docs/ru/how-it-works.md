# Как это работает

Конвейер загрузки Downtify состоит из трёх этапов:

```
Spotify embed  →  YouTube Music search  →  yt-dlp + ffmpeg + mutagen
  (metadata)         (audio match)          (download & tag)
```

## 1. Метаданные — парсинг страницы embed Spotify

Когда вы вставляете URL Spotify, Downtify загружает публичную страницу `open.spotify.com/embed` этого трека, альбома или плейлиста. Не нужны ни аккаунт Spotify, ни API-ключ, ни подписка Premium — страница embed общедоступна.

Для **треков** страница embed возвращает: название, артиста(ов), имя альбома, год выхода, длительность и URL изображения обложки.

Для **альбомов и плейлистов** страница embed возвращает список треков. Плейлистные embed ограничены примерно 50–100 записями, поэтому Downtify также запрашивает полный список у анонимной конечной точки `api.spotify.com` Spotify с постраничным обходом, чтобы обрабатывать плейлисты с сотнями песен.

::: info Обогащение метаданных по каждому треку
Записи плейлистного embed не содержат год выхода и используют обложку плейлиста вместо обложки собственного альбома каждого трека. Для [Монитора плейлистов](features/playlist-monitor.md) Downtify заново запрашивает каждый новый трек по отдельности, чтобы получить верную обложку и год перед загрузкой.
:::

## 2. Подбор аудио — сначала YouTube Music, затем YouTube

Downtify использует [`ytmusicapi`](https://ytmusicapi.readthedocs.io/), чтобы искать на YouTube Music наилучшее совпадение аудио. Поисковый запрос составляется из названия трека и имени артиста.

Результат принимается, только если его название похоже на исходное и у них есть хотя бы один общий артист. Суффикс версии через тире в стиле Spotify и суффикс в скобках в стиле YouTube Music считаются одинаковыми (`Tubarões - Ao Vivo` совпадает с `Tubarões (Ao Vivo)`), а указание артистов, которое YouTube Music упаковывает в одну запись (`A, B, and C`), перед сравнением разбивается. Начальное «The» в именах артистов игнорируется (`Eden Project` совпадает с `The Eden Project`), а название может совпасть с одной из частей заголовка загрузки, разделённых ` - ` (`くちづけDiamond - Kuchizuke Diamond`, `Game OST - Song Title - Artist`), если остальные части не называют другую версию. Караоке, кавер, инструментал, ускоренная/замедленная, концертная (включая `Ao Vivo`/`En Vivo`), акустическая, ремикс и версии на другом языке (например, `(Spanish Version)`) отклоняются, если только сам исходный трек не является такой версией. Среди оставшихся результатов выигрывает тот, чья длительность ближе всего к длительности Spotify, с бонусом за совпадение имени альбома. Если ни один результат не проходит, поиск повторяется со словами в другом порядке (`<title> <artist>` вместо `<artist> <title>`) — YouTube Music ранжирует результаты по-разному в зависимости от порядка слов, и некоторые песни показываются наверху лишь одним из способов. Если и это ничего не находит, а альбом известен, напрямую просматривается список треков альбома.

### Откат на обычный YouTube

Некоторых песен нет на YouTube Music, или они существуют там только как другая запись. Поэтому обычный YouTube тоже ищется, когда:

- на YouTube Music **нет приемлемого совпадения**, или
- длительность его наилучшего совпадения отличается от длительности Spotify **более чем на 10 секунд** — сильный намёк, что это другая запись (например, дублированная версия с тем же названием).

Результаты обычного YouTube проходят те же проверки названия, артиста и версии и никогда не принимаются с отклонением более 30 секунд от длительности Spotify. Результат YouTube заменяет слабое совпадение с YouTube Music, только если его длительность строго ближе; иначе совпадение с YouTube Music сохраняется, поскольку загрузки из его каталога обычно дают наиболее чистое аудио.

Если ни на одном сайте приемлемого совпадения нет, трек терпит неудачу с сообщением `Could not find a YouTube match for '<title>'`, а неправильная песня не загружается.

Для введённых напрямую URL YouTube этот этап пропускается — Downtify загружает именно это видео.

**SoundCloud** — тоже необязательный источник аудио (Настройки → Источники аудио, по умолчанию выключен): на своём месте в порядке источников он ищет на SoundCloud с собственными проверками названия, артиста и длительности, а для вставленной ссылки на трек SoundCloud — чьи название, артист и обложка берутся с самого SoundCloud — он загружает именно этот трек. Подробности на странице SoundCloud в разделе Возможности.

::: info Ссылки Deezer
Вставленная ссылка Deezer на трек/альбом/плейлист/артиста (`deezer.com/track/…`) работает так же, как ссылка Spotify: публичный REST API Deezer поставляет название, артиста(ов), альбом и обложку, каждый трек целиком воспроизводится с YouTube до загрузки, а затем этот же этап ищет его совпадение на YouTube Music/YouTube. У Downtify нет собственного распознавателя дискографии Deezer сверх того, что уже возвращает API Deezer, поэтому ссылка Deezer загружается и (для плейлиста) получает собственный M3U и обложку, но [Монитор плейлистов](features/playlist-monitor.md) за ней не может следить.
:::

## 3. Загрузка и теги — yt-dlp + ffmpeg + mutagen

### Загрузка

[yt-dlp](https://github.com/yt-dlp/yt-dlp) загружает аудио с YouTube (или с SoundCloud — для трека SoundCloud). Для YouTube Downtify настраивает его на перебор нескольких клиентских плееров по порядку (`ios`, `android`, `web_embedded`, `mweb`, `web`, `tv`), чтобы обходить проверки YouTube на ботов. Расширенные параметры против ботов см. в [Переменных окружения](getting-started/environment-variables.md).

### Конвертация

[ffmpeg](https://ffmpeg.org/) конвертирует исходное аудио в выбранный формат (MP3, FLAC, M4A, OGG или OPUS) с выбранным битрейтом.

### Запись тегов

[mutagen](https://mutagen.readthedocs.io/) записывает метаданные в сконвертированный файл:

| Тег | Записывается |
|-----|---------|
| Название | Да |
| Артист(ы) | Да, каждый указанный артист, а также по одному на каждое значение в теге `ARTISTS` |
| Артист альбома | Да, собственный артист альбома, как его указывает источник, иначе первый артист |
| Признак сборника | Только для альбома, который источник относит к «Various Artists», или который администратор помечает как сборник |
| Альбом | Да |
| Год | Да |
| Обложка альбома (JPEG) | Да |
| Тексты песен (обычный + синхронизированный) | Да, если lrclib возвращает результат |
| Метка Explicit | Да, когда песня помечена как содержащая нецензурное содержание (см. [Метку Explicit](features/explicit-marker.md)) |

Какие именно теги ID3/Vorbis/MP4 используются, зависит от выходного формата. Подробности о встраивании текстов песен см. в [Текстах песен](features/lyrics.md).

## Прогресс в реальном времени

Downtify передаёт прогресс загрузки в браузер по соединению **WebSocket** (`/api/ws`). По мере отчётов yt-dlp о прогрессе сервер рассылает процент и статусы всем подключённым клиентам. Прогресс-бар двигается в реальном времени — без опроса и без перезагрузки страницы.

## Именование и организация файлов

Имя выходного файла строится из шаблона, настроенного в Настройках (по умолчанию: `{artists} - {title}`). Символы, недопустимые в именах файлов, удаляются.

Когда *Упорядочивать по артисту* включено, файл помещается в подпапку, названную по артисту альбома — или, для трека из сборника разных артистов, по его первому артисту. Иначе одиночные треки идут в корень папки загрузок, а треки плейлистов и альбомов — в подпапку для конкретного плейлиста или альбома. См. [Несколько артистов и сборники](features/file-organization.md#several-artists-and-compilations).
