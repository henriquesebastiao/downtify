# Интернационализация

Downtify се превежда на две независими места: **приложението** (интерфейсът му) и тази **документация**. Езикът по подразбиране и на двете е **английският**, с още девет езика вградени.

## Смяна на езика

### Приложението

Отидете в **Настройки → Език** и изберете предпочитания от вас език. Изборът се записва в `localStorage` на браузъра и се прилага веднага, без презареждане на страницата. Страницата също го съобщава на сървъра (записът `ui_language` в `settings.json`, вижте [`POST /api/settings/update`](../api-reference.md#post-apisettingsupdate)), при всяко зареждане и при всяка промяна, така че работата, която върви без браузър, да знае вашия език - биографията на изпълнител, взета във фонов режим, когато една негова песен приключи изтеглянето, идва на него (вижте [Когато изтеглянето приключи](artist-images.md#when-a-download-finishes)). От ваша страна няма какво да правите: ако сте избрали език, преди това да съществува, той се взема следващия път, когато отворите Downtify. При няколко браузъра с различни езици печели последният, който го е заредил или променил.

### Документацията

Документацията се отваря на езика, който предпочита браузърът ви, когато е преведена на него, а иначе на английски. **Бутонът с глобус** вдясно в горната лента сменя езика по всяко време и ви оставя на същата страница (и секция). Изборът ви се помни в браузъра и оттогава има предимство пред езика на браузъра, докато не изберете друг.

Страница, която още не е преведена, показва бележка и английския текст, така че всеки език винаги има всяка страница.

## Налични езици

| Код | Език | Приложение | Док. |
| ------- | ------------------ | --- | ---- |
| `en` | English (по подразбиране) | ✓ | ✓ |
| `es` | Español | ✓ | ✓ |
| `pt-BR` | Português (Brasil) | ✓ | ✓ |
| `fr` | Français | ✓ | ✓ |
| `tr` | Türkçe | ✓ | ✓ |
| `el` | Ελληνικά | ✓ | ✓ |
| `hu` | Magyar | ✓ | ✓ |
| `bg` | Български | ✓ | ✓ |
| `de` | Deutsch | ✓ | ✓ |
| `ko` | 한국어 | ✓ | ✓ |

Справочните страници, предназначени за разработчици — [API справочникът](../api-reference.md), [договорът за мобилния клиент](../mobile-client-contract.md) и дневникът на промените — остават на английски на всеки език.

## Принос с превод

Можете да превеждате приложението, документацията или и двете. Те са отделни работи с отделни файлове, така че един pull request може да съдържа едното или другото — или един език може да бъде добавен първо към едното, а по-късно към другото.

| Превеждате | Къде са файловете | Готово, когато |
| ------------- | ------------------- | --------- |
| **Само приложението** | `frontend/src/i18n/locales/<code>.js` | езикът се появи в **Настройки → Език** |
| **Само документацията** | `docs/.vitepress/locales/<code>.mjs` и Markdown страниците в `docs/<code>/` | езикът се появи в менюто с глобус на документацията |
| **И двете** | всичко горно | и двете |

Езикът не е нужно да съществува в приложението, за да бъде добавен към документацията, и обратно.

## Превод на приложението

Добавянето на превод към приложението е процес в три стъпки:

### 1. Копирайте английския езиков файл

Езиковите файлове са в `frontend/src/i18n/locales/`. Всеки файл експортира един обект, чиито ключове съвпадат със структурата на `en.js`. Ползвайте [IETF езиков таг](https://en.wikipedia.org/wiki/IETF_language_tag) за името на файла.

```bash
cp frontend/src/i18n/locales/en.js frontend/src/i18n/locales/it.js
```

### 2. Преведете стойностите

Оставете непроменени ключовете, токените за заместване (напр. `{count}`, `{name}`, `{file}`) и общата форма — само низовете отдясно трябва да се променят. Задайте `language.name` на **родното** име на езика (`"Français"`, `"Deutsch"`, …) — това е етикетът в избора на език.

### 3. Регистрирайте езика

Добавете import и запис към `AVAILABLE_LOCALES` в `frontend/src/i18n/index.js`:

```js
import it from './locales/it.js'

export const AVAILABLE_LOCALES = [
  { code: 'en', name: 'English', messages: en },
  { code: 'es', name: 'Español', messages: es },
  // …
  { code: 'it', name: 'Italiano', messages: it }, // new
]
```

Прекомпилирайте frontend и езикът ви ще се появи автоматично в **Настройки → Език**:

```bash
cd frontend && npm run build
```

### Съвети за превод на приложението

- Липсващите ключове се връщат към английски, така че частичните преводи работят добре — изпратете PR с каквото имате.
- Низовете, зависещи от число, са обекти с форми за множествено число, напр. `tracks: { one: '{count} track', other: '{count} tracks' }`. Формата се избира с [`Intl.PluralRules`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) на браузъра за вашия език, така че добавете формите, които езикът ви ползва (`zero`, `one`, `two`, `few`, `many`, `other`) — `other` е задължителна. Числата се форматират автоматично за езика.
- Токените за заместване като `{count}` или `{file}` трябва да останат непроменени; те се заместват по време на изпълнение.
- Дръжте низовете кратки — интерфейсът е плътно подреден и много дълги преводи може да се пренасят зле.
- След превода стартирайте `npm run dev` от `frontend/` и обходете всяка страница на вашия език, за да забележите какво прелива или звучи странно в контекста.

## Превод на документацията

Английският е източникът: той е в `docs/`. Всеки друг език има папка с името на кода си (`docs/pt-BR/`) със **същите имена на файлове** като английския, плюс един файл за собствените текстове на сайта (`docs/.vitepress/locales/pt-BR.mjs`: заглавията на страничната лента, полето за търсене, долния колонтитул, етикетите на кутиите). Страница, която още не е преведена, е малка заготовка, която показва бележка и включва английската страница.

### Превод на страница от съществуващ език

От `docs/`:

```bash
npm install
npm run i18n -- status pt-BR           # what is translated, what is English-only, what is out of date
npm run i18n -- start pt-BR features/users.md
```

`start` заменя заготовката `docs/pt-BR/features/users.md` с копие на английската страница. Преведете я на място, после я проверете:

```bash
npm test             # the translated pages must keep the English page's structure
npm run dev          # read it in the browser, in your language
```

Отворете pull request, когато страницата се чете добре; частичната работа също е добре дошла — страниците, които не сте пипали, просто остават на английски.

### Добавяне на език към документацията

1. Копирайте `docs/.vitepress/locales/en.mjs` в `docs/.vitepress/locales/<code>.mjs` и го преведете: родното `name`, текстовете на сайта (`ui`), етикетите на кутиите (`containers`) и заглавията на страничната лента (`nav`).
2. Регистрирайте го в `docs/.vitepress/locales/index.mjs`.
3. Създайте страниците като заготовки само на английски: `npm run i18n -- stubs <code>`.
4. Превеждайте страниците една по една с `npm run i18n -- start <code> <page>`.

Езикът се появява в менюто с глобус и в разпознаването на езика на браузъра веднага щом е регистриран.

### Какво да запазите и какво да преведете

- **Превеждайте** текста, заглавията, клетките на таблиците, заглавията на кутиите и стойностите `title`/`text` във front matter на началната страница.
- **Запазете както са** блоковете с код, вградения `code`, URL адресите, променливите на средата, API пътищата и имената на полета, имената на файлове и папки, ключовете на front matter и стойностите на `icon:` и `link:`. Превеждането на коментар в блок с код е допустимо.
- **Връзки**: запазете точно относителните `.md` връзки на английската страница (`[Текстове](lyrics.md#sidecar-lrc-file)`). Връзка към страница, която е само на английски, все още работи. На началната страница връзките се пишат с езиковия префикс (`/pt-BR/features/player/`).
- **Заглавия**: запазете същите заглавия, в същия ред и на същите нива. Връзките към секция (`#sidecar-lrc-file`) продължават да работят на всеки език, защото преведената страница преизползва английските ID на заглавията — вие никога не пишете и не превеждате ID.
- **Имена на бутони и настройки**: приложението има собствен превод на всеки етикет. Ползвайте го, с удебелен шрифт, за да съвпада страницата с това, което читателят вижда на екрана: потърсете етикета в `frontend/src/i18n/locales/<code>.js`. Ако приложението още не е преведено на този език, запазете английския етикет.
- **Кутии** (`::: tip Заглавие`): запазете вида (`info`, `tip`, `warning`, `danger`) и преведете заглавието. Кутия без заглавие е с етикет думата от `containers` в езиковия файл.
- **Тон**: пишете за читателя на този език — страниците са ръководства, а не дума по дума преводи.

### Поддържане на преводите актуални

Когато английска страница се промени, преводите ѝ не е нужно да се променят в същия pull request: преведената страница продължава да работи, а `npm run i18n -- status <code>` изброява страниците, чийто английски източник се е променил след превода им. Обновяването им е добър първи принос.

Тестовете (`npm test` в `docs/`) проверяват, че всеки език има всяка страница и всеки текст на сайта и че преведената страница все още има заглавията, блоковете с код, таблиците, кутиите и връзките на английската страница.
