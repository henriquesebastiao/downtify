# M3U 내보내기

Downtify는 Spotify 재생목록을 다운로드할 때마다(직접 하든 [재생목록 모니터](playlist-monitor.md)를 통하든) 표준 `EXTM3U` 재생목록 파일을 자동으로 만듭니다.

## 파일 위치

| 상황 | M3U 경로 |
|-----------|---------|
| 일반적으로 다운로드한 재생목록 | `<downloads>/<재생목록-이름>/<재생목록-이름>.m3u` |
| *아티스트별로 정리*를 켠 채 다운로드한 재생목록 | `<downloads>/Playlists/<재생목록-이름>.m3u` |

*아티스트별로 정리*가 켜져 있으면 트랙이 여러 아티스트 폴더에 흩어지므로, M3U는 재생목록 하위 폴더 대신 중앙의 `Playlists/` 디렉터리에 놓입니다.

[좋아요 표시한 곡](liked-songs.md)도 구성과 관계없이, 그리고 *M3U 재생목록 생성*이 켜져 있든 아니든 `Playlists/Downtify Liked Songs.m3u`에 기록됩니다.

## 상대 경로

M3U 안의 트랙 경로는 절대 경로가 아니라 **M3U 파일 자체를 기준으로 한 상대 경로**로 기록됩니다. 따라서 같은 파일을 Downtify 컨테이너 내부(`/downloads/…`)에서 읽든, 같은 라이브러리를 다른 루트에 마운트한 다른 소비자(예: `/nas/music/…` 아래의 Jellyfin)에서 읽든 동작합니다. 미디어 서버가 같은 라이브러리 마운트를 가리키게만 하면 재생목록이 하나의 묶음으로 나타납니다.

## 켜기 / 끄기

M3U 생성은 **설정 → 다운로드 및 파일 → M3U 재생목록 생성**으로 제어합니다(기본값은 켜짐). 끄면 M3U 생성을 완전히 건너뛰며, 나머지 다운로드 흐름은 바뀌지 않습니다.

## 커버 아트

이 설정 바로 아래의 **재생목록 커버 아트 저장**(기본값은 켜짐)은 재생목록 고유의 커버 이미지를 M3U 옆에 같은 이름으로 기록합니다. 트랙보다 먼저 기록되므로 폴더가 처음부터 재생목록처럼 보입니다. 그러면 Downtify는 재생목록에 트랙 커버를 격자로 보여 주는 대신 이 이미지를 표시합니다. 라이브러리에서 만든 재생목록은 같은 방식으로 기록되는 최대 네 장의 트랙 커버 모자이크를 받습니다. [재생목록 커버 아트](playlist-cover-art.md)를 참고하세요.

## 기록되는 시점

M3U는 **트랙이 하나 다운로드될 때마다** 다시 쓰이므로, 재생목록 파일은 마지막에 한꺼번에 나타나지 않고 다운로드가 진행되는 동안 점점 늘어납니다. 재생목록과 앨범 다운로드, [CSV 가져오기](library-import.md), [재생목록 모니터](playlist-monitor.md#m3u-integration) 점검 모두 마찬가지입니다.

즉 첫 트랙이 도착하는 순간부터 재생목록을 재생할 수 있고, 동기화가 진행되는 것을 눈으로 볼 수 있으며, 느리거나 멈춘 다운로드 하나가 M3U나 이미 끝난 트랙이 나타나는 것을 막을 수 없습니다.

전체 실행이 끝나면 마지막으로 한 번 더 다시 씁니다. 이때는 각 트랙을 (이번 실행이 내려받은 것의 메모리 목록이 아니라) 파일 시스템을 기준으로 확인하므로, 이전 실행의 파일도 포함하고 실행 도중 디스크에서 바뀐 것도 바로잡습니다.

기록할 때마다 트랙은 다운로드가 끝난 순서가 아니라 **재생목록 순서**로 나열되므로, 일부만 기록된 M3U도 올바른 순서입니다.

::: info 이미 디스크에 있는 트랙
이전 실행에서 내려받은 트랙은 M3U에 계속 남아 있습니다. 마지막 기록에서만 추가되는 것이 아니라 첫 기록부터 포함됩니다.
:::

## 재생성

M3U는 실행할 때마다 새로 만들어집니다. 같은 재생목록 URL을 다시 붙여넣으면 이전 실행에서 빠졌던 트랙까지 포함한 완전하고 순서가 맞는 파일이 만들어집니다.

다운로드에 실패했거나 YouTube Music에서 일치하는 결과가 없던 트랙은 조용히 건너뜁니다.

## 호환성

생성된 파일은 다음을 사용합니다.

- BOM 없는 UTF-8 인코딩
- LF 줄 바꿈
- 표준 `#EXTM3U` / `#EXTINF` 형식

Jellyfin, Navidrome, Plex, VLC, Kodi, Sonos 및 표준 M3U 재생목록을 읽는 모든 플레이어와 미디어 서버와 호환됩니다.

## 직접 만드는 재생목록

**라이브러리 → 재생목록 → 새 재생목록**은 같은 종류의 M3U를 `Playlists/` 아래에 기록하며, Downtify가 다운로드한 Spotify/YouTube 재생목록과 구분할 수 있도록 `#EXTDOWNTIFY:manual` 줄이 하나 더 들어갑니다. 이름을 바꾸거나 곡을 추가·제거할 수 있고([추가 폴더](external-library.md)의 곡도 가능), 이 재생목록이나 트랙을 삭제하거나 추가 폴더의 매핑을 해제하면 M3U가 갱신됩니다. 오디오는 트랙 자체나 가져온 재생목록을 삭제할 때만 지워집니다.

### 재생목록에 곡 추가

관리자는 여러 곳에서 곡을 이 재생목록 중 하나 또는 새 재생목록에 넣을 수 있습니다.

- **곡의 ⋯ 메뉴**(모든 트랙 목록에서) → **재생목록에 추가**.
- 라이브러리에서 **여러 곡을 선택**하고 **재생목록에 추가**를 누르기.
- **앨범의 ⋯ 메뉴** → **재생목록에 추가**는 앨범의 모든 곡을 추가합니다.
- **아티스트의 ⋯ 메뉴**(아티스트 페이지에서) → **재생목록에 추가**는 라이브러리에 있는 아티스트의 모든 곡을 앨범별로 추가합니다.

각 메뉴에는 내 재생목록과, 해당 곡이 이미 담긴 새 재생목록을 만드는 **새 재생목록…** 항목이 나열됩니다. 재생목록에 이미 있는 곡은 건너뛰며, 확인 메시지에 실제로 몇 곡이 추가되었는지(또는 모두 이미 있었다는 것)가 표시됩니다. 재생목록에는 최대 500곡을 담을 수 있습니다.
