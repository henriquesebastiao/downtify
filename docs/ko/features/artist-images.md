# 아티스트 사진, 배너 및 소개

Downtify는 라이브러리의 모든 아티스트에 대해 생성된 이니셜과 빈 텍스트 대신 실제 프로필 사진, 배너, 소개글을 보여줄 수 있습니다. 새 아티스트의 페이지를 처음 열 때 또는 그 아티스트의 곡 하나가 다운로드를 마치는 즉시 자동으로 채워집니다. 그 후에는 직접 다른 사진/배너를 고르고, 다시 가져오거나, 자신만의 소개글을 쓰고, 소셜 링크를 직접 채울 수 있습니다.

편집 기능은 설정을 먼저 켜지 않아도 라이브러리의 모든 아티스트 페이지에서 항상 사용할 수 있습니다.

::: info 설정의 "아티스트 사진 자동 다운로드" / "아티스트 배너 자동 다운로드"에 대하여
**설정 → 다운로드 및 파일 → 아티스트 사진 자동 다운로드 / 아티스트 배너 자동 다운로드**는 Downtify가 아티스트의 사진/배너를 스스로 저장해도 되는지를 정합니다. 이는 아티스트 페이지를 처음 열 때와 그 아티스트의 곡 하나가 다운로드를 마칠 때 일어납니다([새 아티스트를 처음 열 때](#the-first-time-you-open-a-new-artist) 및 [다운로드가 끝나면](#when-a-download-finishes) 참고). 사진은 기본적으로 켜져 있고 배너는 꺼져 있습니다. 이 설정은 편집 창을 절대 제한하지 않습니다. 설정과 관계없이 언제든 사진이나 배너를 직접 고를 수 있습니다.
:::

## 편집 창

**아티스트에게 배너가 설정되어 있으면 페이지 헤더에서 둥근 사진이 숨겨집니다.** 배너만으로 충분한 경우가 많고, 둘 다 보여주면 복잡해 보였기 때문입니다. 하지만 사진이 사라진 것은 아닙니다. 편집을 위해 여전히 한 탭 거리에 있습니다.

라이브러리의 아티스트 페이지(`/library/artist?name=…`)에서 둥근 사진(표시될 때) 위에 마우스를 올리면 **사진 편집** 버튼이, 배너 영역 위에 올리면 **아티스트 편집** 버튼이 나타납니다. 둘 다 같은 창을 엽니다. 위쪽에는 아티스트의 현재 사진이 있고, 그 아래에는 네 개의 탭으로 된 메뉴가 있습니다. 클릭한 버튼에 따라 **프로필** 또는 **배너**로 열립니다(사진은 항상 클릭할 수 있게 보이는 것이 아니므로 기본값은 **배너**입니다).

- **프로필** / **배너** — 두 곳 모두 같은 방식으로 이미지를 고릅니다.
  - **이름으로 검색** — YouTube Music과 Deezer에서 일치하는 아티스트 사진을 검색합니다(Deezer의 일반 자리표시자 이미지만 있는 Deezer 아티스트는 제외됩니다). 다른 이름을 검색하려면 다른 내용을 입력하고, 단발성 후보로 쓰려면 이미지 직접 링크 `http(s)://`를 입력하세요.
  - **기기에서 업로드** — 모든 이미지 파일.
  - **사진 제거 / 배너 제거** — 활성 탭의 이미지가 저장된 후에만 표시됩니다. 확인을 요청한 뒤 보조 파일(sidecar)을 삭제합니다.

  각 검색 결과 카드에는 출처를 나타내는 배지가 붙어 있습니다. 하나를 고르면 즉시 다운로드되어 저장됩니다. 이미지가 현재 저장된 것과 같은 카드에는 프로필 탭과 배너 탭에서 각각 따로 녹색 테두리와 체크 표시가 붙습니다. 그래서 어떤 후보를 쓰고 있는지 한눈에 볼 수 있습니다. 직접 업로드한 사진이나 Downtify가 이를 기억하기 전에 저장된 사진에는 표시할 카드가 없습니다.
- **소개** — 현재 저장된 소개글(없으면 비어 있음)이 들어 있는 단순 텍스트 상자로, 직접 쓰거나 편집할 수 있습니다. 저장하면 현재 텍스트를 그대로 덮어씁니다. 상자 위의 ⚡ **Streams에서 소개 가져오기** 버튼은 직접 입력하는 대신 Apple Music/Deezer 데이터로 채워줍니다. 아래 [소개 자동으로 가져오기](#fetching-a-bio-automatically)를 참고하세요.
- **소셜** — Twitter/X, Instagram, Facebook, YouTube, 웹사이트 링크이며 직접 편집할 수 있습니다. 저장하면 항상 다섯 필드 모두를 양식에 있는 내용으로 바꾸며, 비워 둔 필드도 마찬가지입니다. 소개를 가져와도 직접 채운 링크는 절대 건드리지 않습니다. Deezer의 소셜 링크는 아직 비어 있는 필드만 채웁니다(Deezer는 모든 소셜 네트워크를 알지 못하므로 나머지는 직접 채우면 그대로 유지됩니다).

## 새 아티스트를 처음 열 때

라이브러리 아티스트의 페이지를 열면 아직 아무것도 저장되지 않은 경우에 한해 프로필이 자동으로 채워집니다. 첫 방문 이후의 모든 방문은 빠른 no-op이므로, 이는 절대 반복되지 않으며 한 번 실행된 후에는 아무것도 느려지지 않습니다.

- **사진과 배너** — Spotify에서 가져오며([Spotify](#spotify) 참고), Spotify에 아무것도 없으면 YouTube Music의 이름 정확 일치로 대체합니다. 설정에서 **아티스트 사진 자동 다운로드** 및/또는 **아티스트 배너 자동 다운로드**를 켠 경우에만 해당합니다(둘 다 기본값은 꺼짐이며 각각 독립적입니다). 편집 창에서는 언제든 둘 다 직접 설정할 수 있습니다.
- **소개, 출신, 결성 연도, 장르, 그룹 표시, 배너 색상, 소셜 링크, 관련 아티스트, 플랫폼 ID** — 아래 [소개 자동으로 가져오기](#fetching-a-bio-automatically)에 설명된 대로 Apple Music과 Deezer에서 가져옵니다.

이 작업이 실행되는 동안 Apple Music이나 Deezer가 **실패**하면(접근 불가, 또는 요청 한도 초과) 아무것도 저장되지 않으며(소개도 사진도 마찬가지), 페이지는 아직 프로필을 보여주지 않으므로 다음 방문 때 다시 시도합니다. 서비스가 아티스트를 모른다고 응답한 경우에만 응답으로 간주됩니다. 그러면 다른 서비스가 가진 정보로 프로필이 만들어집니다. Spotify 부분(관련 아티스트)은 프로필 생성을 절대 막지 않습니다.

## 다운로드가 끝나면

아티스트의 곡 하나가 다운로드를 마치면 — 앱에서 직접 시작했든 [플레이리스트 모니터](playlist-monitor.md) 스캔이 시작했든 — 그 아티스트에게 아직 프로필이 없을 경우 같은 채우기가 백그라운드에서 실행됩니다. 그래서 다운로드한 아티스트는 페이지를 열기도 전에 준비되어 있습니다. 다운로드는 절대 느려지지 않습니다. 아티스트는 대기열에 들어가 몇 초 뒤에 한 번에 두 명씩 채워지며, 이미 대기열에 있는 아티스트는 그 아티스트의 곡이 아무리 더 도착해도 다시 대기열에 들어가지 않습니다(한 아티스트의 50곡짜리 플레이리스트도 한 번만 채웁니다). 이미 라이브러리에 있는 곡은 다시 다운로드되지 않으며 아무것도 일으키지 않습니다.

- **어느 아티스트** — 파일이 보관되는 아티스트입니다. 앨범 아티스트, 없으면 처음 표기된 아티스트입니다. `Various Artists`는 건너뜁니다.
- **언어** — 소개와 장르는 페이지가 서버에 보관하는 웹 인터페이스 언어로 가져옵니다([국제화](internationalization.md) 참고). 페이지가 알려주기 전까지는 영어입니다.
- **사진과 배너** — **아티스트 사진 자동 다운로드** / **아티스트 배너 자동 다운로드**가 허용하는 만큼만, 그 시점에 읽어서 적용하므로 설정을 바꾸면 바로 다음 곡부터 적용됩니다.
- **Top songs** — 이런 방식으로 만들어지지 않으며 아티스트 페이지를 기다립니다([Top songs](top-songs.md) 참고).

아티스트에 대해 어디서도 아무것도 찾지 못한 경우에도 이는 한 번만 실행되며, 이후 방문 때마다 다시 시도하지 않습니다. 나중에 언제든 편집 창에서 사진/배너를 직접 고르거나 가져오기 버튼을 다시 시도하세요.

## 링크 탭

저장된 링크가 하나라도 있는 아티스트는 **소개** 바로 앞에(**소개**는 계속 마지막 탭) 개수 카운터가 달린 **링크** 탭을 갖습니다. 링크는 카드로 나열되며, 어떤 화면에서든 아티스트에게 배너가 있든 없든 마찬가지입니다. **스트리밍 플랫폼**이 먼저, 그다음 **소셜**이 나옵니다. 각 카드는 사이트 이름과 주소를 보여주고 새 탭에서 엽니다. 실제로 저장된 것만 나열되며, 링크가 없는 아티스트에게는 링크 탭이 없습니다(이 경우 `?tab=links`는 첫 번째 탭을 엽니다).

- **스트리밍 플랫폼** — Spotify, YouTube Music, Deezer, Apple Music이며 프로필의 `platforms_id`로 구성됩니다. 저장된 각 ID가 링크가 됩니다(예: 저장된 Deezer ID는 해당 아티스트의 Deezer 페이지 링크가 됨). ID는 소개를 처음 가져올 때 각 플랫폼에서 이름 정확 일치로 모두 자동 확인됩니다(Spotify ID는 아티스트의 자체 Spotify 곡 중 하나가 있으면 거기서 가져오므로 동명이인을 고를 수 없습니다). 아티스트 프로필 JSON에서 직접 하나를 추가하거나 고칠 수도 있습니다(아래 참고).
- **소셜** — Twitter/X, Instagram, Facebook, YouTube, 웹사이트: 위의 소셜 탭에서 비어 있지 않은 필드마다 카드 하나가 생깁니다. 웹 주소만 열립니다. `https://` 없이 입력된 링크에는 이것이 붙고, 다른 종류의 주소(예: `javascript:`)는 무시됩니다.

## Spotify

Spotify는 자유 텍스트 검색 소스로는 나타나지 않지만, 선택기와 첫 방문 자동 채우기(위 참고) 모두 그곳에서 아티스트를 찾아냅니다. 먼저 아티스트의 이미 다운로드된 곡 몇 개를 확인합니다. 하나가 Spotify에서 다운로드되었다면 Downtify는 그 곡의 Spotify ID를 이미 알고 있어 이미지를 직접 확인합니다. 이름이 같은 다른 아티스트로 갈 수 없으므로 가장 신뢰할 수 있는 경로입니다. Spotify에서 온 곡이 하나도 없으면(예를 들어 YouTube에서 다운로드된 경우) 아티스트를 정확한 이름으로 검색합니다(대소문자 구분 없음 — 유사 일치는 절대 사용하지 않습니다). 선택기에서는 이 후보가 **Spotify** 라벨과 함께 가장 먼저 표시됩니다.

이름 검색은 Spotify 자체 웹 플레이어의 검색창을 사용하므로 Spotify가 바꿀 수 있는 내부 식별자에 의존합니다. 그런 일이 생기면 Downtify는 실패하는 대신 사진/배너를 YouTube Music으로 대체하고 Spotify ID를 비워 둡니다.

사진과 배너는 Spotify에서 실제로 서로 다른 이미지이며 다르게 확인됩니다. 정사각형 사진은 아티스트의 공개 임베드 페이지에서, 넓은 배너는 Spotify 자체 아티스트 페이지 데이터에서 가져옵니다(임베드는 이를 전혀 노출하지 않습니다). 모든 아티스트에게 배너가 설정되어 있는 것은 아닙니다. 없으면 정사각형 사진으로 대체하는 대신 배너 선택기에 Spotify 후보를 제공하지 않습니다.

Spotify에서 온 곡이 없는 아티스트는 그저 Spotify 후보가 없을 뿐입니다. YouTube Music/Deezer에서 검색하거나, 링크를 붙여넣거나, 이미지를 업로드하세요.

## 소개 자동으로 가져오기

헤더 아래에 아티스트 페이지는 읽기 전용의 짧은 소개글을 보여줍니다. 저장된 것이 없으면 비어 있습니다. 채우려면 편집 창의 **소개** 탭을 열고 텍스트 상자 위의 **Apple Music에서 가져오기** 또는 **Deezer에서 가져오기**를 클릭하세요([소스 선택](#choosing-the-source) 참고). 그러면 해당 서비스의 소개가 상자에 불러와져 검토 후 저장할 수 있습니다. 스스로 저장하는 첫 방문 자동 채우기는 Apple Music에서 아티스트를 이름 정확 일치로 찾아(Apple 자체 음악 앱이 쓰는 것과 같은 이름 검색 사용) 소개, 출신, 결성 연도, 장르, 그룹 표시, 배너 강조 색상을 가져오고 — 텍스트(소개와 장르)는 현재 인터페이스 언어로 — 결과를 저장합니다. 장르(Apple Music은 아티스트당 하나를 제공, 예: "Hard rock")는 아티스트 페이지의 소개 탭 맨 위에 출신과 결성 연도 옆에 작은 알약 모양으로 표시됩니다. Apple Music은 아티스트가 그룹인지 알려줍니다. 그룹의 경우 이 날짜는 "1995년 결성"으로 읽히고, 날짜가 보통 생일인 솔로 아티스트의 경우 "출생: 1984년 9월 27일"로 읽힙니다(모든 인터페이스 언어로 번역됨. 그룹 표시를 알 수 없는 아티스트는 "결성"으로 남습니다). 날짜 자체는 Apple Music이 준 그대로 표시되므로 가져온 언어를 유지합니다. Apple Music에 정확히 일치하는 항목이 없거나, 있어도 사용자의 언어로 된 소개 텍스트가 없으면 두 번째 소개 소스로 Deezer를 시도합니다. Deezer는 소셜 링크와 "팬들이 좋아하는" 관련 아티스트 이름도 가져오며(관련 아티스트는 아티스트의 프로필 파일에 저장되지만 아직 어디에도 표시되지 않고 향후 추가를 위해 보관됨), 소셜 탭도 함께 채웁니다. 두 소스 모두 아무것도 없을 때에만 추측했거나 잘못된 소개 대신 오류가 표시됩니다.

Apple Music의 편집 소개글은 모든 아티스트에 대해 모든 언어로 작성되어 있지 않습니다. 특정 아티스트에 대해 어떤 언어가 없으면 대신 Deezer의 소개(있는 경우)가 사용되고, 출신/결성 연도/그룹 표시는 번역된 텍스트가 아닌 사실이므로 계속 Apple Music에서 가져옵니다(장르는 항상 Apple Music에서만 오므로 Apple에 일치 항목이 없으면 비어 있음). 일부 언어(작성 시점의 불가리아어)는 Apple Music이 아예 제공하지 않으며 항상 기본 언어의 소개로 대체됩니다.

소개는 아티스트의 JSON에 일반 텍스트로 저장됩니다. HTML 태그나 글머리 기호 문자는 없습니다. 빈 줄이 단락을 구분하고, Apple Music 소개의 각 `•` 글머리(Apple은 한 번의 줄바꿈으로 구분)는 각각 별도의 단락이 됩니다. Deezer의 HTML 소개도 같은 방식으로 평탄화됩니다(각 단락은 빈 줄로 구분된 단락이 되고 다른 모든 태그는 버려짐). 아티스트 페이지는 각 단락을 따로 보여주며 그 안의 단일 줄바꿈은 유지하고, 소개 탭의 텍스트 상자는 정확히 그 텍스트를 편집합니다.

이렇게 다시 가져오는 것은 버튼을 클릭할 때만 실행됩니다. 위에서 설명한 첫 방문 자동 채우기 이후에는 스스로 아무것도 덮어쓰지 않습니다. 처음 한 번만(자동 채우기든 수동 클릭이든) 이름으로 검색해야 합니다. 확인된 Apple Music과 Deezer 아티스트 ID는 이후 아티스트의 프로필 파일에 캐시되므로 다시 가져올 때는 같은 아티스트를 직접 다시 읽기만 합니다.

저장된 소개를 지우려면 소개 탭을 열고, 텍스트 상자를 비우고 저장하세요. 출신, 결성 연도, 장르, 그룹 표시, 소셜 링크, 관련 아티스트, 캐시된 플랫폼 ID는 그대로 유지됩니다.

## 소스 선택

소개 탭에는 어떤 소개가 더 잘 읽히는지 고를 수 있도록 텍스트 상자 위에 두 개의 링크가 있습니다.

- **Apple Music에서 가져오기** — Apple Music의 편집 소개를 텍스트 상자에 불러옵니다. Apple Music에 이 아티스트에 대한 사용자 언어의 소개가 없으면 대체물 대신 오류가 표시됩니다.
- **Deezer에서 가져오기** — Apple Music에 있더라도 Deezer의 소개를 불러옵니다. Deezer에 없으면 오류가 표시됩니다.

링크를 클릭하면 **텍스트 상자만 채워집니다.** **저장**을 누르기 전까지는 아무것도 저장되지 않으므로, 읽어 보고, 편집하고, 먼저 다른 서비스를 시도해 볼 수 있으며, 저장하지 않고 창을 닫으면 현재 소개는 그대로 남습니다. 소개 텍스트만 불러옵니다. 출신, 결성 연도, 장르, 소셜 링크, 관련 아티스트, 플랫폼 ID는 이 링크로 건드려지지 않습니다(그것들은 첫 방문 자동 채우기가 채웁니다). 자동 채우기는 어느 서비스인지 묻지 않습니다. Apple Music의 소개를 사용하고, Apple Music에 없을 때만 Deezer의 소개로 대체합니다.

## 파일이 저장되는 위치

```
<downloads>/.metadata/ArtistImage/<Artist>.jpg
<downloads>/.metadata/ArtistBannerImage/<Artist>.banner.jpg
<downloads>/.metadata/ArtistData/<Artist>.json
<downloads>/.metadata/ArtistTopSongs/<Artist>.topsongs.json
```

아티스트마다 파일 하나가 그 이름으로 저장됩니다(곡 파일 이름과 같은 방식으로 정리됨). 데이터베이스 레코드가 없으므로 디스크에 파일이 있는지가 아티스트 페이지가 확인하는 기준입니다. 새 사진/배너를 저장하면 이전 것을 덮어씁니다(웹 인터페이스는 이전 것의 사본이 계속 표시되는 것을 막습니다. 저장된 모든 이미지의 URL에 파일의 수정 시간이 포함되므로 교체된 사진은 다시 가져오고 그대로인 사진은 캐시에 남습니다). `ArtistData/<Artist>.json`에는 위에서 설명한 소개/소셜/관련 아티스트/플랫폼 ID 데이터가 들어 있고, 추가로 `current_cover`와 `current_cover_banner`에 어떤 이미지가 현재 사진/배너인지 기록됩니다. 다운로드한 URL의 경로(호스트와 쿼리는 제외하여 다른 CDN 주소의 같은 이미지도 여전히 일치함), 또는 직접 업로드한 경우 `upload`입니다. 편집 창은 이것으로 각 후보를 비교해 사용 중인 것을 표시합니다. 이는 다운로드 폴더 아래의 일반 파일이므로 Navidrome 같은 서비스를 같은 위치로 지정하면 직접 읽을 수 있습니다.

아티스트 이름은 디스크에 저장된 대로 일치시킵니다. 파일 이름에는 `/`를 쓸 수 없기 때문에 Downtify는 `AC/DC`를 `ACDC`로 보관하고, 아티스트 태그가 없는 곡은 그 파일 이름에서 아티스트를 가져옵니다. 그래서 같은 아티스트가 `AC/DC` 또는 `ACDC`로 나타날 수 있습니다. 모든 이름 검색(Spotify, Deezer, YouTube Music, Apple Music)은 대소문자와 파일 이름에 쓸 수 없는 문자를 무시하므로 두 표기 모두 같은 아티스트를 찾고 위의 같은 파일을 공유합니다. 다른 부분이 있는 이름 — 예를 들어 `AC/DC Tribute` — 은 여전히 다른 아티스트이며 절대 일치하지 않습니다.

`platforms_id`는 `spotify`, `youtubemusic`, `deezer`, `applemusic` 키를 인식하며 모두 자동으로 확인됩니다. Spotify는 아티스트의 자체 Spotify 곡 중 하나에서, 없으면 이름 정확 일치로, 나머지는 이름 정확 일치로 확인합니다. 소개를 가져오면 누락된 Spotify ID도 채워지므로 이 기능이 생기기 전에 열린 아티스트도 한 번 가져오고 나면 Spotify 아이콘이 생깁니다. 이미 저장된 ID는 절대 교체되지 않으며, JSON 파일을 직접 편집해 하나를 직접 설정할 수도 있습니다.

## 범위 밖

여기서 사진/배너를 고르는 것은 다운로드 파이프라인에 절대 영향을 주지 않습니다. 자신의 오디오 파일 태그에 삽입되는 내용에는 아무 영향이 없으며, 곡을 다운로드해도 아티스트 이미지를 자동으로 가져오지 않습니다.

*관련* 탭은 가지고 있지 않은 아티스트에도 사진을 보여주며, 라이브러리의 *아티스트* 그리드, 아티스트 자신의 페이지, 모니터의 *아티스트* 탭(목록과 편집 창에서 모니터링 중인 아티스트), [탐색](discover.md)과 [Finder](finder.md)의 아티스트도 마찬가지입니다. 이 페이지가 이미 아티스트의 Deezer 이미지를 가지고 있는 곳에서는 이름 검색이 필요 없으며, 아티스트를 위해 저장한 사진이 있으면 대신 그것이 표시됩니다. 사진을 직접 고르지 않은 모든 아티스트에 대해(Deezer에 없을 때 라이브러리와 아티스트 자신의 페이지는 아티스트의 곡 커버 중 하나를 사용하고, 모니터에는 곡이 없으므로 이니셜을 표시) - 실제 사진만: Deezer에 사진이 없는 아티스트(일반 자리표시자 이미지를 제공)는 평소의 이니셜을 받습니다 - 하지만 이는 표시 전용입니다. 서버는 Deezer 이미지를 저장하지 않고 브라우저로 중계하며(브라우저는 3시간 캐시), 이는 절대 아티스트의 사진이나 배너가 되지 않습니다. 실제 응답만 유지됩니다. Deezer에 접근할 수 없거나 그 순간 요청 한도를 초과한 경우 타일은 일단 이니셜(또는 곡 커버)을 표시하고 아무것도 기억되지 않으므로, 다음에 페이지를 열 때 사진이 나타납니다. 사진은 직접 하나를 설정한 아티스트나, 위에 설명한 대로 첫 방문에서 사진/배너가 저장된 아티스트(설정이 허용하는 경우)에 대해서만 디스크에 기록됩니다. [`GET /api/artists/photo-proxy`](../api-reference.md#get-apiartistsphoto-proxy)를 참고하세요.
