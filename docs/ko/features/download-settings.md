# 다운로드 설정

사이드바에서 **설정**을 여세요(휴대폰에서는 **더보기 → 설정**). 페이지는 일반, 음원 출처, 다운로드 및 파일, 태그 및 가사, Navidrome, 라이브러리, 정보 섹션으로 나뉩니다. 변경 사항은 아래에 나타나는 바에서 **변경사항 저장**을 누를 때까지 보류되며, 저장하지 않은 변경 사항이 있는 채로 페이지를 나가면 먼저 확인을 묻습니다. 설정은 디스크에 저장되어 컨테이너를 재시작해도 유지됩니다.

## 형식

| 형식 | 확장자 | 참고 |
|--------|-----------|-------|
| MP3 | `.mp3` | 기본값. 범용 호환성. |
| FLAC | `.flac` | 무손실. 비트레이트 설정은 무시됩니다. |
| M4A | `.m4a` | MPEG-4 컨테이너의 AAC. Apple 기기에 적합합니다. |
| OGG | `.ogg` | Ogg Vorbis. 개방형 형식으로 품질 대비 용량이 좋습니다. |
| OPUS | `.opus` | 낮은 비트레이트에서 가장 좋은 압축. |

## 비트레이트

손실 형식(MP3, M4A, OGG, OPUS)에서 사용할 수 있습니다. FLAC는 이 설정을 무시합니다.

| 옵션 | Kbps |
|--------|------|
| 낮음 | 128 |
| 보통 | 192 |
| 높음 | 256 |
| 최고 | **320** (기본값) |

다운로드한 오디오는 모든 손실 형식에서 고른 비트레이트로 인코딩됩니다. YouTube가 제공하는 오디오가 이미 대상 코덱이고 대략 그 비트레이트라면(예: **M4A @ 128**의 경우 약 128 kbps AAC 스트림), 다시 인코딩하면 품질만 떨어지므로 재인코딩하지 않고 그대로 유지합니다.

::: info 비트레이트를 높여도 음질이 좋아지지 않습니다
YouTube 오디오는 최대 약 **128–160 kbps**(AAC 또는 Opus)까지이며, Downtify는 항상 받을 수 있는 최고의 스트림을 내려받습니다. 256이나 320 kbps로 인코딩하면 원본을 충실히 보존하는 더 큰 파일이 만들어지지만, 원본에 없던 디테일을 되살릴 수는 없습니다. 파일 크기가 더 중요하다면 낮은 비트레이트를 고르세요.
:::

## 출력 파일명 템플릿

기본 파일명 템플릿은 다음과 같습니다.

```
{artists} - {title}
```

이렇게 하면 `The Night Owls - Do I Still Recall.mp3` 같은 파일명이 만들어집니다.

사용할 수 있는 토큰:

| 토큰 | 설명 |
|-------|-------------|
| `{title}` | 트랙 제목 |
| `{artists}` | 쉼표로 구분한 아티스트 이름 |
| `{album}` | 앨범 이름 |
| `{tracknumber}` | 앨범에서 트랙의 위치로, 2자리까지 0으로 채웁니다(예: `01`, `12`). 원본에 트랙 번호가 없으면(예: 자유 텍스트/YouTube 검색 결과) 비어 있습니다. |
| `{year}` | 발매 연도(예: `2025`). 원본에 발매일이 없으면(예: 자유 텍스트/YouTube 검색 결과) 비어 있습니다. |

템플릿에 `/`를 넣어 하위 폴더를 만들 수도 있습니다. 예를 들어 라이브러리를 `아티스트/앨범 (2025)/01 - 제목.mp3` 형태로 구성하려면 — 각 앨범이 발매 연도와 함께 자기 폴더에 들어가므로 전체 디스코그래피를 내려받을 때 편리합니다.

```
{artists}/{album} ({year})/{tracknumber} - {title}
```

::: info
이것은 아래의 **아티스트별로 정리** / **앨범별로 정리** 토글과 별개입니다. 그 토글은 재생목록/앨범 다운로드를 라이브러리 전체에서 공유하는 아티스트별 또는 앨범별 폴더로 보냅니다. `{tracknumber}`와 `{year}`는 위와 같은 템플릿이 그 토글을 켜지 않고도 같은 구성을 트랙마다 직접 만들 수 있게 해 줄 뿐입니다.
:::

## 동시 다운로드 수

동시에 내려받는 곡의 수를 제어합니다. 프리셋(1, 2, 3, 5, 8)을 고르거나 옆의 숫자 입력란에 **1에서 30** 사이의 값을 직접 입력하세요.

| 값 | 동작 |
|-------|-----------|
| **1** | 순차 — 한 번에 한 곡(가장 안전하고 자원 사용이 가장 적음) |
| **3** | 기본값. 속도와 안정성의 좋은 균형. |
| **8** | 큰 재생목록에서 더 빠름 |
| **최대 30** | 매우 빠른 연결에 가장 좋음. CPU와 대역폭을 더 쓰고 YouTube가 요청을 제한할 가능성이 커집니다. |

이 제한은 모든 일괄 다운로드 — 재생목록/앨범 다운로드, 일괄 대기열 엔드포인트, CSV [라이브러리 가져오기](library-import.md) — 와 **[기존 음악 폴더](external-library.md)** 동기화 조회(가사, 커버, 장르)에 적용됩니다. 새 트랙을 한 번에 하나씩 내려받는 재생목록 모니터 점검에는 적용되지 **않습니다**. 설정에서 이 값을 바꾸면 재시작 없이 즉시 적용되며, 서버는 `1–30` 범위를 벗어난 값을 범위 안으로 맞춥니다.

## 다운로드 간격

요청을 연달아 쏘는 대신, 한 곡을 마친 뒤 다음 곡을 시작하기 전에 설정한 초만큼 Downtify가 기다리게 합니다.

| 값 | 동작 |
|-------|-----------|
| **0** | 기본값 — 꺼짐, 지연 없음. |
| **5 / 15 / 30 / 60** | 프리셋이며, **0에서 300초** 사이의 값을 직접 입력할 수도 있습니다. |

재생목록, 앨범, 일괄 다운로드와 CSV [라이브러리 가져오기](library-import.md), 재생목록 모니터의 자동 점검에 적용됩니다. 단일 트랙 수동 다운로드에는 적용되지 않으며(기다릴 "다음" 곡이 없음), 어떤 일괄 작업이든 *마지막* 트랙 뒤에는 건너뛰므로 실행이 쓸모없는 대기로 끝나지 않습니다.

더 낮은 **동시 다운로드 수** 값과 함께 쓰면, 큰 재생목록이나 가져온 라이브러리를 무인으로 내려받을 때 YouTube 요청 제한을 피하는 주된 수단이 됩니다.

## 동기화 조회 간격

같은 발상이지만 다운로드가 아니라 **[기존 음악 폴더](external-library.md)** 를 위한 것입니다. 동기화는 가사, 없는 커버, 장르를 **[동시 다운로드 수](#parallel-downloads)** 만큼의 트랙 묶음으로 조회한 뒤, 다음 묶음 전에 이 초만큼 기다립니다. 기본값은 **0**(조회가 계속 동시에 실행되며, 여전히 동시 다운로드 수로 제한됨)입니다. 큰 컬렉션에서는 몇 초를 두어 LRCLIB, 커버 출처, iTunes에 한꺼번에 요청이 몰리지 않게 하세요.

## 커버 아트 다운로드

Downtify가 앨범 아트를 아예 포함할지 제어합니다. 기본적으로 켜져 있습니다. 끄면 커버 아트 가져오기를 완전히 건너뜁니다 — 나머지 모든 태그(제목, 아티스트, 앨범, 연도, 가사)는 평소처럼 포함되지만, 커버 이미지를 요청하거나 쓰지 않으므로 파일이 더 작아지고 다운로드도 약간 빨라집니다.

이것을 끄면 *앨범별로 정리* 옵션([파일 정리](file-organization.md) 참고)이 만드는 별도 `cover.jpg`의 기록도 건너뛰며, 이렇게 내려받은 트랙은 [플레이어](player.md)와 라이브러리에 아트가 표시되지 않습니다(대신 기본 음표 아이콘이 나옵니다).

그 `cover.jpg`는 앨범 폴더의 모든 트랙이 공유합니다. 라이브러리 페이지에서 트랙을 삭제하면 이것도 지워지지만, 그 폴더에 남은 **마지막** 트랙일 때만 그렇습니다 — 같은 앨범의 다른 트랙이 남아 있는 동안은 커버가 유지됩니다.

## 커버 아트 해상도

위의 **커버 아트 다운로드**가 켜져 있을 때만 의미가 있습니다. **YouTube Music** 또는 **Deezer**에서 가져와 포함하는 커버 아트에 Downtify가 요청하는 목표 크기(가로·세로, 픽셀)를 정합니다. 프리셋(300, 600, 800, 1000, 1200)을 고르거나 슬라이더를 **300에서 1200** 사이 어디로든 끄세요. 현재 값(픽셀)이 옆에 표시됩니다. 기본값은 600입니다.

Downtify가 기본으로 포함하는 것보다 높은 해상도로 커버를 표시하는 Plex 같은 미디어 서버에 라이브러리를 연결할 때 유용합니다.

두 출처는 설정을 다르게 적용합니다. 둘 중 하나만 실제로 요청에 따라 크기를 바꿀 수 있기 때문입니다.

- **YouTube Music** 썸네일은 URL을 수정해 크기를 바꿀 수 있습니다 — 실제 CDN에서 확인한 결과, 높은 프리셋은 대부분의 앨범 아트에서 (단순 확대가 아니라) 실제로 더 많은 디테일을 돌려주며, 원본 이미지 자체의 해상도까지 올라갑니다.
- **Deezer**는 어떤 트랙, 앨범, 아티스트, 재생목록 커버든 고정된 네 가지 크기(56, 250, 500, 1000px)만 제공합니다 — 요청할 수 있는 중간 크기가 없습니다. Downtify는 설정값 이상이면서 가장 작은 크기를 고릅니다(300px을 요청하면 정확한 300px 크기가 없으므로 500px짜리를 받음). 1000px을 넘게 요청해도 Deezer의 가장 큰 1000px을 받습니다.

::: info Spotify에서 가져온 커버는 영향을 받지 않습니다
Downtify는 Spotify로 확인된 트랙/앨범/재생목록에 대해 Spotify 공개 embed API가 제공하는 **가장 큰** 커버를 이미 포함합니다 — 요청할 더 큰 크기가 없습니다. 이 설정은 YouTube Music(자유 텍스트 검색, YouTube URL, 실제 오디오를 위해 YouTube Music에 다시 매칭된 모든 Spotify 트랙) 또는 Deezer(붙여넣은 Deezer 링크, 또는 [차트](charts.md)의 트랙)로 확인된 트랙의 상한만 올립니다.
:::

설정에서 이 값을 바꾸면 현재 열려 있는 검색 페이지까지 포함해 즉시 적용됩니다 — 이미 디스크에 있는 것을 다시 내려받을 필요가 없습니다.

## 기존 파일 덮어쓰기

Downtify의 기존 동작에 맞게 기본적으로 켜져 있습니다. 모든 다운로드는 파이프라인(오디오 가져오기, 태그, 커버 아트, 가사)을 거치며 계산된 출력 경로에 이미 있는 파일을 덮어씁니다.

### "다시"가 실제로 뜻하는 것

켜져 있으면 다시 내려받기는 기존 파일의 수리가 아니라 **완전히 새로운 실행**입니다. Downtify는 이미 가진 것을 살피지 않습니다. 설정된 순서대로 [음원 출처](#audio-provider)를 검색하고 — 그래서 slskd가 첫 번째라면 대체 수단이 아니라 slskd를 먼저 시도합니다 — 응답하는 출처에서 오디오를 가져와, 그 위에 오늘의 태그, 커버 아트, 가사를 씁니다.

큰 라이브러리를 다시 내려받기 전에 알아 둘 만한 결과가 하나 있습니다.

::: warning 형식이 다르면 옛 파일이 남습니다
새 파일은 [파일명 템플릿](#output-filename-template)이 만든 경로에 **새** 오디오의 확장자로 써집니다. Downtify는 둘의 확장자가 같을 때만 옛 파일을 덮어씁니다.

그래서 slskd가 FLAC로 응답했을 때 `아티스트 - 곡.mp3`를 다시 내려받으면 **둘 다** 생깁니다. `아티스트 - 곡.mp3`(옛 파일, 그대로)와 `아티스트 - 곡.flac`입니다. [slskd 파일을 그대로 두기](slskd-navidrome.md#leave-files-in-place)가 켜져 있으면(기본값) slskd 파일은 다운로드 폴더로 복사조차 되지 않으므로, 옛 파일은 있던 자리에 그대로 있고 새 파일은 `slskd/` 아래에 있습니다.

잃는 것은 없지만 중복이 생깁니다. 파일을 정말로 교체하려면 경로, 형식, 태그를 유지하는 [음원 교체](replace-audio.md)를 보세요.
:::

### 커버 아트는 파일이 아니라 Spotify나 YouTube Music에서 옵니다

내려받은 오디오가 가진 아트워크는 — slskd 파일에 포함된 고해상도 커버를 포함해 — 태그를 쓰는 동안 **버려지고 교체됩니다**. Downtify는 항상 Spotify나 YouTube Music에서 가져온 트랙의 커버를 설정한 [커버 아트 해상도](#cover-art-resolution)(기본 600px)로 포함합니다. 제목, 아티스트, 앨범 및 나머지 태그도 마찬가지입니다. 출처의 자체 태그는 유지되지 않습니다.

이미 가진 파일에 더 큰 아트워크를 원한다면 다시 내려받기는 먼 길입니다. [라이브러리 업그레이드](library-upgrade.md)가 바로 그 일을 합니다 — 각 파일에 포함된 커버를 Spotify, iTunes, YouTube Music과 비교해 가장 큰 것을 쓰고, 없는 가사와 태그를 채우며, 오디오는 절대 건드리지 않습니다.

이미 디스크에 있는 곡은 절대 내려받지 않게 하려면 끄세요. 재생목록을 내려받거나, [CSV 라이브러리](library-import.md)를 가져오거나, [재생목록 모니터](playlist-monitor.md)가 서로 또는 라이브러리에 이미 있는 곡과 트랙을 공유하는 재생목록을 동기화할 때 가장 중요합니다 — 옵션이 켜져 있으면 그런 중복이 모두 다시 내려받아집니다.

끄면 Downtify는 새 다운로드가 갈 곳만이 아니라 **다운로드 폴더 어디에서나** 곡을 찾습니다.

- 라이브러리 루트(단일 트랙 다운로드),
- 모든 재생목록의 폴더(재생목록 다운로드, CSV 가져오기, 재생목록 모니터),
- 아티스트/앨범 폴더, 또는 *아티스트/앨범별로 정리*를 켜거나 끄기 전의 평면 구성.

오디오 파일(`.mp3`, `.flac`, `.m4a`, `.ogg`, `.opus`)의 이름이 [출력 파일명 템플릿](#output-filename-template)이 그 곡에 만들어 주는 이름과 (대소문자 구분 없이) 같으면 이미 내려받은 곡으로 칩니다. 남아 있는 `.lrc` 가사 파일만으로는 해당되지 않습니다. 템플릿에 폴더가 있다면(예: `{artists}/{title}`) 그 폴더도 일치해야 하므로, 제목이 같은 다른 아티스트의 곡이 이 곡으로 오인되지 않습니다. 파일에는 Spotify/YouTube 트랙 ID가 없으므로 일치 여부는 이름으로 판단합니다. 이름을 바꾼 파일이나 다른 파일명 템플릿으로 저장된 파일은 인식되지 않습니다.

곡을 건너뛸 때:

- 아무것도 가져오지 않습니다: 오디오, 커버 아트, 가사, 다시 태그하기 모두 없습니다. Spotify 트랙은 YouTube Music 검색 전에 확인하므로, 이미 내려받은 곡은 검색 요청을 쓰지 않습니다.
- 대기열에는 곡이 완료로 표시되고, 재생목록 [M3U 파일](m3u-export.md)은 어디에 있든 기존 파일을 가리킵니다(예: `../아티스트 - 제목.mp3`). 그래서 재생목록은 여전히 끝까지 재생됩니다.
- 같은 곡이 동시에 두 번 대기열에 들어가면(한 재생목록에 두 번 있거나, 병렬로 내려받는 두 재생목록에 있을 때), 한 부만 내려받습니다. 다른 쪽은 그것을 기다린 뒤 건너뜁니다.

## 긴 트랙

**설정 → 다운로드 및 파일 → 최대 허용 곡 길이**는 다운로드 *와* 스트림 모두에 대해 트랙 길이의 상한을 정합니다(기본 **10분**, `0`이면 모두 허용). 더 긴 곡은 아무것도 가져오기 전에 *"… 이상의 트랙은 다운로드되지 않습니다"* 대기열 오류와 함께 거부됩니다 — 한 시간짜리 믹스나 업로드는 라이브러리 트랙이어야 할 모습이 아닙니다. 같은 상한이 스트리밍도 지킵니다. 더 긴 트랙은 `400`으로 거부되며(길이를 아는 호출자는 `duration`으로 전달하고, 캐시된 파일은 어떻게든 검사됩니다), 긴 업로드가 스트림 캐시에 쌓이지도 않습니다. 이미 내려받은 파일과 (보통 더 긴) 팟캐스트 에피소드에는 영향이 없습니다.

## 음원 제공자

기본 음원 제공자는 **YouTube Music**입니다. Downtify는 [`ytmusicapi`](https://ytmusicapi.readthedocs.io/)로 트랙 길이를 비교해 가장 잘 맞는 결과를 검색합니다. YouTube Music에 받아들일 만한 결과가 없거나 길이가 크게 어긋나는 결과(다른 녹음일 가능성)만 있으면, Downtify는 자동으로 일반 YouTube 검색으로 대체합니다 — [작동 방식](../how-it-works.md#fallback-to-standard-youtube)을 참고하세요.

**설정 → 음원 출처**에서는 일반 **YouTube**만 쓰거나 **slskd**(Soulseek)를 순서 있는 대체 목록으로 쓸 수도 있습니다 — [slskd와 Navidrome](slskd-navidrome.md#audio-sources-and-fallback-order)을 참고하세요.

### 특정 음원 출처 강제하기

Downtify가 잘못된 YouTube Music 영상(예: 원곡 대신 커버)을 고르면 트랙별로 바꿀 수 있습니다.

**옵션 A — YouTube Music URL을 직접 붙여넣기**

`https://music.youtube.com/watch?v=…`(또는 일반 `youtube.com/watch?v=…` URL)를 검색창에 붙여넣고 다운로드를 누르세요. Downtify는 바로 그 영상에서 오디오를 가져옵니다.

::: info
YouTube URL로 내려받으면 메타데이터(제목, 아티스트, 커버)가 Spotify가 아니라 YouTube에서 옵니다. 깔끔한 태그를 원하면 옵션 B를 사용하세요.
:::

**옵션 B — 실패한 트랙에 오디오 강제하기**

1. **다운로드 대기열**에서 실패한 트랙 아래의 **음원 출처 강제 지정**을 클릭합니다.
2. 나타나는 입력란에 YouTube 또는 YouTube Music URL을 붙여넣습니다.
3. **Enter**를 누르거나 **적용**을 클릭합니다.

Downtify는 바로 그 영상으로 트랙을 다시 내려받으면서 모든 Spotify 메타데이터(제목, 아티스트, 앨범, 커버 아트, 가사)를 유지합니다.

## 포함되는 메타데이터

Downtify는 형식에 관계없이 내려받은 모든 파일에 다음 태그를 포함합니다.

| 태그 | 출처 |
|-----|--------|
| 제목 | Spotify embed |
| 아티스트 | Spotify embed |
| 앨범 | Spotify embed — 단일 트랙 다운로드에서는 트랙의 공개 Spotify 페이지가 가리키는 앨범(트랙 embed 자체에는 없음) |
| 연도 | Spotify embed (트랙 단위 조회) |
| 앨범 아트 | Spotify로 확인된 트랙은 Spotify embed(트랙 단위 커버), 그 외에는 YouTube Music 썸네일 또는 Deezer 커버. 선택 사항 — [커버 아트 다운로드](#download-cover-art)와 [커버 아트 해상도](#cover-art-resolution) 참고 |
| 가사 | lrclib (활성화된 경우) |
