# 라이브러리 카탈로그와 경로 동기화

Downtify는 `/downloads` 아래 파일(slskd 폴더 — [slskd 파일을 그대로 둘](slskd-navidrome.md#leave-files-in-place) 때 — 와 설정에서 추가한 [추가 폴더](external-library.md))의 작은 **카탈로그**를 유지해, 파일이 이동하거나 재생목록이 커져도 라이브러리 페이지, 플레이어, M3U 내보내기, Navidrome 동기화, 중복 감지가 일관되게 유지됩니다.

## 저장되는 것

| 저장소 | 위치 | 용도 |
|-------|----------|---------|
| **트랙 인덱스** | `/data/downtify_library.db` | Spotify 트랙 ID를 라이브러리 경로에 매핑해, 이미 디스크에 있는 트랙을 알아볼 수 있게 합니다 |
| **재생목록 카탈로그** | `/data/downtify_library.db` | 내려받은 각 Spotify 재생목록에 속한 트랙 |
| **재생목록 다운로드** | `/data/downtify_library.db` | 추적 중인 Spotify 재생목록 다운로드와 그 Spotify 트랙 목록의 캐시 |
| **Navidrome 인덱스** | `/data/downtify_library.db` | 파일별 Navidrome 곡 ID |
| **라이브러리 메타데이터 캐시** | `/data/downtify_library.db` | `GET /tracks`를 위한 파일별 제목, 아티스트, 앨범, 앨범 아티스트, 트랙 번호, 연도, 길이, 커버 크기. 파일의 수정 시각이나 크기가 바뀔 때만 다시 읽음 |
| **업그레이드 실행** | `/data/downtify_library.db` | [라이브러리 업그레이드](library-upgrade.md) 대기열과 각 트랙을 마지막으로 확인한 시점, 재시작해도 실행이 이어지도록 |
| **경로 스캔 캐시** | RAM, 그리고 `/data/downtify_library.db`의 스냅샷 | `GET /tracks`의 접힌 행, 재생목록 목록, 경로 쌍. UI 라우트는 디스크를 훑지 않고 이 스냅샷을 제공합니다. 완료된 다운로드는 각각 **즉시 스냅샷에 병합**됩니다(새 아티스트가 기다리지 않고 나타나도록). 삭제는 **그 파일들을 즉시 스냅샷에서 제거**합니다(앨범이 기다리지 않고 그리드에서 사라지도록). 전체 트리 순회는 다운로드 대기열이 한가해진 몇 초 뒤에 백그라운드에서 실행됩니다 — 고정 타이머가 아닙니다. `GET /list?refresh=true`는 스냅샷을 버리고 지금 다시 스캔합니다. |
| **숨긴 항목** | `/data/downtify_library.db` | 관리자가 [사용자에게서 숨긴](users.md#hiding-from-users) 곡, 앨범, 아티스트 |
| **커버 아트 캐시** | `/data/cover_cache` (선택) | `GET /cover`를 위해 추출한 커버 이미지 |

파일은 이동하더라도 **콘텐츠 키** — 파일 이름과 크기의 해시 — 로 매칭됩니다. 파일을 다른 폴더로 옮겨도 키는 유지되고, 다른 파일로 교체하면 새 키를 받습니다.

## 설정 → 라이브러리

### 커버 아트를 디스크에 캐싱

켜면 Downtify가 추출한 커버 이미지를 `/data/cover_cache` 아래에 보관해, 라이브러리와 플레이어가 썸네일마다 태그를 다시 읽지 않게 합니다. 언제든 안전하게 끌 수 있으며 디스크 공간만 듭니다.

### 라이브러리 경로 정합성 검사

Downtify 밖에서 디스크의 **파일을 옮기거나 이름을 바꾼** 뒤, 또는 직접 삭제한 뒤에 사용하세요.

1. **설정 → 라이브러리 → 라이브러리 경로 정합성 검사**를 엽니다.
2. Downtify가 라이브러리 폴더를 스캔하여:
    - 파일이 있던 자리에 더 이상 없지만 같은 파일(같은 콘텐츠 키)이 다른 곳에서 발견되면 트랙 인덱스와 재생목록 카탈로그의 **경로를 갱신**합니다.
    - 더 이상 존재하지 않는 파일의 **오래된 항목을 제거**합니다.
    - 콘텐츠 키가 생기기 전에 저장된 옛 항목을 **인덱싱**합니다.
    - **[좋아요 표시한 곡](liked-songs.md#keeping-likes-in-step-with-the-files)**을 새 위치로 따라가게 합니다.
3. **M3U 생성** 및/또는 **Navidrome에 재생목록 만들기**가 켜져 있으면 영향받은 재생목록이 다시 쓰입니다.

버튼을 누를 때(또는 `POST /api/library/reconcile`을 호출할 때)만 실행되며 — 일정에 따라서는 절대 실행되지 않습니다.

### 기존 음악 폴더

Downtify가 내려받지 않은 컬렉션을 재생하려면 **설정 → 라이브러리**에서 폴더를 추가하고 **폴더 동기화**를 누르세요. 파일은 디스크에 남고, 태그를 읽어 아티스트를 매칭합니다. [기존 음악 폴더](external-library.md)를 참고하세요.

::: warning
재생목록을 다시 쓰면 태그가 등록된 Spotify 트랙과 분명히 맞지 않는 라이브러리 파일이 삭제됩니다 — [slskd와 Navidrome](slskd-navidrome.md#playlist-sync)을 참고하세요.
:::

::: info 삭제 vs 이동
**라이브러리** 페이지에서 트랙을 삭제하면 이미 카탈로그를 정리하고 영향받은 M3U 파일과 Navidrome 재생목록을 백그라운드에서 다시 쓰므로, 나중에 고칠 것이 없습니다.
:::

## 라이브러리 페이지

라이브러리 페이지에는 네 개의 탭 — **앨범**, **아티스트**, **재생목록**, **트랙** — 이 있습니다.

- **앨범, 아티스트, 재생목록**은 커버 그리드나 간결한 목록으로 표시되며(전환은 기억됨), 텍스트 필터와 최근 추가, 이름, 아티스트, 연도, 트랙 수 정렬이 있습니다. 앨범과 아티스트는 각 파일의 태그(앨범 아티스트, 앨범, 연도)로 구성되므로 파일이 디스크에서 어떻게 정리되어 있는지에 의존하지 않습니다. 앨범 아티스트가 `Various Artists`인 트랙은 아티스트 태그로 묶이므로 `Zé Neto & Cristiano` 같은 듀오 이름이 그 이름으로 표시됩니다. 앨범 태그가 없는 트랙은 앨범이 아니라 트랙과 그 아티스트 아래에 나타납니다.
- **재생목록**은 [M3U 파일](m3u-export.md)이 있는 내려받은 재생목록, **새 재생목록**으로 만든(편집 가능한) 재생목록, 그리고 아직 M3U가 없는 추적 중인 [재생목록 다운로드](slskd-navidrome.md#playlist-downloads)입니다. 가져온 Spotify/YouTube 재생목록은 [분리](#detach-an-imported-playlist)하기 전까지 읽기 전용입니다. 다른 사람이 [나에게 공유한](users.md#sharing-playlists) 재생목록은 내 것과 구분되어 그리드 아래에 나열됩니다. 곡에 [좋아요](liked-songs.md)를 누른 뒤에는 *좋아요 표시한 곡*이 맨 앞에 나열됩니다. 직접 만든 재생목록은 최대 네 장의 트랙 커버로 모자이크를 만들고, 가져온 재생목록은 M3U와 함께 저장된 아트워크를 유지합니다.
- **트랙**은 텍스트 필터, 형식 필터, 체크박스가 있는 정렬 가능한 표(제목, 앨범, 형식, 추가한 날짜, 길이)입니다 — 하나를 클릭한 다음 다른 하나를 Shift-클릭하면 범위가 선택됩니다. 열 머리글을 클릭하거나 표 위의 **정렬 기준** 메뉴로 정렬하세요(머리글이 숨겨지는 휴대폰에서는 이 방법뿐): 최근 추가 또는 오래된 순, 제목/아티스트/앨범 A–Z 또는 Z–A, 긴 곡 또는 짧은 곡 먼저. 선택은 기억됩니다.

재생목록의 곡에도 같은 **정렬 기준** 메뉴가 있으며, 선택지에 **재생목록 순서**(재생목록 자체의 순서, 처음 시작하는 값)가 추가됩니다. 열 머리글 클릭도 됩니다. **재생**과 곡 목록은 고른 순서를 따르며, 선택은 모든 재생목록에 대해 기억됩니다.

앨범, 아티스트, 재생목록을 열면 **재생**, **셔플**, **대기열에 추가**, **ZIP으로 다운로드**와 함께 트랙이 표시됩니다. 직접 만든 재생목록에는 **곡 추가**, **이름 변경**, **공유…**([재생목록 공유하기](users.md#sharing-playlists) 참고)도 있고, 가져온 재생목록에는 **공유…**와 **원본에서 분리**(아래)가 있습니다. 내려받은 재생목록 페이지는 트랙이 몇 개 내려받아졌는지 보여주고, 누락된 트랙을 **누락된 곡 다운로드**와 함께 나열하며, **새 트랙 모니터링**을 제공합니다. **재생목록 삭제**는 **⋯** 메뉴에 있습니다: 가져온 재생목록은 오디오를 삭제하고, 직접 만든 재생목록은 재생목록만 제거합니다.

### 가져온 재생목록 분리하기

Spotify나 YouTube Music 링크에서 가져온 재생목록은 Downtify가 원본과 동기화를 유지하므로 편집할 수 없습니다. 하나를 다듬으려면 — 맞지 않는 곡을 빼거나 맞는 곡을 추가 — 열어서 **원본에서 분리**를 선택하세요. 직접 만든 것과 같은 재생목록이 되어, 곡과 소유자는 그대로 유지되고 **곡 추가**, **이름 변경**, 곡 제거를 쓸 수 있게 됩니다. 대신 원본과의 연결이 끊어집니다: 더 이상 Spotify나 YouTube Music에서 갱신되지 않고, [재생목록 모니터](playlist-monitor.md) 감시(있었다면)가 제거되며, "누락된 곡" 추적도 사라집니다. 이미 내려받은 곡은 절대 건드리지 않으며, 아트워크는 첫 편집 때까지 유지되다가 곡들의 모자이크로 대체됩니다. 분리는 앱에서 되돌릴 수 없으며, 링크를 다시 내려받으면 새로 가져온 재생목록이 만들어집니다.

모든 계정이 같은 라이브러리를 봅니다. 관리자가 [사용자에게서 숨긴](users.md#hiding-from-users) 것은 그들에게서 빠지고, 관리자는 숨겨진 항목에 취소선 눈 아이콘이 붙은 채 모든 것을 봅니다. 관리자는 곡, 앨범, 아티스트의 `…` 메뉴나 **트랙**의 선택 바에서 숨기고 표시합니다.

**ZIP으로 다운로드**는 선택한 트랙을 폴더 구조를 유지한 채 하나의 ZIP으로 현재 탐색 중인 기기에 저장합니다 — Downtify가 홈 서버에서 돌고 여러 트랙을 로컬에 두고 싶을 때 유용합니다. **전체 선택**과 함께 쓰면 현재 필터가 보여주는 모든 것을 가져올 수 있습니다. 아카이브는 다운로드하면서 만들어지므로 서버 디스크에는 아무것도 기록되지 않으며, 다운로드당 2000트랙으로 제한됩니다.

## API

| 메서드 | 경로 | 설명 |
|--------|------|-------------|
| `GET` | `/list?refresh=true` | 경로 스캔 캐시를 우회한 라이브러리 경로 |
| `GET` | `/api/library/summary` | 전체 트랙 목록 없이 홈 페이지 수치와 최근 앨범 |
| `GET` | `/api/library/albums` | 모든 트랙 없이 앨범 타일(수치 + 커버 파일) |
| `GET` | `/api/library/artists` | 라이브러리와 둘러보기를 위한 아티스트 타일(수치 + 커버 파일) |
| `GET` `POST` | `/api/library/visibility` | 관리자: 사용자에게서 숨긴 것, 항목 숨기기 / 표시 |
| `POST` | `/api/library/lookup` | 이미 내려받은 검색/링크 곡의 라이브러리 행 |
| `GET` | `/tracks` | 태그가 있는 라이브러리 트랙. `?playlist=`, `?artist=`, `?album=`, `?q=`, `?limit=`로 일부만 반환 |
| `GET` | `/media/{path}` | `slskd/…`와 `ext/…` 경로를 포함해 라이브러리 파일을 제공 |
| `GET` | `/playlist-cover?file=…` | `/playlists`가 `cover`로 보고하는 재생목록 자체의 [커버 아트](playlist-cover-art.md)를 제공 |
| `POST` | `/api/library/archive` | 선택한 트랙의 ZIP 준비(1회용 티켓을 반환) |
| `GET` | `/api/library/archive/{token}` | 그 ZIP을 브라우저로 스트리밍 |
| `DELETE` | `/api/library/playlist?playlist_name=…` | 가져온 재생목록의 트랙, M3U, 카탈로그 삭제 — 또는 직접 만든 재생목록의 M3U만 삭제 |
| `POST` | `/api/library/playlists` | 비어 있는 편집 가능한 재생목록 생성 |
| `POST` | `/api/library/playlists/tracks` | 직접 만든 재생목록에 라이브러리 파일 추가 또는 제거 |
| `POST` | `/api/library/playlists/rename` | 직접 만든 재생목록 이름 변경 |
| `PUT` | `/api/library/playlists/visibility` | 내가 소유한 [재생목록을 공유](users.md#sharing-playlists)(보기 전용) |
| `POST` | `/api/library/playlists/copy` | 열 수 있는 재생목록의 사본을 편집 가능한 내 재생목록으로 저장 |
| `POST` | `/api/library/playlists/detach` | 가져온 재생목록을 편집 가능한 것으로 전환 |
| `POST` | `/api/library/reconcile` | 라이브러리 경로를 바로잡은 뒤 M3U/Navidrome 재생목록 갱신 |
| `POST` | `/api/library/external/sync` | 추가 음악 폴더의 백그라운드 스캔 시작 |
| `GET` | `/api/library/external/sync` | 진행 중인 추가 폴더 동기화 또는 마지막으로 끝난 로그 |
| `POST` | `/api/library/external/unmap` | 오디오를 삭제하지 않고 추가 폴더를 라이브러리에서 제거 |
| `GET`/`POST` | `/api/library/upgrade…` | 이미 내려받은 것을 스캔하고 복구 — [라이브러리 업그레이드](library-upgrade.md#api) 참고 |

요청과 응답 형식은 [API 레퍼런스](../api-reference.md#library)를 참고하세요.
