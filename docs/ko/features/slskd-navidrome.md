# slskd와 Navidrome

자체 호스팅 라이브러리를 위한 두 가지 선택적 연동입니다.

- **[slskd](https://github.com/slskd/slskd)** — YouTube Music, YouTube와 함께 추가 음원 출처로서, 직접 운영하는 slskd 서버를 통해 Soulseek 네트워크에서 트랙을 내려받습니다.
- **[Navidrome](https://www.navidrome.org/)** — 내려받은 재생목록을 Navidrome에 미러링해 모든 Subsonic 클라이언트에 나타나게 합니다.

둘 다 기본적으로 꺼져 있으며 **설정**에서 구성합니다.

## 음원 출처와 대체 순서

**설정 → 음원 출처**는 순서가 있는 목록입니다. 출처를 눌러 추가하거나 제거하고, 둘 이상 선택했다면 화살표로 순서를 바꿉니다. 각 트랙은 이 순서대로 출처를 시도하며 오디오를 제공하는 첫 출처에서 멈춥니다.

| 출처 | 하는 일 |
|--------|-------------|
| **YouTube Music** | 기본값. YouTube Music에서 검색하며, 받아들일 만한 결과가 없으면 일반 YouTube로 대체합니다 — [작동 방식](../how-it-works.md#fallback-to-standard-youtube)을 참고하세요. |
| **YouTube** | 일반 YouTube에서만 검색합니다. |
| **SoundCloud** | 기본적으로 꺼져 있습니다. SoundCloud에서 검색하고, 붙여넣은 SoundCloud 링크는 그 트랙을 그대로 내려받습니다 — [SoundCloud](soundcloud.md). |
| **slskd** | slskd를 통해 Soulseek를 검색하고 가장 잘 맞는 파일을 내려받습니다. |

slskd를 켜면 목록 맨 앞에 놓입니다. slskd가 유일한 출처가 되더라도 그 뒤에 YouTube Music과 YouTube가 여전히 시도되므로, slskd가 찾지 못하는 트랙도 내려받아집니다. 다운로드 대기열은 각 트랙을 어느 출처가 제공했는지 보여줍니다.

## slskd

### 설정

1. slskd를 실행하고 Downtify용 API 키를 만듭니다(slskd 문서 참고).
2. slskd의 다운로드 폴더를 Downtify 컨테이너에 마운트합니다 — slskd가 쓰는 것과 같은 호스트 폴더입니다. [Docker Compose → slskd와 함께](../getting-started/docker-compose.md#with-slskd-soulseek)를 참고하세요.
3. **설정 → slskd (Soulseek)**에서 slskd를 켜고 다음을 채웁니다.
    - **slskd URL** — 두 컨테이너가 Docker 네트워크를 공유한다면 예: `http://slskd:5030`.
    - **API 키**.
    - **다운로드 폴더** — 그 폴더가 마운트된 *Downtify 컨테이너 안의* 경로(기본값 `/slskd`)이며, 호스트 경로가 아닙니다.

URL이나 API 키 없이 slskd를 켜면 저장이 오류 메시지와 함께 거부됩니다.

### 연결 테스트

저장하기 전에 필드를 확인하려면 필드 아래의 **연결 테스트**를 누르세요 — 저장 여부와 상관없이 폼에 입력된 값을 사용하며 아무것도 바꾸지 않습니다. 다음을 알려줍니다.

| 결과 | 의미 |
|--------|---------------|
| **slskd 0.21.4에 연결되었습니다.** | 주소가 맞고 API 키가 받아들여졌습니다 |
| **slskd가 Soulseek에 로그인되어 있습니다.** / **로그인되어 있지 않습니다** | slskd 자체가 Soulseek 네트워크에 로그인했는지 여부. 아니라면 로그인할 때까지 검색 결과가 없습니다 — 설정 자체는 맞으므로 경고입니다 |
| **Downtify가 `/slskd`를 읽을 수 있습니다.** / **읽을 수 없습니다** | 위의 다운로드 폴더가 *이* 컨테이너 안에 있고 읽을 수 있는지 여부. 경고의 흔한 원인은 마운트되지 않은 폴더입니다 — [설정](#setup)을 참고하세요 |
| **slskd가 API 키를 거부했습니다.** | 서버가 응답했지만 이 키에는 아닙니다 |
| **… 에 연결할 수 없습니다 / 시간 내에 응답하지 않았습니다.** | 주소나 포트가 틀렸거나, 서버가 꺼져 있거나, Downtify 컨테이너에서 접근할 수 없습니다 |
| **slskd처럼 보이지 않습니다.** | 무언가 응답했지만 slskd가 아닙니다 — 흔히 포트가 틀렸거나 주소에 기본 경로가 빠졌습니다 |
| **HTTPS 인증서를 신뢰할 수 없습니다.** | 내 네트워크에서는 `http://`를, 아니면 신뢰할 수 있는 기관의 인증서를 쓰세요. Downtify는 인증서 검사를 건너뛰지 않습니다 |

필드를 수정하면 폼의 내용을 더 이상 설명하지 않으므로 마지막 결과가 지워집니다. 주소와 키를 모두 채울 때까지 버튼은 비활성 상태입니다.

### 트랙이 매칭되는 방식

Downtify는 트랙의 제목과 아티스트로 slskd를 검색하고, 파일 이름과 길이가 트랙과 얼마나 잘 맞는지로 결과의 순위를 매깁니다. 똑같이 좋은 결과 중에서는 MP3, 그다음 FLAC를 선호하며, 256 kbps 미만의 비트레이트를 보고하는 파일은 건너뜁니다. 최대 다섯 후보를 차례로 시도합니다. 전송이 끝나면 Downtify는 파일을 보관하기 전에 태그와 길이를 트랙과 대조합니다.

받아들일 만한 것이 나오지 않거나, 전송이 **전체 타임아웃** 안에 끝나지 않거나, 원격 피어의 대기열에서 **대기 타임아웃**보다 오래 진행 없이 머물면 Downtify는 다음 음원 출처로 넘어갑니다.

### 파일을 그대로 두기

**slskd 파일을 그대로 두기**가 켜져 있으면(기본값) 내려받은 파일이 slskd 폴더에 남습니다. Downtify는 그 자리에서 파일에 메타데이터, 커버 아트, 가사를 쓰고 `slskd/…` 경로로 라이브러리에 등록합니다. 라이브러리, 플레이어, M3U 파일이 그 경로를 쓰며 `/media/slskd/…`를 통해 제공됩니다.

끄면 파일명 템플릿과 [파일 정리](file-organization.md) 설정에 따라 파일이 다른 다운로드 옆으로 복사됩니다.
전송된 원본 파일은 slskd 폴더에 그대로 남습니다. [저장 공간 및 사용량](storage-usage.md#the-library-not-its-working-copies)은 이 사본을 라이브러리와 따로 *slskd 작업 사본*으로 집계하므로 차지하는 공간을 확인할 수 있습니다.

::: info
slskd 파일은 원래 형식을 유지합니다 — 설정에서 고른 형식으로 트랜스코딩되지 않습니다.
:::

## Navidrome

### 설정

1. Navidrome의 음악 폴더가 Downtify의 다운로드 폴더(그리고 slskd 파일을 그대로 둔다면 slskd 폴더)를 포함하는지 확인하세요. Navidrome은 트랙을 스캔한 뒤에만 재생목록에 추가할 수 있습니다.
2. **설정 → Navidrome**에서 Navidrome을 켜고 URL, 사용자 이름, 비밀번호를 입력합니다.
3. 선택적으로 **관리자** 사용자 이름과 비밀번호를 추가합니다. 그러면 Downtify는 Navidrome 자체의 예약된 스캔을 기다리는 대신, 새 트랙을 매칭하기 전에 라이브러리를 스캔하도록 Navidrome에 요청합니다.

### 연결 테스트

저장하기 전에 필드를 확인하려면 필드 아래의 **연결 테스트**를 누르세요 — 저장 여부와 상관없이 폼에 입력된 값을 사용하며 아무것도 바꾸지 않습니다. 다음을 알려줍니다.

| 결과 | 의미 |
|--------|---------------|
| **navidrome 0.53.3에 연결되었습니다.** | 주소가 맞고 사용자 이름과 비밀번호가 받아들여졌습니다 |
| **이 계정은 라이브러리 스캔을 시작할 수 있습니다.** | 스캔에 쓰는 계정이 관리자입니다. 입력한 관리자 사용자 이름이거나, 비워 두었다면 일반 계정입니다 |
| **이 계정은 라이브러리 스캔을 시작할 수 없습니다.** | Navidrome은 관리자만 스캔을 시작하게 하며, Downtify가 시도해도 알려주지 않습니다 — 새 곡이 늦게 나타날 뿐입니다. 관리자 사용자 이름과 비밀번호를 채우세요 |
| **관리자 계정이 관리자가 아닙니다.** | 입력한 관리자 로그인은 작동하지만 일반 사용자의 것입니다 |
| **Navidrome이 관리자 사용자 이름 또는 비밀번호를 거부했습니다.** | 스캔 계정의 로그인이 틀렸으며, 메인 로그인은 따로 보고됩니다 |
| **Navidrome이 사용자 이름 또는 비밀번호를 거부했습니다.** | 서버가 응답했지만 이 로그인에는 아닙니다 |
| **… 에 연결할 수 없습니다 / 시간 내에 응답하지 않았습니다.** | 주소나 포트가 틀렸거나, 서버가 꺼져 있거나, Downtify 컨테이너에서 접근할 수 없습니다 |
| **Navidrome처럼 보이지 않습니다.** | 무언가 응답했지만 Subsonic API가 아닙니다 — 흔히 포트가 틀렸거나 주소에 기본 URL이 빠졌습니다 |
| **HTTPS 인증서를 신뢰할 수 없습니다.** | 내 네트워크에서는 `http://`를, 아니면 신뢰할 수 있는 기관의 인증서를 쓰세요. Downtify는 인증서 검사를 건너뛰지 않습니다 |

스캔 권한은 조회만 하며, 테스트는 절대 스캔을 시작하지 않습니다. 필드를 수정하면 마지막 결과가 지워지고, 주소, 사용자 이름, 비밀번호를 모두 채울 때까지 버튼은 비활성 상태입니다.

::: info 페이지로 되돌려 보내는 것은 없습니다
응답에는 찾은 것 — 버전, 경로, 상태 — 만 담기며, 비밀번호나 Downtify가 보낸 요청은 절대 담기지 않습니다.
:::

### 재생목록 동기화

미러링은 관리자가 설정합니다(설정 → Navidrome). 일반 계정은 미러를 만들 수 없지만, 연동이 켜지면 그들의 다운로드도 다른 사람의 것처럼 미러링됩니다.

**Navidrome에 재생목록 만들기**가 켜져 있으면, Downtify는 다음 뒤에 같은 이름의 Navidrome 재생목록을 만들거나 갱신합니다.

- Spotify 재생목록 다운로드가 끝났을 때,
- [재생목록 모니터](playlist-monitor.md) 점검이 트랙을 추가했을 때,
- 라이브러리에서 트랙이 삭제되었거나 [라이브러리 경로가 수정](library-catalog.md#fix-library-paths)되었을 때.

트랙은 먼저 경로로, 그다음 태그로 Navidrome 곡과 매칭됩니다. **Navidrome 재생목록 공개**는 Navidrome에서의 재생목록 공개 여부를 제어합니다.

::: warning 태그가 재생목록과 맞지 않는 파일은 삭제됩니다
재생목록이 갱신될 때(삭제, **라이브러리 경로 정합성 검사**, 또는 이미 완전한 재생목록에서 **누락된 곡 다운로드** 후), Spotify 트랙으로 등록된 라이브러리 파일의 포함된 제목/아티스트가 그 트랙과 분명히 맞지 않으면 **디스크에서 삭제**됩니다 — Downtify는 이를 잘못된 다운로드로 취급합니다. 태그를 직접 편집한다면 이 점을 염두에 두세요.
:::

### 재생목록 커버 아트

설정할 것은 없습니다. [재생목록 커버 아트 저장](playlist-cover-art.md)이 켜져 있으면, Navidrome의 음악 폴더가 그 파일을 포함하는 한 Navidrome은 Downtify가 재생목록의 M3U 옆에 쓰는 `.jpg`를 **사이드카 이미지** — 재생목록 이미지를 해석하는 Navidrome만의 방식 — 로 가져갑니다. Downtify는 이를 위해 API를 호출하지 않습니다.

## 재생목록 다운로드

**라이브러리** 페이지는 Downtify로 내려받은 Spotify 재생목록을 **재생목록 다운로드** 아래에 나열합니다. 펼치면 각 재생목록에 대해 현재 Spotify 트랙 목록 대비 라이브러리에 트랙이 몇 개 있는지 볼 수 있습니다. 여기서 다음을 할 수 있습니다.

- **누락된 곡 다운로드** — 아직 라이브러리에 없는 트랙만 대기열에 추가합니다.
- 이미 내려받은 트랙을 **재생**합니다.
- 재생목록을 펼쳐 누락된 개별 트랙을 보고 내려받습니다.
- 재생목록을 **삭제**합니다 — 아래를 참고하세요.

### 재생목록 삭제

재생목록을 삭제하면(이 패널에서, 또는 라이브러리의 재생목록 필터 옆 **재생목록 삭제**로) 그 재생목록에 등록된 모든 트랙 — **다른 재생목록에도 들어 있는 트랙 포함** — 과 M3U 파일, 그 옆에 저장된 [커버 아트](playlist-cover-art.md)가 디스크에서 삭제되고 추적도 중단됩니다. 그 트랙을 공유하던 다른 재생목록은 백그라운드에서 M3U와 Navidrome 재생목록이 다시 쓰입니다.
