# 사용자와 로그인

Downtify를 쓰는 모든 사람은 **사용자 이름과 비밀번호**로 로그인하며, 사람마다 자기 계정을 가질 수 있습니다. 관리자는 **설정 → 사용자 관리**에서 계정을 관리하고 **설정 → 활동 로그**에서 모두가 무엇을 하는지 봅니다.

## 처음 로그인하기

새 서버에는 계정이 하나 있습니다.

| 사용자 이름 | 비밀번호 |
|----------|----------|
| `admin` | `downtify` |

이 계정으로 로그인한 뒤 **설정 → 일반 → 계정**에서 **비밀번호를 바꾸세요**. Downtify를 아는 사람이라면 기본 비밀번호도 압니다. 바꾸기 전까지는 로그인 후 Downtify가 알려 주고 설정에 경고를 표시합니다.

::: warning 서버를 노출하기 전에 기본 비밀번호를 바꾸세요
기본 비밀번호는 아무것도 보호하지 못합니다. 홈 네트워크 밖에서 Downtify에 접근할 수 있게 하기 전에 바꾸고, 그 경우 HTTPS를 사용하세요([리버스 프록시 뒤에서](mobile-apps.md#behind-a-reverse-proxy) 참고).
:::

### 이전 버전에서 업그레이드하기

계정이 없는 버전을 쓰던 서버도 같은 `admin` 계정을 갖게 되며, 로그인 페이지가 — 관리자가 로그인할 때까지 — 한 번 사용할 사용자 이름과 비밀번호를 알려 줍니다.

- 이전의 **로그인 필수** 옵션에서 비밀번호를 설정했다면, 그 비밀번호가 `admin`에 계속 쓰입니다.
- 그렇지 않으면 `downtify`입니다.

업그레이드 전에 로그인했던 브라우저는 다시 로그인합니다. 그 전에 연결한 휴대폰은 계속 연결되어 있으며 이제 `admin`에 속합니다.

## 관리자와 사용자

| | 관리자 | 사용자 |
|---|---|---|
| 듣기, 검색, 다운로드, 좋아요, 둘러보기, 차트, Finder, 팟캐스트 | ✓ | ✓ |
| 휴대폰 앱 연결(자기 계정에) | ✓ | ✓ |
| 설정 → 일반(자기 계정과 환경설정), 앱 연동, 정보 | ✓ | ✓ |
| 그 밖의 모든 설정(출처, 파일, 태그, Navidrome, 라이브러리, 서버), 서버 이름 바꾸기 | ✓ | |
| [자기 재생목록 공유](#sharing-playlists)(보기 전용), 공개 재생목록 팔로우, 사본 저장 | ✓ | ✓ (관리자가 허용할 때) |
| 파일과 재생목록 삭제(사용자는 [자신이 내려받은 것](#deleting-songs)과 자기 재생목록만), 자기 재생목록 모니터와 팟캐스트 구독 관리, 트랙 오디오 교체, 아티스트 사진 편집 | ✓ | ✓ (본인 것만) |
| [사용자에게서 곡, 앨범, 아티스트 숨기기](#hiding-from-users) | ✓ | |
| 사용자 관리, 활동 로그 보기 | ✓ | |

관리자가 필요한 일을 시도한 사용자는 그렇다는 메시지를 받습니다.

## 내 라이브러리

라이브러리는 공유됩니다. 모든 계정이 누구든 내려받은 모든 곡을 봅니다 — 라이브러리, 내려받음으로 표시된 검색 결과, 연결된 휴대폰에서요. 파일은 두 번 저장되지 않습니다. 두 사람이 같은 곡을 내려받으면 디스크에 한 번만 저장되며 각자 소유자로 기록됩니다.

좋아요, 재생목록(내려받은 것과 라이브러리에서 만든 것), 다운로드 대기열은 관리자가 아닌 한 — 또는 다른 사람이 볼 수 있도록 [재생목록을 공유](#sharing-playlists)하지 않는 한 — 본인 것으로 남습니다. 듣기는 공유됩니다 — 누구나 어떤 트랙이든 재생, 미리듣기, 스트리밍할 수 있고 무엇이든 자기 재생목록에 추가할 수 있습니다. 다른 사람이 이미 내려받는 중인 트랙을 요청하면 두 번 가져오는 대신 그 작업에 합류합니다: 대기열 행 하나, 다운로드 하나, 그리고 각자의 소유 기록 — 기다리는 사람은 각자 대기열에서 자기 순서를 봅니다.

팟캐스트, 재생목록 모니터, 둘러보기 기록도 같은 방식입니다. 계정마다 자기 프로그램을 구독하고, 자기 재생목록과 아티스트를 팔로우하며, 자기 추천을 학습시킵니다. 관리자는 모든 계정의 행을 봅니다. 듣기 자체는 공유됩니다 — 누구나 어떤 트랙이든 재생, 미리듣기, 스트리밍할 수 있습니다.

### 재생목록 공유하기

재생목록은 소유자가 공유할 때까지 — 재생목록 페이지의 **공유…** 또는 **⋯** 메뉴에서 — 소유자(와 관리자)에게만 비공개입니다. 재생은 이미 계정 간에 공유되며, 이것은 누가 목록을 *볼 수 있는지*에 관한 것뿐입니다. *좋아요 표시한 곡*을 제외한 모든 재생목록을 공유할 수 있으며, 가져온 것도 포함됩니다.

| 공개 범위 | 누가 보나요 |
|------------|-------------|
| **비공개** | 소유자와 관리자만 — 기본값 |
| **특정 사용자** | 소유자가 고른 사용자 이름 |
| **공개** | 서버의 모든 사람 |

다른 사람의 재생목록은 내 것과 섞이지 않습니다. 라이브러리의 **재생목록** 탭은 내 것 아래에 두 섹션으로 나열하며, 각 항목에 소유자가 표시됩니다.

- **나에게 공유됨** — 이름으로 나를 지정한 재생목록으로, 항상 표시됩니다. 새로 공유된 것은 열어 볼 때까지 **새로움** 표시가 붙습니다.
- **공개 재생목록** — 모든 사람의 공개 재생목록을 소유자와 이름 순으로 정렬해 탭의 필터로 검색할 수 있고, 소유자, 곡 수, 팔로우 여부를 보여줍니다. 섹션은 접힌 채 시작하며 **설정 › 일반 › 공개 재생목록 표시**로 완전히 숨길 수 있습니다(기본적으로 켜져 있음, 테마처럼 본인 설정).

사이드바에도 나에게 공유된 것과 내가 팔로우하는 공개 재생목록 중 일부가 표시됩니다.

**보는 사람이 할 수 있는 일:** 재생, 셔플, 대기열에 추가, ZIP으로 다운로드(또는 휴대폰/데스크톱 앱으로), 공개 재생목록을 **팔로우**해 — *공개 재생목록 표시*가 꺼져 있어도 — 자기 목록에 남기고 소유자의 변경 사항을 따라가기, 그리고 **사본 저장**: 자기가 볼 수 있는 곡으로 이루어진 비공개 편집 가능한 자기 재생목록. 보는 사람은 다른 사람의 재생목록을 편집, 이름 변경, 삭제, 공유, 분리할 수 없습니다.

**공유 해제:** 소유자가 재생목록을 다시 비공개로 하거나 목록에서 누군가를 빼면, 그 사람의 목록에서 즉시 사라집니다(팔로우했든 아니든). 공개가 아니게 된 재생목록은 더 이상 팔로우되지 않습니다. 이미 저장한 사본은 그 사람에게 남습니다. 공유된 재생목록의 이름을 바꿔도 공유는 유지되고, 삭제하면 공유도 함께 사라집니다. 관리자가 [사용자에게서 숨긴](#hiding-from-users) 곡은 다른 곳과 마찬가지로 그들에게는 공유 재생목록의 트랙에서 제외됩니다.

관리자는 **설정 › 라이브러리 › 사용자의 재생목록 공유 허용**으로 이 모든 것을 끌 수 있습니다(기본적으로 켜져 있음). 꺼져 있는 동안은 모든 공유가 숨겨지고 아무도 공유하거나 팔로우할 수 없으며, 다시 켜면 공유가 돌아옵니다.

연결된 앱도 같은 목록을 받습니다. [`GET /api/v1/playlists`](../api-reference.md#get-apiv1playlists)는 각 목록의 소유자와 보기 전용 여부를 알려 주고, WebSocket의 `playlists_changed`가 새로고침하라고 알립니다.

### 사용자에게서 숨기기

다른 계정이 무엇을 보는지는 관리자가 정합니다. 관리자가 무언가를 숨기기 전까지는 모든 것이 모두에게 보입니다: **곡**, 앨범 전체, 아티스트 전체입니다. 숨겨진 항목은 라이브러리, 검색의 "라이브러리에 있음" 표시, 재생목록의 트랙 목록, 연결된 휴대폰이 동기화하는 항목에서 사라집니다 — 사용자에게만, 관리자에게는 아닙니다.

- **라이브러리에서** 곡, 앨범, 아티스트의 `…` 메뉴를 열고 **사용자에게서 숨기기**(되돌리려면 **사용자에게 표시**)를 고르세요. 트랙 탭에서는 여러 곡을 선택하고 선택 바의 **사용자에게서 숨기기**를 사용하세요.
- 관리자는 계속 모든 것을 봅니다. 숨겨진 항목에는 작은 취소선 눈 아이콘이 붙고, 툴팁이 이유를 알려줍니다: 단독으로 숨김, 앨범과 함께 숨김, 아티스트와 함께 숨김.
- **설정 › 사용자 관리 › 사용자에게서 숨긴 항목**에는 숨긴 모든 아티스트, 앨범, 곡이 나열되며 각각 옆에 **사용자에게 표시**가 있습니다.
- 숨긴 곡은 다른 폴더로 옮겨도, [라이브러리 업그레이드](library-upgrade.md)나 [음원 교체](replace-audio.md)가 파일을 다시 써도 숨김이 유지됩니다. 파일을 삭제하면 규칙을 잊습니다.
- 앨범 규칙은 앨범의 아티스트와 제목에, 아티스트 규칙은 라이브러리가 곡을 묶는 아티스트에 일치합니다 — 라이브러리의 앨범/아티스트 탭이 쓰는 것과 같은 이름입니다.

::: info 숨기기는 무엇이 나열되는지에 관한 것입니다
계정이 앱에서 무엇을 보는지를 제어하며, 이미 주소를 아는 파일을 누가 가져올 수 있는지는 제어하지 않습니다. 민감한 파일을 보호하는 데 쓰지 마세요.
:::

숨기기와 표시는 [활동 로그](#activity)에 기록됩니다.

### 곡 삭제하기

곡을 삭제하면 모두에게서 디스크에서 사라지므로, 내려받은 사람을 따릅니다. 관리자는 무엇이든 삭제할 수 있습니다. 사용자는 자신이 내려받은 곡을 삭제할 수 있고, 다른 사람도 같은 곡을 내려받았다면 삭제는 자기 몫만 포기하며 곡은 공유 라이브러리에 남습니다. 계정을 통해 아무도 내려받지 않은 곡(재생목록 모니터 점검, 계정 도입 전 다운로드, [추가 폴더](external-library.md))은 관리자만 삭제할 수 있습니다. 내 재생목록을 삭제해도 다른 사람의 파일은 절대 함께 삭제되지 않습니다.

### 계정별 사용량

**설정 › 사용자 관리**는 각 계정 아래에 보유한 것을 나열합니다: 트랙과 크기, 좋아요, 재생목록, 요청한 다운로드, 양방향 트래픽(업스트림에서 가져온 것 대 클라이언트에 제공한 것), 그 아래에 모두의 합계. "트랙"은 계정이 내려받은 곡을 세며, 볼 수 있는 것을 세지 않습니다.

## 내 계정과 환경설정

**설정 → 일반**은 **계정**으로 시작합니다: 사용자 이름이나 비밀번호를 바꾸거나 로그아웃합니다. 사이드바(휴대폰에서는 **더보기**)에서도 로그아웃할 수 있습니다.

**일반**의 나머지 — 테마, 언어, 플레이어에 가사 표시, 검색 결과의 앨범 — 는 **본인 것**입니다. 로그인하는 모든 브라우저에서 계정을 따라가며 다른 사람에게는 아무 영향이 없습니다.

**설정 → 앱 연동**은 내 계정에 연결된 휴대폰을 나열합니다(관리자는 모든 사람의 것을 소유자와 함께 봄). **모든 기기에서 로그아웃**은 내 앱의 연결을 해제하고 모든 브라우저에서 로그아웃시킵니다.

## 사용자 관리하기

**설정 → 사용자 관리**에서 관리자는 다음을 할 수 있습니다.

- **사용자 추가** — 사용자 이름(문자, 숫자, `.`, `-`, `_` 3~32자), 비밀번호(8자 이상), 역할.
- 사용자 **편집** — 이름 바꾸기, 관리자나 사용자로 변경, 새 비밀번호 지정(해당 사용자의 브라우저가 로그아웃되며, 앱은 연결된 채 유지).
- 사용자 **삭제** — 앱의 연결이 해제되고 브라우저가 로그아웃됩니다. 파일은 디스크에 남고(관리자는 계속 볼 수 있음), 좋아요, 재생목록, 팟캐스트 구독, 모니터, 추천 기록, 트래픽 카운터는 함께 사라집니다.
- **전체 사용자 일괄 로그아웃** — 모든 사용자의 모든 앱 연결이 해제되고 모든 브라우저가 로그아웃되며, 내 것도 포함됩니다.

관리자는 항상 최소 한 명 있습니다. 마지막 관리자는 삭제하거나 사용자로 바꿀 수 없고, 자기 계정은 삭제할 수 없습니다.

## 활동 로그

**설정 → 활동 로그**(관리자)는 Jellyfin의 대시보드처럼 다음을 보여줍니다.

- **현재 재생 중** — 각 브라우저와 앱이 무엇을 재생 중인지, 누구에 의해, 곡의 어디쯤인지, 일시정지 여부. 몇 초마다 새로고침됩니다.
- **활동 기록** — 로그인(과 실패한 로그인, 접속 주소 포함), 로그아웃, 재생한 곡, 다운로드, 좋아요, 삭제한 파일, 사용자에게서 숨기거나 표시한 곡, 연결/해제된 앱, 추가/변경/삭제된 계정, 변경된 비밀번호와 설정. 사용자나 종류로 필터링하세요. 저장된 설정은 이름만 표시되고 값은 절대 표시되지 않습니다. 항목은 90일간 보관됩니다.

앱도 재생한 것을 보고합니다 — [모바일 클라이언트 규약](../mobile-client-contract.md#8-report-plays)을 참고하세요.

## 계정 끄기

나만 접근할 수 있는 서버 — 내 컴퓨터에 있거나 이미 비밀번호를 묻는 무언가 뒤에 있는 — 는 계정이 전혀 필요 없을 수 있습니다. `DOWNTIFY_DISABLE_AUTH=true`를 설정하세요([환경 변수](../getting-started/environment-variables.md#mobile-apps-and-sign-in) 참고).

```yaml
environment:
  - DOWNTIFY_DISABLE_AUTH=true
```

그러면:

- 로그인 페이지가 없습니다. Downtify를 여는 누구든 첫 번째 관리자로 사용합니다(새 서버에서는 `admin`).
- 로그아웃 버튼, **설정 → 사용자 관리**, **설정 → 일반**의 **계정** 부분, **설정 → 앱 연동**의 **모든 기기에서 로그아웃**이 사라집니다.
- 휴대폰은 여전히 (그 관리자에게) 연결할 수 있고, **설정 → 활동 로그**는 계속 어디서 무엇이 재생되는지 보여줍니다.
- 테마, 언어, 그 밖의 **일반** 환경설정은 그 관리자의 것으로 유지됩니다.

::: warning 서버에 접근할 수 있는 사람은 누구나 모든 것을 할 수 있습니다
계정을 끄면 아무도 누구인지 묻지 않습니다. 네트워크의 모든 사람 — 포트가 노출되어 있다면 인터넷의 모든 사람 — 이 설정을 바꾸고, 음악을 삭제하고, 휴대폰을 연결할 수 있습니다. 다른 사람이 접근할 수 있는 서버에서는 계정을 끄지 마세요.
:::

`false`로 설정(또는 제거)하면 로그인이 다시 필요해지며, 계정, 비밀번호, 앱은 그대로입니다.

## 비밀번호를 잊으셨나요?

서버에서 다음을 실행하세요 — `admin`이 비밀번호 `downtify`를 되찾고(이름이 바뀌었거나 삭제되었다면 관리자로 다시 만들어짐), 다른 계정과 연결된 앱은 그대로 둡니다.

```bash
docker exec downtify python main.py auth-reset
```

Docker 밖에서는 Downtify 폴더에서 `python main.py auth-reset`(또는 `uv run python main.py auth-reset`)을 실행하세요. 그런 다음 로그인해서 비밀번호를 바꾸세요.

## 스크립트와 API

이제 모든 API 호출에 자격 증명이 필요합니다([API 레퍼런스](../api-reference.md#server-and-sign-in) 참고). 스크립트는 `POST /api/auth/login`으로 로그인해 `downtify_session` 쿠키를 유지하거나, 연결된 기기의 토큰을 쓸 수 있습니다.
