# 기존 음악 폴더

Downtify의 라이브러리는 Downtify가 내려받은 파일과, 직접 지정한 **추가 폴더**로 구성됩니다. 이 폴더들은 `/downloads`로 복사되지 않습니다. Downtify는 각 파일의 태그(제목, 아티스트, 앨범, 트랙 번호, 연도)를 읽고, 이미 가지고 있는 곡은 건너뛰며, 나머지를 라이브러리와 플레이어의 해당 아티스트 아래에 정리합니다.

## 폴더 추가

1. 호스트의 폴더를 컨테이너에 마운트합니다(Docker). 설정에 입력하는 경로는 **컨테이너 안의** 경로이며, [slskd의 다운로드 폴더](slskd-navidrome.md)와 같은 규칙입니다.
2. **설정 → 라이브러리**를 엽니다.
3. **기존 음악 폴더 연결**에서 경로를 하나 이상 추가합니다(예: `/music/collection`). 입력하는 동안 디렉터리를 제안합니다.
4. 아직 동기화하지 않고 보관만 하려면 **저장**을, 바로 하려면 **폴더 동기화**를 누르세요. 목록을 저장하고 즉시 스캔합니다.

```yaml
services:
  downtify:
    volumes:
      - ./downloads:/downloads
      - /path/on/host/to/mp3s:/music/collection
      - downtify_data:/data
```

그러면 설정의 폴더는 `/music/collection`입니다.

::: warning 파일은 있던 자리에 남습니다
동기화는 파일을 `/downloads`로 복사하지 않습니다. 폴더에 쓰기 권한이 있으면 다운로드가 기록하는 것과 같은 부가 정보를 해당 파일에 **기록합니다**. 가사(그리고 `.lrc` 사이드카 — 파일 옆 또는 설정에서 고른 폴더), 파일에 없으면 커버, 가능하면 iTunes의 장르입니다. 이후의 동기화는 가사가 이미 태그에 있더라도 없는 사이드카를 기록하며, 원본 파일에 쓰기 권한이 있으면 기존 `.lrc`를 설정에서 현재 고른 위치로 **옮깁니다**. 라이브러리에서 트랙을 삭제하면 디스크의 해당 파일도 여전히 삭제됩니다.
:::

::: tip 읽기 전용 마운트
Downtify가 MP3를 다시 쓰지 않게 하려면 컬렉션을 `:ro`로 마운트하세요. 동기화는 그래도 파일을 색인합니다. `.lrc` 파일은 [가사 폴더](lyrics.md#sidecar-lrc-file)에 두세요(**오디오 파일과 같은 위치에 .lrc 저장**을 끄세요). 없는 커버는 MP3가 아니라 `/data/cover_cache`(라이브러리의 커버 엔드포인트)에 저장됩니다. iTunes 장르는 파일이 아니라 Downtify의 라이브러리 메타데이터 데이터베이스에 저장됩니다. 읽기 전용 파일 옆에 이미 있는 `.lrc`는 가사 폴더로 **복사**되고 제자리에 남습니다.
:::

## 동기화가 하는 일

1. 설정된 모든 폴더에서 재생 가능한 오디오를 찾습니다(라이브러리의 다른 곳과 같은 형식: MP3, M4A, FLAC, OGG, WAV, AAC, OPUS).
2. 내장 태그를 읽습니다. 제목/아티스트가 없는 파일은 다른 라이브러리 행과 마찬가지로 파일 이름의 `아티스트 - 제목`을 사용합니다.
3. 라이브러리에 이미 그 곡이 있으면(같은 아티스트 + 제목, 둘 다 알려진 경우 길이 차이가 몇 초 이내) 파일을 **건너뜁니다**. Downtify가 내려받은 곡이든 다른 추가 폴더에서 온 곡이든 마찬가지입니다.
4. 라이브러리에 이미 있는 이름과 **아티스트를 매칭**합니다(`The Beatles`와 `Beatles`는 한 아티스트가 됩니다). 알려진 아티스트와 맞지 않는 이름은 새 아티스트로 나타납니다. 새 아티스트는 완료된 다운로드와 똑같은 프로필 채우기(해당 설정이 켜져 있으면 사진/소개)를 위해 대기열에 들어갑니다.
5. 폴더에 쓰기 권한이 있으면 **다운로드처럼 태그를 입힙니다**. 가져온 각 트랙에 다운로드가 쓰는 것과 같은 가사 공급자, 커버 조회(파일에 아트워크가 없을 때만), iTunes 장르 조회를 사용합니다. 가사는 파일에 들어가고, `.lrc` 사이드카는 오디오 옆이나 설정에서 고른 [가사 폴더](lyrics.md#sidecar-lrc-file)에 기록됩니다. 커버와 장르는 [다운로드 설정](download-settings.md)(`download_cover_art`, `download_lyrics`)을 따릅니다. **읽기 전용** 마운트에서는 MP3를 다시 쓰지 않습니다. 없는 커버는 `/data/cover_cache`에, 장르는 라이브러리 카탈로그에 저장되고, `.lrc` 파일은 가사 폴더를 골랐다면 그곳으로 갑니다. 조회는 **동시 다운로드 수** 크기의 묶음으로 실행되며, 설정 → 다운로드 및 파일의 **동기화 조회 간격**이 묶음 사이에 대기하므로 큰 폴더도 공급자의 요청 제한에 걸리지 않습니다.
6. 라이브러리 경로 캐시를 무효화하여, 라이브러리 페이지와 플레이어가 평소의 짧은 스캔 TTL을 기다리지 않고 결과를 볼 수 있게 합니다.

동기화는 **백그라운드에서** 실행됩니다. 설정에서 나가도 되며, 아직 작업 중일 때 돌아오면 여전히 동기화 중임을 보여 줍니다. 끝나면 설정에 **마지막 동기화 로그**(가져옴 / 중복 / 오류, 그리고 가사/커버 메모)가 표시됩니다.

이 폴더에 파일을 더 넣은 뒤에는 **폴더 동기화**를 다시 실행하세요. 동기화하지 않고 폴더 목록만 저장해도 다음 라이브러리 스캔(약 1분 뒤, 또는 다음 다운로드/삭제 때)에 포함됩니다.

목록에서 폴더를 제거하면 **매핑이 해제됩니다**. 해당 트랙은 라이브러리와 플레이어에서 사라지고, Downtify가 만든 부가 파일(`.lrc` 사이드카, 캐시된 커버)은 삭제됩니다. 디스크의 오디오 파일은 그대로 남습니다.

존재하지 않거나 읽을 수 없는 폴더는 동기화 후에 알려 주며, 나머지는 계속 스캔합니다.

## 라이브러리 경로

추가 폴더의 파일은 가상 경로 `ext/<id>/…`를 씁니다(id는 폴더 경로의 해시이므로 목록 순서를 바꿔도 됩니다). 플레이어와 `GET /media/…`는 제자리에 둔 Soulseek 파일의 `slskd/…`처럼 이 경로를 사용합니다.

이미 `/downloads`(또는 slskd 원본 폴더) **안에** 있는 폴더는 여기서 무시됩니다. 그 트리가 이미 라이브러리이기 때문입니다.

## API

| 메서드 | 경로                          | 설명                                                                             |
| ------ | ----------------------------- | -------------------------------------------------------------------------------- |
| `POST` | `/api/library/external/sync`  | 백그라운드 스캔을 시작합니다. 선택 본문 `{folders: ["/path", …]}`는 먼저 저장됩니다. |
| `GET`  | `/api/library/external/sync`  | 실행 중인 작업 또는 마지막으로 끝난 로그.                                        |
| `POST` | `/api/library/external/unmap` | 오디오를 삭제하지 않고 폴더를 라이브러리에서 제외합니다.                         |

응답 형식은 [API 레퍼런스](../api-reference.md#post-apilibraryexternalsync)를 참고하세요.

## 기본 라이브러리 폴더

등록된 외부 폴더 중 하나를 우선하려면 **설정 → 라이브러리 → Primary library folder**를 선택하세요.
기본값은 기존 동작을 유지합니다.
아티스트, 전체 제목(버전 포함), 앨범이 일치해야 하며,
알 수 없는 메타데이터는 다른 파일을 숨기지 않습니다. 선택한 출처는
다른 사본에 클립 인트로나 아웃트로가 포함된 녹음을 대표할 수 있습니다.

이는 목록 표시 설정이지 마이그레이션이 아닙니다. 원본 파일, 저장된 재생목록 경로,
소유자, 좋아요, 공개 범위 규칙은 다시 쓰거나 삭제하지 않습니다.
재생목록 배지는 표시되는 대표 항목에 합쳐지며, 명시적으로 저장된
재생목록은 여전히 원래 경로를 재생합니다. 선택한 폴더의 서로 다른 앨범과 버전은
별개로 유지됩니다. 비어 있거나 사용할 수 없는 폴더는 나머지 라이브러리로 대체됩니다.
제거하면 설정이 초기화됩니다.
